# Task completion 写入合同用户设计

## UDES-001 模型语义输入与机器永久结果分层

- 状态: confirmed
- 来源: 用户明确要求从工具职责解决模型直接阅读和修改内容的极简化，同时保持正常程序输出完整
- 关联需求: REQ-001, AC-001, AC-002

模型只提交完成结果的语义正文和命令所需收据；工具从正式任务目标、显式执行版本和收据形成完整永久记录。格式选择服从最小充分 Token、可读性和可靠修改，而不是让模型复制机器 envelope。

## UDES-002 修正必须闭合全局影响

- 状态: confirmed
- 来源: 用户要求不要片面修改破坏全局，并持续推进直到没有明显同类问题
- 关联需求: AC-003, AC-004, AC-005

修正应同时覆盖新写入、旧结果读取、上一版输入、失败原子性、查询诊断和 Delivery Workflow 消费者；不得只改一个测试或一个输出样例。
