# 用户设计

## UDES-001 两级自定义 Agent

- 状态: superseded
- 来源: 用户原话“luna 默认就是 max，terra 不要了，sol 默认 medium”
- 关联: REQ-001, AC-001, AC-002, AC-003

Luna 承接窄而明确的任务，默认并显式使用 `max`；Sol 承接复杂任务，显式使用 `medium`；不再提供 Terra 中间角色。

## UDES-002 失败后先改进再重试

- 状态: confirmed
- 来源: 用户追问“是每次失败都改进么”后的当前改进项 5
- 关联: REQ-002, AC-004

正式验证不能在输入和实现未变化时反复运行到成功；失败必须留下记录，重试要有明确理由并受次数限制。

## UDES-003 静态证据与快速实验分工

- 状态: confirmed
- 来源: 用户明确选择 Luna 整理静态证据/现状地图、Sol low 快速迭代与实验，主代理负责规划和真正实现；随后要求选择规则写入全局 AGENTS 并让模型与档位可独立更新；最终确认使用 `should` 而非绝对强制创建，并重申实验的本质是通过实际操作快速尝试、取证、找路径或错误，不限于全陌生场景
- 关联: REQ-003, AC-006, AC-007, AC-008, AC-009, AC-010, AC-011

Luna medium 只提供证据地图，Sol low 通过可回滚的实际修改或运行快速确认实现路径、暴露错误与真实约束；主代理裁决证据、形成方案并修改生产源码。实验不要求任务全陌生、静态取证穷尽或没有初步方向。角色名使用 `evidence` 与 `experiment` 的长期语义，不把具体模型名作为调用身份。用户未指定时由全局 `should` 规则以必要性、独立边界与委派净收益默认选择是否委派，不形成无条件创建义务。
