# AgentBase Evo 实施方案

本文件依据[需求](requirements.md)、[用户设计](user-design.md)、[基本设计](design.md)和[现状证据](current-state.md)，供用户审查及实施模型执行。条目为可修订实施方案；用户已授权初版实施，状态与实际证据归 [任务表](TASK_TABLE.md)，[完成成本估算](estimates.md)不替代实际消耗。保留原 SOL 身份，在原职责内修订。

## SOL-001 方案职责与当前边界

- 状态: proposed
- 关联: GAP-001, DES-001, DES-012, CON-001, CON-002

实施覆盖 REQ-001 至 REQ-013，以独立评分的可用闭环为先，再接齐七类组件和自动迭代。中间阶段可交付使用，但不能以评分原型代替全部需求完成。软件缺失或宿主能力缺口返回设计处理，不偷偷缩小支持范围。

实施按 SOL-011 的真实产出和依赖组织任务，当前授权与必要验证范围见 CON-001。Deploy、Release 仍需独立授权，方案存在不授予这些操作权限。

## SOL-002 技术取舍与职责

- 状态: proposed
- 关联: GAP-001, DES-002, DES-011, OBS-001, OBS-004, OBS-005, OBS-006

在现有 `agent_eval.py` 增加 `evo <action>` 命令组，新增实现放入 `development/agent-evaluation/evo/`。沿用 Python，采用标准库 SQLite 保存事务化调度与结果关系，文件保存可编辑规格、冻结快照和证据附件；不引入外部数据库、队列服务或第三方演进框架作为运行依赖。

| 职责 | 接入动作与边界 |
| --- | --- |
| 规格、目录、计划解析 | 新增 Evo 职责；同一解析结果供运行、评分、恢复和报告消费 |
| 队列、预算、资源 | 一个调度状态 owner；任务表只记录开发任务，不成为运行状态源 |
| 组合投影 | 在 `agentbase_codex.py` 扩展已有职责，旧 SWE 默认选择与 Evo 显式选择共用 |
| 运行适配器 | 调用现有模型、SWE、路由、hook、MCP、工具 owner，不复制其领域判断 |
| 字段、计算、报告 | Evo 维护派生计算；原始结果和领域判定保持原来源 |
| 事件与用量 | 扩展已有解析职责，Evo 只建立关联与查询投影 |

不预先要求每行成为独立模块；按实际依赖组织代码。验证从原入口和新消费者同时调用共享能力，证明未形成两套同责决定。

## SOL-003 研究规格与评测选择

- 状态: proposed
- 关联: GAP-001, DES-001, DES-003, DES-008, DES-011

实现版本化研究规格、七类组件组合、评测项/组、评分配置及预算 schema，并提供不含真实题目的合成示例。目录支持增删和激活，冻结研究保留当时选择；引用冲突、未知项和空集合都有明确返回。

`plan` 解析来源、依赖闭包、激活集合、去重作业、运行条件、观察需求及资源缺口，只读生成可审查计划，不准备环境或启动模型。用户可分别维护组合与评测组，不用复制整份研究配置修改一个评分公式。

将影响执行的观察合同与只影响计算的评分版本分开：改权重只生成新派生结果；增加必要观察才改变执行身份。用重复组引用、删除后恢复历史、空选择和只改公式验证身份与执行数量。

## SOL-004 组合组装、运行与环境身份

- 状态: proposed
- 关联: GAP-001, DES-004, DES-006, DES-012, OBS-002, OBS-003

先扩展现有投影 owner 接受解析后的组合，分别记录源码、构建/投影和实际运行身份。旧 SWE 默认仍映射原合同；Evo 显式组合不继承旧路径强制关闭 hooks 等限制。冲突配置在解析阶段指出，不依覆盖顺序隐藏。

首个消费者接通 AGENTS、选定 skill 和固定角色设置；随后按实际运行职责接齐：

| 变量 | 必要接入与直接证据 |
| --- | --- |
| 子代理与 Codex 设置 | 来源选择、启动配置、实际角色创建与有效设置；不能仅检查文件 |
| 工具 | 由原组件入口准备可运行候选产物或脚本，Evo 绑定其身份与启动路径；用实际执行证明消费该产物 |
| MCP | server/companion/Provider 生命周期与隔离；真实 Provider 调用结果 |
| hook | 候选事件绑定与实际触发；脚本单测不冒充原生宿主事件 |

环境池按 DES-006 区分共享不变资产、独占可写槽位和证据归档。准备先预留磁盘，同身份投影与已有执行复用；组件编译仍由其正式入口维护，框架不另建通用构建系统。完成后保留必要证据再重置受管差异。以连续两次不同候选、并发可写隔离、重置失败和磁盘不足验证复用不污染。最终增加一个确有七类参与的组合场景；支持证据来自真实使用，不能用七种文件都存在代替。

## SOL-005 自定义数据与评分适配

- 状态: proposed
- 关联: GAP-001, DES-003, DES-007, DES-008, OBS-008, OBS-010

建立字段目录，接入既有质量结果、用量和时长，再扩展工具事件、代理关系及环境开销。字段声明类型、单位、粒度、来源和覆盖；自定义字段通过同一合同进入计算，不另开无法追溯的评分通道。

实现 DES-008 的声明式计算图、选择/分组/聚合、条件、权重、归一化及多个输出；超出表达能力的计算走显式选择的固定版本本地计算器。执行前检查类型、单位、依赖环和关联粒度，拒绝隐式任意代码求值。只评分入口消费已有结果，不隐式补跑 subject 或安装依赖。

先用同一组合事实计算两套不同评分，演示按代理选择工具调用、全部尝试 Token/成功结果数及自定义效率分。覆盖零分母、空集合、缺失值、失败样本、重复累计通知、父子总量、重叠组、多对多关联及公式变更后重算。结果应能逐层追到输入与公式，原 reward 和旧 composite_score 不被改写。

程序、模型和人工 grader 均输出有来源的独立判定；模型评分的提示、rubric 和版本冻结。评分设施异常与行为失败分开，候选不能改写用于判定自身的 grader。

## SOL-006 独立评分与自动循环

- 状态: proposed
- 关联: GAP-001, DES-001, DES-008, DES-010

先实现 `evaluate` 与 `score`，优化控制器随后消费同一运行/计算链，避免形成第二套评分规则。控制器只向模型提供授权数据，输出修改假设、允许路径内的差异及预期收益；冻结候选后再评测。

实现单个挑战者的提案、修改、检查、执行、评分和选择闭环，再开放有限多轮。评测题内产生的 subject patch 与修改 AgentBase 组件的候选 patch 分属不同产物，不能相互写回。规则/skill 的候选仍经过实际受影响的结构合同；候选自己修改的测试不能单独成为独立验收证据。

## SOL-007 对照与候选选择

- 状态: proposed
- 关联: GAP-001, DES-007, DES-008, DES-010, DES-012

冻结输入、观察协议、非变量模型参数和冷/热缓存条件；按任务家族划分开发、选优和最终验收集。重复次数事先声明，经原适配器允许的入口执行，不用新研究别名绕过同输入失败不得重采样的合同。

选择顺序遵守外部质量及必要证据约束，再按明确成本、速度和自定义策略比较；列出样本量、覆盖和不可比原因。独立评分不强制划分三套数据；自动迭代中已用于改写的最终验收数据不得继续称为未见。验证失败候选不晋升、成本缺失不冒充节省、未评分不当通过，以及停止条件不会触发额外一轮。

## SOL-008 人工参与与暂停恢复

- 状态: proposed
- 关联: GAP-001, DES-005, DES-008, DES-010

提供本地评审包导出与评分导入，绑定产物、rubric、评分项和版本，支持盲比与逐项意见。显式导入形成裁决记录；空白不算认可，更正保留替代关系。报告展示缺评项与待裁决问题。

等待人工时保存状态并释放执行资源；恢复只进行尚缺阶段。用半数评分、版本不符、重复导入及更正验证不会覆盖不匹配结果，也不会重新运行已完成 subject。

## SOL-009 队列、预算与故障恢复

- 状态: proposed
- 关联: GAP-001, DES-005, DES-006, DES-007

用 SQLite 事务实现作业领取、单调度器租约、资源预留和 attempt 状态；worker 执行，CLI 只读监控。原始收据仍由执行 owner 维护，数据库记录关联，不复制一份可独立修改的结果事实。

建立本机总上限、研究上限、独占宿主与子代理占用的统一资源判断。按可证明容量预留后代，不能让所有父作业占满资源后同时等子代理。预算结算去重请求与共享后代；无法强制内部请求硬限时公开限制，取消后保留实际消耗，结果不明先对账而非自动重跑。

在领取后、进程启动后、收据落盘前后进行有界故障注入，覆盖双调度器、失联存活进程、磁盘等待、取消及后代未结束。验收核心是恢复不重复花模型额度、不会释放仍在使用的槽位，而不是状态标签数量。

## SOL-010 追溯、存储与候选导出

- 状态: proposed
- 关联: GAP-001, DES-007, DES-009, DES-011, OBS-009

沿既有审计/用量 owner 接入实际宿主事件映射，保存能力声明、来源位置、流内序号和已证关联。优先用合成协议样本检查兼容，再以授权小场景校验本机实际创建、消息、工具、文件和用量；未知事件保留诊断，不能静默统计为零。

提供 `status/watch/trace/report`，按研究、组、作业、阶段、代理和错误渐进查询。摘要、轨迹、评分使用一致快照；迟到事件更新覆盖和派生索引，保留版本。监控脱离模型运行，关闭视图不终止作业；模型读取短别名，机器记录保留完整身份。

必要正文与附件本地去重归档，清理环境前确认引用可恢复。报告可重建，不归档认证、无关宿主数据或私有推理。候选导出受管差异、来源和证据索引，不自动应用到真实安装。验证从分数到动作/产物的定位、缺失来源提示、索引重建和脱敏边界；记录采集开销，不凭文件变短宣称 Token 收益。

## SOL-011 接入步骤与兼容性

- 状态: proposed
- 关联: GAP-001, DES-012, SOL-003, SOL-004, SOL-005, SOL-006, SOL-008, SOL-009, SOL-010

| 阶段 | 产出与依赖 | 完成证据 |
| --- | --- | --- |
| M1 离线评分核心 | 规格、目录、快照、字段与公式、已有产物评分和报告 | 合成数据可复算，多套公式不重跑模型，旧结果语义不变 |
| M2 可用评分版 | 依赖 M1；首个真实组合、队列/预算/环境池、全代理用量、基础追溯及人工介入 | 一条真实链闭合；并发/恢复守限，子代理成本有来源，人工恢复不重跑 |
| M3 七类组件接齐 | 依赖 M2；独立配置变量、候选工具、MCP、hooks 和组合接入 | 各类实际加载与行为证据，加一个七类共同参与的合法场景 |
| M4 自动迭代 | 依赖 M2 与所选组合对应的 M3 能力；有限候选、对照、选择、停止 | 一轮真实挑战者闭合，质量/预算/人工等待及拒绝晋升可核查 |
| M5 基础版收敛 | 依赖前述阶段；兼容、恢复、使用说明及需求复核 | 全部十三项需求有适用证据；明确宿主追溯缺口，不宣称全面效果提升 |

M1+M2 是可使用的中间交付；本次“完成 Evo”的估算包含 M1—M5。M3 内只并行已经有稳定前提的独立适配，M4 不等待无关适配但最终完成仍需 M3 全部接齐。

旧 SWE CLI、corpus、资格、独立 Verifier 和默认投影保持原结果。共享投影的硬编码选择原位替换，旧调用显式映射默认合同；只绑定退出实现的测试更新/退出，稳定行为测试保留。原 `composite_score=null` 不变，新评分放入 Evo 派生结果。路由输出与尝试身份由原 owner 接入，不污染正式研究结果。

实现稳定后按影响运行既有 `test_agent_evaluation_infrastructure.ps1`（evaluator 禁用）及受影响组件的正式检查。真实模型、原生 hook 和 Provider 验证采用明确预算的小场景，结构检查不冒充这些行为证据。遇到共享前提失败先修正并重验该处，不展开后续批量。

## SOL-012 首个试点与完成边界

- 状态: proposed
- 关联: GAP-001, DES-012, SOL-007, SOL-011

首个真实消费者选择 AGENTS、subagent-orchestration skill 与固定角色配置，完成一次主代理实际调用子代理的用量与追溯闭环；独立 grader/controller 验证单 root 配置。已取得的角色、命令、MCP、hook 与逐请求证据足以证明初版运行入口，不为框架验收继续展开角色效果矩阵。已有 evidence 复用与实际内容优化效果属于后续显式研究，评判有效结果及成本，不奖励创建代理数量。

先证明独立评测和同一产物多套评分，再在授权范围内验证一个候选的自动循环。M3 的真实 hook/MCP/工具接入单独补足，不能从首个角色场景外推七类全部可用。小样本用于证明框架运行能力；优化效果研究在框架交付后另定规模。

## SOL-013 独立代码阅读题接入

- 状态: proposed
- 关联: REQ-014, UDES-003, CON-002, DES-003, DES-006, DES-011, DES-012, DES-013

在 Evo 既有目录解析、Codex 组合投影、调度、用量与轨迹、评分入口内接入代码阅读协议；它与要求修改补丁的 SWE 协议有不同题目契约，领域评分分别维护，共享运行和数据职责不复制。旧阅读题与实验记录保留为历史输入，不覆写旧版本，也不再让新 Evo 阅读题指向活跃项目。

先从真实项目复制有界源码与工程配置，保留正常搜索上下文，排除构建、缓存、宿主状态及题目研究材料。真实题面、定位答案、人工复核依据、工程快照、抽取配方与研究配置全部放入本地忽略目录；通用框架、接口说明和合成测试才进入 Git。

首个切片证明一题通过导入、目录验证、计划选择、正式运行适配器和定位评分器进入 Evo 结果。模型传输仅在合成测试中替代，本轮不运行真实模型。该接缝成立后接入其余题型；覆盖路径项、单行与完整范围、非法/额外答案、快照漂移和旧 SWE 兼容。新快照重新核对答案，不以哈希刷新代替定位和完整性判断。正式基础设施检查禁用 evaluator，真实目录另做无模型静态校验。
