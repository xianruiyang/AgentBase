# AgentBase Evo 需求与边界

本文件保存用户已明确的结果和范围，供方案维护者与后续实施模型恢复目标。继承 [AgentBase 根需求](../../requirements.md)和项目约定；具体技术选择与验证办法由 [solution.md](solution.md)提出，不因写入文档而获得实施或模型运行授权。

## REQ-001 指定组件组合的评分与内容演进

- 状态: confirmed
- 来源: 用户要求指定 agentMd、skill、hook、MCP、工具组合，并明确补充“组件还包含子 agent 设置、Codex 设置”

Evo 的目标是支持用户指定 AGENTS 指令、skills、hooks、MCP、工具、子 agent 设置和 Codex 设置组成的一个或多个组合，对选定组合评分或迭代优化。子 agent 设置和 Codex 设置是独立可选的组件，不仅作为其他内容的固定依赖。范围覆盖七类内容，不只优化 skill description，也不把部署流程优化当作本计划目标。

组合的表示、可修改面、固定依赖及运行方式由方案具体化；这些实现选择不得缩减上述对象范围。

## REQ-002 模型参与自动迭代

- 状态: confirmed
- 来源: 用户要求“可以由模型介入”及“自动迭代框架”
- 关联: REQ-001

框架应支持模型参与候选改进，并根据评测反馈组织后续迭代。自动迭代是可选运行模式，不是使用评分能力的前置条件；具体阶段、权限、停止与恢复方式由方案定义并接受审查。

## REQ-003 支持人工介入评分

- 状态: confirmed
- 来源: 用户要求“也可以有人工介入如部分内容评分的部分”
- 关联: REQ-001, REQ-002

评测与迭代允许部分内容由人工评分或裁决，人工结果能够被后续迭代消费。不得将所有内容必须全自动评分作为实现前提。

## REQ-004 基于现有评测与源码研究形成方案

- 状态: confirmed
- 来源: 用户要求拉取并研究 AutoSkill、EvoSkill、Anthropic Skill Creator，“结合目前已有的评测框架”给出方案

方案应使用 AgentBase 当前评测框架的实际能力和第三方源码证据作依据，区分可复用能力、需要适配的机制和仍未验证的行为。用户未指定必须整体接入某个第三方框架；具体复用方式由方案提出。

## REQ-005 独立评分模式

- 状态: confirmed
- 来源: 用户明确要求“这个框架可以只用于评分”
- 关联: REQ-001, REQ-003

Evo 可以只对指定组合进行评测评分和结果报告，不要求生成修改候选、执行自动优化或写回组件内容。程序、模型和人工评分能力在该模式下同样可用；对已有产物评分与运行场景后评分的具体入口由方案定义。

## REQ-006 评测内容分组管理

- 状态: confirmed
- 来源: 用户明确要求“评测内容可以分组，方便增删，选择激活”
- 关联: REQ-001, REQ-002, REQ-005

评测内容应支持命名分组，允许增删分组及其中的评测项，并选择激活哪些组参与当前评分或优化。评测内容组与被评估的组件组合分别管理；修改评测分组不要求修改组件内容。

## CON-001 当前授权与阶段边界

- 状态: confirmed
- 来源: 用户先要求“先只给出方案”，随后确认名称与独立子计划层级、初始化必要内容，并补充组件范围、独立评分和评测分组需求

当前授权覆盖子计划建立、必要文档初始化和已有研究/方案的组织。它没有启动框架实现、真实模型评测、外部服务或主机安装。后续按用户对具体工作的授权推进；计划存在、技术方案完整或任务表状态不创建额外授权。

本约束限制当前工作阶段，不把评分与自动迭代的长期实现目标视为已完成。Deploy 与 Release 继续分别需要当次明确授权；源码与文档的 Git 维护按项目已有授权执行。

## CON-002 继承项目运行与数据边界

- 状态: confirmed
- 来源: [AgentBase 项目约定](../../../AGENTS.md)、[根需求](../../requirements.md)

Evo 继承 Windows 本地执行、质量优先于端到端 Token 成本且成本优先于速度、真实题目和实际评测记录只留本机、安装副本不作为源码真源、无远程 CI，以及不自主查询或改变线程推理深度等既有约束。具体条文仍由对应上游 owner 维护，不在本文件建立另一套规则。
