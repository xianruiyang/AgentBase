# 模型交互面合同：目标设计

## DES-001 根需求拥有模型交互面上位合同

- 状态: confirmed
- 满足: REQ-001, REQ-002, REQ-003, AC-001, AC-008

`docs/requirements.md` 把原 REQ-012 从工具输出扩展为所有模型直接读取、生成或修改内容的项目级结果；上一版工具双视图仍是该合同的已实现子集，不建立平行新需求重复同一原则。

## DES-002 全局内核拥有交互面判断顺序

- 状态: confirmed
- 满足: REQ-001, AC-001, AC-002, AC-003, UDES-001

`global/AGENTS.md` 定义跨项目都成立的认知顺序：先确认事实 owner、消费者、当前判断或修改责任与生命周期，再选择读取面、修改面或机器面。它不维护文件清单、字段协议、统一格式器或领域投影。

## DES-003 内容 owner 拥有唯一真源和消费者投影

- 状态: confirmed
- 满足: REQ-002, AC-004, AC-005, UDES-002, UDES-003

模型/人维护的语义真源产生可重建机器产物；程序维护的机器真源通过有界模型投影、查询或受验证语义修改入口服务模型。同一事实只保留一个长期决定路径，消费者投影不复制领域判断或变成第二真源。

## DES-004 模型读取面与修改面承担不同合同

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003, AC-006

读取面以当前决策的最小充分证据、语义分页和精确恢复为目标；修改面以职责局部性、稳定定位、生成区隔离和直接验证为目标。内容短或格式紧凑不能替代修改可靠性，内容完整也不能自动取得模型上下文资格。

## DES-005 Delivery Workflow 拥有阶段文档交互资产合同

- 状态: confirmed
- 满足: REQ-003, AC-007

`delivery-workflow` 的公共产物合同明确阶段 Markdown 是模型/人维护的语义真源，manifest、保护快照、索引和状态视图是机器管理或可重建产物；模型按稳定 ID 局部修改正式条目，工具按需投影，不编辑缓存或生成视图。

## DES-006 Task Table Manager 拥有结构化任务资产合同

- 状态: confirmed
- 满足: REQ-003, AC-007

`task-table-manager` 明确任务合同、状态和结果 JSON 是结构化权威记录，模型通过 taskctl 的有界模型读取面和带 revision 的语义写入口维护；`TASK_TABLE.md` 与索引只供读取或重建。machine 视图继续服务测试和程序消费者。

## DES-007 Event Logger 拥有机器日志到模型恢复面的投影

- 状态: confirmed
- 满足: REQ-003, AC-002, AC-005, AC-006, AC-008

`codex-event-logger` 保持 `conversation.json` 与 `file-operations.jsonl` 为机器记录真源；读取器从一次有界事实读取形成默认模型恢复视图和显式 machine JSON。模型视图只保留恢复或历史选择所需的对话、goal、文件操作、异常与续查信息，字段优先级由该 owner 决定。

## DES-008 项目验证覆盖规则、资产合同与真实消费者

- 状态: confirmed
- 满足: REQ-003, AC-008, CON-001

静态合同验证根需求、全局/项目规则和三项 skill 的职责链；隔离 Policy 场景覆盖工具返回、模型读取文件和模型修改文件；组件测试验证 event logger 同源双视图和恢复预算，task/work 回归验证既有消费者未退化。规则、文档和测试分别只证明其直接范围。
