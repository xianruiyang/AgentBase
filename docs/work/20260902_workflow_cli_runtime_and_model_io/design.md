# Workflow CLI 运行时与模型输入输出：目标设计

## DES-001 workflow-cli 是独立运行时 owner

- 状态: confirmed
- 满足: REQ-001, AC-001, AC-002

`tools/workflow-cli` 唯一维护 `workctl`、`taskctl` 的源码、组件测试、版本、包清单、Windows 安装器和主机 Status。安装根只保存受管运行时，用户 PATH 只登记其 `current` 目录；skill 仅是模型侧消费者，不复制可执行源码。

## DES-002 模型与机器视图共享事实但分离身份

- 状态: confirmed
- 满足: REQ-002, AC-003, AC-004

每条命令先计算一次 canonical 事实。machine 视图保留稳定完整结构和机器身份；model 视图由该命令 owner 按当前动作投影。需要跨进程回传机器身份时，model 视图取得工作区内可读短句柄，CLI 通过派生索引解析，语义真源与内容寻址资产保持唯一。

## DES-003 taskctl 分离持久来源句柄与临时复核句柄

- 状态: confirmed
- 满足: AC-003

执行来源句柄以任务 ID 与递增序号命名，和不可变来源快照共同持久化，直到结果写入后仍可审计；最终复核分页句柄以复核序号命名，保存在可重建缓存并有界保留，失效时从第一页重新取得。句柄索引保存完整引用并检测冲突，模型不读取该映射。

## DES-004 安装器只投影决策所需状态

- 状态: confirmed
- 满足: AC-001

安装器默认 model 回执只给动作结果、版本、是否需要新终端和失败恢复；安装根、受管成员、文件指纹、PATH 原值及完整诊断只进入 machine 视图。Status 直接执行两个命令的版本入口并核对安装状态，不从仓库或 skill 安装副本反推结果。
