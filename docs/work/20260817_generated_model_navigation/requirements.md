# 生成式模型导航摘要需求

## REQ-001 生成给模型阅读的导航文件只保留有效摘要

- 状态: confirmed
- 来源: 用户明确把生成给模型阅读和修改的文件纳入消费者分层原则
- 关联: AC-001, AC-002, AC-003

`TASK_TABLE.md` 与 `WORK_STATUS.md` 作为可重建模型/人类复核导航，摘要区只显示实际存在的状态、进展、异常和明确空结论；machine CLI 摘要继续完整。

## AC-001 非零状态和问题才展开为逐项统计

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

任务状态表不列出所有零状态；未决、未知引用、延后项、结果问题和上游问题只在非零时展开。正常零值不通过多行固定模板进入模型读取面。

## AC-002 语义空结果必须明确

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

没有任务、没有结果引用、没有未决 ID 等会改变判断的空状态各用一句明确结论表达，不能因稀疏化而让模型分不清“零”和“未读取”。结果存在时即使带验证结果数为零也必须显示该进展缺口。

## AC-003 任务明细导航保持完整

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

存在任务时，`TASK_TABLE.md` 继续保留 ID、状态、owner、标题、依赖、结果引用和合同 revision；空单元格继续使用可见占位，避免表格错位。摘要精炼不得破坏定位、CAS 或关系导航。

## CON-001 本轮边界

- 状态: confirmed
- 来源: 当前持续开发授权与单次发布限制
- 关联: REQ-001

只改变两项 render owner 生成的 Markdown 摘要及直接合同/测试；不批量重写历史生成物，不改变阶段/任务真源、machine 输出或 Codex 安装。
