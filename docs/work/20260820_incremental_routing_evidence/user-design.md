# 用户设计

## UDES-001 独立验证不应固定全量触发

- 状态: confirmed
- 来源: 用户原话“独立验证这块也优化下，目前太慢，而且每次都要触发，消耗token太多”
- 关联: REQ-001, REQ-002

保持独立验证的质量边界，同时减少没有真实语义变化的重复触发、等待和 Token。

## UDES-002 有差异时使用独立子进程

- 状态: confirmed
- 来源: 用户原话“这个子进程启动和开subagent比，其实有无区别。假如无区别的话，用subagent，有区别的话，先彻底解决这个权限问题”
- 关联: REQ-003, AC-006

若 subagent 不能提供与独立子进程等价的隔离，就先解决 CLI 启动权限，并继续使用真正独立的子进程验证。

## UDES-003 形成可长期复用的评估测试基础架构

- 状态: confirmed
- 来源: 用户原话“需要完成一个评估测试基础架构，彻底解决以后的测试还有评估问题”
- 关联: REQ-004, AC-009, AC-010

本轮结果不能只是把当前失败重跑到通过；应形成以后修改都能复用的统一测试、评估、恢复和正式门禁入口，减少同类问题与重复成本。
