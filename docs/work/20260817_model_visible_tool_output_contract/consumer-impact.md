# 模型可见工具输出消费者影响复核

## 复核边界

本表按根 `README.md` 的正式 owner 清单复核当前会进入模型上下文或被程序解析的输出入口。它用于证明本版本没有把 taskctl/workctl 的方案误套到所有工具，也不把尚未验证的组件宣称为已迁移；各组件的具体协议仍归其正式 owner。

| Owner / 入口 | 当前消费者与合同 | 本版本裁决 | 后续重开条件 |
| --- | --- | --- | --- |
| `tools/srcq` | 已从完整事实源提供默认 model、显式 machine 与 native/artifact；正式文档和真实代理审计已覆盖字段准入、分页与 Token 成本 | 作为同项目参考，不修改、不复制其 renderer | srcq 质量、分页、模型成本或消费者合同出现适用失败 |
| `task-table-manager/taskctl.py` | Codex 直接读取查询结果，测试和潜在自动化解析 JSON；修改前两类消费者共用完整 JSON | 本版本迁移：同一 handler 结果派生默认 model 与显式 machine，仓库内机器消费者显式接入 | 模型遗漏必要任务证据、machine 字段退化、出现未迁移真实消费者或预算恢复失效 |
| `delivery-workflow/workctl.py` | Codex 直接读取阶段查询，测试解析 JSON；修改前同样共用完整 JSON | 本版本迁移：在交付 owner 内建立同名双视图并迁移仓库消费者 | 模型遗漏阶段正文/关系、machine 字段退化或真实消费者未接入 |
| `mcp/vscode-lsp-mcp` | MCP stdio 是 machine-only JSON 协议；Codex 的常规源码查询先由 `srcq` 投影，只有真实符号语义不足时才渐进调用 MCP | 不把 CLI 双视图加入 MCP 协议；本版本未改协议、schema 或客户端 | MCP 工具结果被证明向模型暴露与当前语义动作无关的大型字段，且不能由调用参数有界化 |
| `codex-event-logger/read_codex_turn_log.py` | 专为模型恢复历史而有界读取，当前输出仍包含路径、限制、字节计数与完整记录对象；没有证据证明这些字段在各恢复场景都必要 | 不在 task/work 版本中顺带改写历史恢复合同；记录为后继模型输出审计候选，不宣称已满足新双视图合同 | 真实压缩恢复或历史追溯样本能区分必要记录、机器审计字段与可恢复分页，并完成质量/Token 对照 |
| `reasoning-governor` | 状态和设置返回结构化 receipt；模型需要配置读回与匹配字段证明下一轮状态，宿主/脚本也可能解析 | 保留现有小型验证 receipt，不用通用稀疏 renderer 删除成功判据 | 真实调用证明 receipt 中存在不参与状态或设置验收的稳定冗余，且 machine 消费者可显式迁移 |
| `codex-qq-hook` | Hook、传输、状态与人工排查具有不同消费者；skill 已限制模型向用户只报告状态的四项事实，但脚本输出并非统一模型合同 | 不把通知生命周期与凭据/传输输出混入本版本；保留现有授权和机器链路 | 状态或排查的真实模型调用显示原始配置、回执或日志进入上下文且超过当前动作所需范围 |
| `development/skill-routing`、`development/codex-deployment` | 面向 CI、发布器和项目维护者的验证/发布入口；模型只在开发任务中读取有界成功摘要或失败诊断 | 保持机器/运维合同；本版本只更新与新规则直接相关的静态断言和独立证据 | 正式命令的正常输出持续向模型倾倒大型机器对象，或新增程序消费者需要稳定独立视图 |

## 结论

本版本关闭的是当前已有直接高成本证据、共享同一问题且能由统一消费者迁移闭合的 taskctl/workctl 输出面。全局规则和根需求覆盖未来所有模型可见工具，但不据此声称其他 owner 已完成迁移；`codex-event-logger` 是当前最明确的后继审计候选，必须用真实恢复任务先证明最小充分字段，不能直接复制本版本的 task/work 投影。
