# 模型可见工具输出合同：需求分析

## REQ-001 模型只接收当前动作的最小充分工具证据

- 状态: confirmed
- 来源: 用户在当前对话中明确提出进入模型上下文的工具输出只保留工具使用所需信息，并进一步确认模型直接阅读和修改的内容应采用极简设计
- 关联: AC-001, AC-002, AC-003, UDES-001, UDES-003

Codex 直接消费 taskctl、workctl 等工具输出时，只取得完成当前判断、动作、验证或恢复所需的最小充分证据，不再默认接收面向程序的完整数据对象。

## AC-001 模型字段具有直接消费者

- 状态: confirmed
- 来源: REQ-001 对用户要求的原子化
- 关联: REQ-001

模型视图中的每个字段都能对应当前判断、定位、动作、验证或恢复；正常零值、空集合、重复身份、机器 envelope、schema、receipt 和与当前动作无关的完整快照不进入典型输出。

## AC-002 预算不足仍保留语义优先级和恢复入口

- 状态: confirmed
- 来源: REQ-001 对用户要求的原子化
- 关联: REQ-001

模型预算在选择证据单元前生效；预算不足时保留目标或任务身份、当前状态、异常、直接依据和精确续查信息，不把所有字符串一并截短，也不在仍有可用核心信息时退化为单句增大预算提示。

## AC-003 典型决策质量不因精炼下降

- 状态: confirmed
- 来源: 用户确认质量优先于 Token
- 关联: REQ-001, CON-001

模型视图支持原场景、同类变体和相近非触发场景取得与同一次机器事实一致的结论；精炼导致遗漏阻塞、异常、证据时效、授权或必要恢复动作时不得采用。

## REQ-002 程序获得稳定完整且与模型同源的机器输出

- 状态: confirmed
- 来源: 用户明确指出正常工具输出仍需格式化且有足够信息
- 关联: AC-004, AC-005, UDES-002

程序、测试和自动化通过显式机器视图继续获得稳定、完整、可解析的结构；模型精炼不得削弱机器合同，也不得复制一套事实计算。

## AC-004 两种视图来自同一权威结果

- 状态: confirmed
- 来源: REQ-002 对用户要求的原子化
- 关联: REQ-002

命令先完成一次领域事实计算，再由模型和机器 renderer 投影；状态、诊断、候选映射、分页和快照身份不在 renderer 中重新裁决。

## AC-005 机器消费者显式选择并保持可迁移

- 状态: confirmed
- 来源: REQ-002 对用户要求的原子化
- 关联: REQ-002

仓库内现有程序消费者和回归测试显式请求机器视图；机器视图保持当前 JSON 合同及 pretty 选项。没有直接证据的外部消费者不形成永久兼容分支，但正式文档明确给出迁移动作。

## REQ-003 taskctl 与 workctl 采用一致输出面合同

- 状态: confirmed
- 来源: 当前问题已在两个模型直接调用的工作流 CLI 中发现，srcq 已提供同项目可复用的成功合同
- 关联: AC-006, AC-007, AC-008

taskctl 和 workctl 使用一致的 `model`、`machine` 输出面命名与默认选择，同时分别保留任务域和交付域的相关性投影 owner。

## AC-006 模型调用默认进入 model 视图

- 状态: confirmed
- 来源: REQ-003 对当前消费者的原子化
- 关联: REQ-003

两项 CLI 的默认成功和错误输出均面向模型；程序消费者显式选择 `machine`。pretty 只作用于机器 JSON，避免一个选项同时改变消费者和排版两个维度。

## AC-007 高成本查询具有领域化投影

- 状态: confirmed
- 来源: 当前真实输出测量与职责分析
- 关联: REQ-003, AC-001, AC-002

taskctl 的 `status`、`context`、`completion-context` 和 workctl 的 `status`、`context` 至少具有命令专属投影：保留当前状态、异常、直接依赖、必要正文、证据摘要、分页或恢复信息；completion-context 模型视图不复制候选结果中的完整 source_snapshot，任务执行 context 仍按既有完成合同保留必要执行来源快照。

## AC-008 输出合同具有结构、质量和成本回归

- 状态: confirmed
- 来源: REQ-003 对验收的原子化
- 关联: REQ-003, CON-001

回归分别覆盖默认 model、显式 machine、错误、低预算、分页、异常与正常场景；以机器结果为同源事实基线验证模型投影，并用项目采用的保守 Token 估算和适用 tokenizer 测量典型真实输出。

## CON-001 质量、Token、速度顺序不变

- 状态: confirmed
- 来源: 项目根需求与用户当前确认
- 关联: REQ-001, REQ-002, REQ-003

先保证需求、正确性、授权、安全、可维护性和完成证据；质量同等充分时才降低 Token，二者不退化时才优化速度。

## CON-002 本版本不改变 source_snapshot 事实表示

- 状态: confirmed
- 来源: 用户此前明确要求不把 source_snapshot 压缩混入当前推进
- 关联: REQ-001, REQ-002

本版本不引入 source_snapshot 引用池、哈希压缩、第二快照状态或新的结果时效语义。模型完成复核视图可以省略不参与判断的完整映射；任务执行 context 中完成结果必须消费的来源映射仍保持现有合同。

## CON-003 不混入插件迁移且不继承发布授权

- 状态: confirmed
- 来源: 用户此前明确边界以及项目发布合同
- 关联: REQ-003

本版本不改变插件分发模式。任何向真实 Codex 根目录的 Publish 必须另行取得用户针对当次发布的明确同意，开发、验证、Git 维护和历史发布均不能替代。
