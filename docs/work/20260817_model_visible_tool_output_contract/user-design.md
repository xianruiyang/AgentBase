# 模型可见工具输出合同：用户设计

## UDES-001 模型直接阅读和修改的内容采用极简设计

- 状态: confirmed
- 来源: 用户当前对话明确设计
- 关联需求: REQ-001

进入模型上下文的工具输出只保留工具在当前动作中实际使用的信息，不把程序完整对象直接倾倒给模型。

## UDES-002 正常程序输出保持格式化和足够信息

- 状态: confirmed
- 来源: 用户当前对话明确设计
- 关联需求: REQ-002

程序调用的正常工具输出仍需结构稳定、字段足够并适合解析；模型极简视图不能以删除机器能力来实现。

## UDES-003 使用低 Token 且便于模型阅读的表达

- 状态: confirmed
- 来源: 用户明确提出 YAML、TOML、HJSON 等低成本候选，并要求从根本原则解决
- 关联需求: REQ-001, REQ-003

模型视图在完成信息筛选后采用实际 Token 消耗低且模型易读的表达；格式由测量和可恢复性裁决，不要求为了名称偏好固定为某一种序列化标准。
