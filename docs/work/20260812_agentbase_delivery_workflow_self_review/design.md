# AgentBase 交付链自审与改进：目标设计

## DES-001 交付链由受保护目标和可修订认识两层组成

- 状态: confirmed
- 关联: REQ-001, AC-001, UDES-001

`delivery-workflow` 负责需求、用户设计、模型设计、现状、方案和延后讨论项的语义链。需求与用户设计在执行前固化；模型设计、现状、方案和任务在执行中按新证据修订，最终目标集合只能来自受保护基线。

## DES-002 workctl 提供可组合且语义准确的工作区操作

- 状态: confirmed
- 关联: REQ-001, AC-001, AC-002, UDES-001

`workctl` 只创建与维护确定性容器、基线完整性、索引、影响查询和有界视图。每个命令的字段名与返回值必须准确描述实际发生的文件操作或诊断，使模型无需读源码即可安全组合下一步。

## DES-003 taskctl 直接消费同一工作区的上游索引

- 状态: confirmed
- 关联: REQ-001, AC-001, AC-002, UDES-001

`taskctl` 在同一工作区维护任务合同、状态和结果；任务通过稳定上游 ID 建立追溯，CLI 提供依赖推荐、精确上下文和并发保护，但不把诊断升级为执行许可或语义否决。

## DES-004 最终复核从基线建立可分页的一致证据快照

- 状态: confirmed
- 关联: REQ-001, AC-001, AC-002

最终复核必须精确遍历受保护的 `REQ/AC/UDES`、适用约束和开放延后项，并将候选任务结果作为证据输入。CLI 保证快照、身份和分页一致性，模型判断每份证据能否直接证明目标。

## DES-005 验证覆盖真实使用链与工具安全边界

- 状态: confirmed
- 关联: REQ-001, AC-003

回归测试除字段和数量外，还覆盖从初始化、保护、索引、任务创建、执行、完成到最终上下文的真实组合，以及路径、并发、漂移、分页和损坏输入等确定性安全边界；skill 路由与可移植部署合同随职责变化同步验证。
