# 任务结果诊断与证据时效语义：需求分析

## REQ-001 完成复核直接揭示全部返回结果诊断

- 状态: confirmed
- 来源: 用户确认按当前需求推进下一版本，并要求全面考虑、避免片面修改破坏全局
- 关联: AC-001, AC-002, AC-003, CON-001

模型读取 `completion-context` 或进度摘要时，应能直接区分查询级诊断、结果记录诊断、任务合同修订陈旧和来源快照问题；任何返回页包含结果诊断时，不得同时以没有作用域说明的零值汇总制造“没有诊断”的表象。

## AC-001 完成复核提供分页级分层诊断汇总

- 状态: confirmed
- 来源: REQ-001 对项目根需求 AC-018、AC-028、AC-030 的本轮投影
- 关联: REQ-001

每个 `completion-context` 响应页分别返回查询诊断数、候选结果诊断条目数、含诊断的候选结果数、按 kind 汇总和总数；完整结果诊断仍只保存在当前页唯一候选目录中。计数范围明确限定为当前返回页及其候选目录，不跨页猜测全局总数。

## AC-002 状态摘要分开结果引用与两类时效问题

- 状态: confirmed
- 来源: REQ-001 对项目根需求 AC-018、AC-028 的本轮投影
- 关联: REQ-001

`status` 与 `render` 不再用 `current_result_count` 暗示结果语义仍然当前，也不再用 `stale_result_count` 混称所有陈旧来源；输出分别表达当前状态引用的结果数、任务合同 revision 陈旧结果数、含来源快照问题的结果数、结果诊断条目数和按 kind 汇总。

## AC-003 分层汇总保持预算、分页和唯一证据闭包

- 状态: confirmed
- 来源: REQ-001 对项目根需求 AC-007、AC-018、AC-031 的本轮投影
- 关联: REQ-001

新增汇总只从最终返回的候选目录机械派生；预算移除目标或候选页变化后同步重建，不复制完整诊断、不引入跨页状态、不改变 snapshot、精确游标、门禁或候选证据字段。

## REQ-002 后继验证结果明确提供当前证据而不掩盖旧结果

- 状态: confirmed
- 来源: 用户确认下一版本应基于当前需求实际开发，并要求考虑全局完成语义
- 关联: AC-004, AC-005, CON-002

当后继任务重新执行或验证陈旧前置证据覆盖的行为时，其结果应以当前来源版本和直接验证明确声明所支持的目标；旧结果继续保留原来源快照和诊断，辅助工具不得静默过滤、改写或宣布其已恢复有效。

## AC-004 当前证据沿既有目标中心合同表达

- 状态: confirmed
- 来源: REQ-002 对项目根需求 AC-014、AC-028、AC-030 的本轮投影
- 关联: REQ-002

后继结果只有同时满足以下条件时，才能由模型作为相应目标的当前候选证据：`evidence_for` 明确列出重新覆盖的目标或合同 ID，`source_snapshot` 保存执行时实际使用且对这些 ID 完整的当前语义闭包，`verification` 与 `evidence_refs` 指向直接复测。任务依赖、`consumes`、任务状态或同页候选关系本身不表示重新验证。

## AC-005 CLI 不裁决旧诊断是否已被后继证据解决

- 状态: confirmed
- 来源: REQ-002 对项目根需求 REQ-005、AC-014、AC-017 的本轮投影
- 关联: REQ-002

`taskctl` 只返回旧结果诊断、后继结果证据和无歧义汇总，不生成整体通过值、诊断 resolved 状态或基于后继结果的自动抑制。最终复核仍由模型按当前用户确认目标、约束、DCR 和直接证据裁决。

## REQ-003 下一版本闭合正式 owner 与全部当前消费者

- 状态: confirmed
- 来源: 用户要求全面考虑需求并避免局部修改破坏全局
- 关联: AC-006, AC-007, CON-003, CON-004

本轮在 `task-table-manager` 的结果合同和查询投影 owner 中统一修正语义，并同步迁移 `completion-context`、`status`、`render`、文档合同、测试、真实工作区验证、skill 路由证据、项目总计划和完成审计。

## AC-006 所有共享消费者使用同一结果诊断聚合

- 状态: confirmed
- 来源: REQ-003 对项目根需求 AC-006、AC-021、AC-022 的本轮投影
- 关联: REQ-003

结果诊断继续由唯一 `result_diagnostics` 机制产生；查询、状态和生成视图只聚合其输出，不复制来源时效规则。旧歧义字段从仓库当前消费者退出，不保留无真实对象的兼容模式或第二统计入口。

## AC-007 原场景、变体与相近非触发场景共同验证

- 状态: confirmed
- 来源: REQ-003 对项目根需求 AC-027、AC-028、AC-033 的本轮投影
- 关联: REQ-003

验证至少覆盖：查询诊断为零但候选结果诊断非零、仅任务 revision 陈旧、来源快照缺失/不完整/陈旧、后继结果明确提供当前证据、只有依赖但没有当前证据声明、分页与预算裁剪，以及没有结果诊断的相近正常场景；再运行受影响模块回归、skill 校验、独立路由证据和真实工作区读回。

## CON-001 质量优先且不借汇总删减证据

- 状态: confirmed
- 来源: 项目根需求 CON-001
- 关联: REQ-001, REQ-002, REQ-003

不得为缩短输出删除结果诊断、来源快照、证据字段、目标关系、约束、DCR 或分页保护；汇总只帮助识别已返回事实，不替代完整证据。

## CON-002 不新增结果到结果的平行有效性状态

- 状态: confirmed
- 来源: 项目根需求 AC-006、AC-023 与当前最终复核目标中心合同
- 关联: REQ-002

本轮使用既有 `evidence_for`、`source_snapshot`、`verification` 和 `evidence_refs` 表达新的当前证据，不新增 `resolved_diagnostics`、`revalidated_result_refs` 或其他会与目标证据时效并行的第二状态源。若未来出现必须精确消费特定历史结果版本的真实消费者，再独立裁决结果版本依赖合同。

## CON-003 不混入来源快照压缩或插件迁移

- 状态: confirmed
- 来源: 用户明确限定本轮边界
- 关联: REQ-003

本轮不改变 `source_snapshot` 表示、引用池或压缩，不处理 AgentBase 插件迁移，也不借当前开发扩展其他架构改进。

## CON-004 Codex 发布仍需当次明确授权

- 状态: confirmed
- 来源: 用户再次强调发布授权边界与项目发布合同
- 关联: REQ-003

本轮可修改项目真源、验证并按项目既有 Git 授权维护版本；任何向实际 Codex 根目录执行 `Publish` 的操作仍须用户针对该次发布另行明确同意。
