# 常驻模型上下文与恢复面收敛：需求分析

## REQ-001 降低 AgentBase 高频模型读取面的完整决策成本

- 状态: confirmed
- 来源: 用户确认按“常驻上下文审计、handoff 先行”的建议继续开发
- 关联: AC-001, AC-002, AC-003, AC-004

AgentBase 应减少每个适用任务都会进入模型上下文的全局规则与 skill 路由面，以及接手时直接读取的恢复面成本；优化必须先保持目标、授权、证据、路由和执行质量，再比较完整输入成本，不以字符减少本身作为完成。

## AC-001 常驻规则保持跨项目行为合同

- 状态: confirmed
- 来源: REQ-001 与项目既有全局内核职责
- 关联: REQ-001

候选不得遗漏会改变目标校准、授权、安全、事实判断、owner、影响闭合、工具升级、验证或交付结论的全局不变量；不得仅因当前平台指令存在相似规则就删除 AgentBase 的可移植用户策略。

## AC-002 skill description 保持预加载路由边界

- 状态: confirmed
- 来源: REQ-001 与现有独立路由合同
- 关联: REQ-001

每个项目 skill 的 description 继续在加载正文前完整表达实际触发、关键非触发和必要协同边界。只有正文已加载后才需要的执行细则不得常驻 description；任何改动须由脱离仓库的 Routing、Policy 与 References 证据及适用回归证明没有路由退化。

## AC-003 handoff 只承担当前恢复职责

- 状态: confirmed
- 来源: REQ-001 与项目记录合同
- 关联: REQ-001

`docs/handoff.md` 应以最低充分范围恢复当前仓库版本、真实安装与发布状态、直接证据、未决候选、授权限制和精确后继入口；已由正式完成审计持有且不改变下一动作的历史展开只保留链接，不形成第二份历史说明。

## AC-004 使用同质量候选的真实模型 Token 验收

- 状态: confirmed
- 来源: REQ-001 与 CON-001
- 关联: REQ-001, CON-001

基线与候选使用同一适用 tokenizer 比较常驻规则、skill descriptions 和 handoff 恢复面；Token 只在语义与路由质量先成立后参与采纳，不把单次比例提升为固定项目阈值。

## CON-001 质量优先于 Token，Token 优先于速度

- 状态: confirmed
- 来源: 项目根需求 CON-001
- 关联: REQ-001, AC-004

不得为满足文件上限、缩短行数或追求比例而压缩会改变模型判断的信息；速度只在质量与上下文成本均不退化时参与选择。

## CON-002 不混入独立候选或新的 Codex 发布

- 状态: confirmed
- 来源: 用户确认按前述候选继续开发；本轮刚完成的发布授权只适用于已发布提交
- 关联: REQ-001

本版本不改变 `source_snapshot` 表示、引用池或时效语义，不实施插件迁移，也不把本次开发后的候选再次发布到 Codex；后续 Publish 仍需用户针对该次操作重新明确同意。
