# 常驻模型上下文与恢复面收敛：目标设计

## DES-001 三个正式 owner 分别形成最小充分读取面

- 状态: confirmed
- 满足: REQ-001, AC-001, AC-002, AC-003, UDES-001

`global/AGENTS.md` 只维护跨项目且在正文加载前就必须成立的执行不变量；各 `SKILL.md` description 只维护该 skill 的预加载触发、非触发与必要协同边界；`docs/handoff.md` 只维护当前恢复所需的项目状态与精确入口。三者不互相复制详细协议，也不新建统一摘要器或平行规则源。

## DES-002 语义单位先于文本单位裁决

- 状态: confirmed
- 满足: AC-001, AC-002, CON-001

候选以“缺失后是否改变适用任务的判断或动作”为准逐项裁决。当前平台重复、文件较长、句式相似或能移入另一个文件都不能单独证明可删除；只有既有 owner 已完整定义且当前读取时点无需该信息时才下沉，合并后仍须保持稳定、局部和可验证的边界。

## DES-003 验证链覆盖静态结构、独立路由与恢复充分性

- 状态: confirmed
- 满足: AC-001, AC-002, AC-003, AC-004

全局规则或 description 候选先通过结构、引用和内部冲突检查，再由不同的 detached evaluator 分别验证 Routing、Policy 与 References；handoff 候选用当前版本、真实安装状态、回滚入口、未决候选、授权边界和下一动作清单验证恢复充分性。最后在质量成立后比较同一 tokenizer 下的模型 Token。

## DES-004 发布生命周期与开发候选分离

- 状态: confirmed
- 满足: CON-002

提交 `86ee057` 已通过本次明确授权发布；本交付链的后续改动只进入仓库候选和 Git 历史。部署状态说明必须区分已发布基线与未发布开发候选，任何再次 Publish 都进入新的用户授权周期。
