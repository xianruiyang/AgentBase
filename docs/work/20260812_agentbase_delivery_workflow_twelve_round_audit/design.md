# AgentBase 交付链十二轮审查与改进：目标设计

> 使用 `DES-*` 二级标题记录满足需求所需的职责、接口、状态和依赖，并显式引用 `REQ-*` 与 `AC-*`。

## DES-001 每轮在上一轮已验证版本上重新建立证据

- 状态: confirmed
- 满足: REQ-001, AC-001, AC-002, AC-003, UDES-001, UDES-002

每一轮只选择由该轮直接证据确认的差距，先修订可变上游、投影任务、实施并完成目标同层验证；只有该轮结果成立后才开始下一轮。后轮不得沿用已经被修改的旧代码事实，也不得把重复运行同一检查计作新一轮。

## DES-002 工作流身份在创建和读取时始终有效

- 状态: confirmed
- 满足: REQ-001, AC-002

`workflow.json` 与 `task-table.json` 的 ID 和标题必须是非空、规范化的文本。创建入口不得产生自身后续命令无法读取的工作区，读取入口不得接受缺失身份的长期真源。

## DES-003 CLI 对预期环境错误保持有界机器可读输出

- 状态: confirmed
- 满足: REQ-001, AC-002

文件已存在、权限拒绝、路径类型错误等可预期的文件系统失败必须返回非零退出码和单个有界 JSON 错误，不输出 Python traceback；模型无需解析运行时堆栈即可决定修正输入或报告环境阻塞。

## DES-004 阻塞状态与阻塞原因构成单一一致事实

- 状态: confirmed
- 满足: REQ-001, AC-002

任务只有在 `status=blocked` 时才持有非空 `blocked_reason`，且进入 blocked 必须有原因。单独提交非空阻塞原因应把任务置为 blocked；离开 blocked 必须同时清除原因，避免状态统计与恢复上下文表达相反事实。

## DES-005 CLI 参数错误与运行错误共享机器可读协议

- 状态: confirmed
- 满足: REQ-001, AC-002

缺少必需参数、未知参数和非法 choices 等解析失败也必须返回退出码 2 和单个有界 JSON 错误。`--help` 仍保留标准人类可读帮助；调用错误不应切换到另一种输出格式。

## DES-006 截断的任务与图查询必须可连续消费

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

`list`、`next`、`deps` 和 `dependents` 在限制条目后必须返回稳定续页游标，并接受该游标读取下一页；未改变输入时逐页可遍历全部匹配项。游标失效应明确报错，而不是静默从头或漏项。

## DES-007 受保护基线必须保留可验证的用户确认来源

- 状态: confirmed
- 满足: REQ-001, AC-003, UDES-001

基线只接受 `confirmed_by=user` 和非空、规范化的 `confirmation_ref`。创建与每次读取都验证这两个字段，并在摘要中暴露确认引用；文档哈希完整不能替代“由谁、依据哪次确认”成立。

## DES-008 独立任务表初始化必须服从既有交付工作流身份

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003, UDES-001

在包含 `workflow.json` 的目录恢复缺失任务表时，`taskctl init` 只能使用该 workflow 的同一 ID 与标题；不允许创建写入成功但立即被组合读取拒绝的平行身份。

## DES-009 语义图只由明确关系字段建立

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

索引只从条目的 `关联/关联需求/关联目标/满足/解决/依赖/后继证据/目标ID` 等正式关系字段提取 ID。标题、正文、代码示例、来源和证据描述中偶然出现的 ID 形文本不能建立引用、未知引用或最终候选链。

## DES-010 done 状态必须源自实际执行阶段

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

`complete` 只接受 `in_progress` 或 `review`。`todo/claimed` 尚未表示实际执行，`blocked` 明确表示不能继续；这些状态必须先通过现有 start/note 路径进入可完成阶段。该状态约束只保护执行记录，不裁决结果语义是否充分。

## DES-011 最终上下文的目标、约束和 DCR 作为独立流分页

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

首次完成上下文可以同时返回三类首屏；后续目标、单目标候选、约束或 DCR 页只返回请求的流，并标明本页流类型。所有续页继续使用同一 snapshot；不同流的游标不能混用或组合。

## DES-012 任务表导出与状态查询共享同一存储事实

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

`TASK_TABLE.md` 必须使用与 `status` 相同的当前结果校验和汇总路径，显式展示需复核数、当前结果数、含验证结果数与含未决结果数。损坏或过期的当前结果不能只在 JSON 查询失败，却继续被导出视图显示为正常结果。

## DES-013 总工作状态视图同时呈现三类闭合度与确认来源

- 状态: confirmed
- 满足: REQ-001, AC-002, AC-003

`WORK_STATUS.md` 必须分别呈现任务执行、可修订语义和任务结果证据三类状态，并显示受保护基线的确认者和确认引用。三类计数只是接手与复核导航；视图继续明确声明不产生最终完成判定。
