# AgentBase 交付工作流渐进上下文下一版：方案设计

## SOL-001 拆分交付产物合同并建立动作路由

- 状态: confirmed
- 解决: GAP-001
- 满足: DES-001, DES-002, AC-001, CON-002
- 依赖: 无
- 风险: 拆分后遗漏共享定义或让同一语义在多个引用重复；通过唯一 owner 搜索和链接校验控制
- 验证: `delivery-workflow` 结构校验；静态合同检查全部引用、阶段映射与关键语义唯一归属；完整交付链仍可达全部合同

把 `artifact-contracts.md` 收敛为工作区、稳定 ID 和通用条目的公共合同；新增受保护目标、可修订规划、执行与完成三个职责引用。`SKILL.md` 作为正式入口根据当前动作选择公共合同与适用阶段合同，迭代和工具引用继续条件加载，不保留旧全文副本。

## SOL-002 在交付 owner 定义最小语义闭包与扩展条件

- 状态: confirmed
- 解决: GAP-002
- 满足: DES-003, DES-004, AC-002, AC-003, AC-004, CON-003
- 依赖: SOL-001
- 风险: 过度压缩可能遗漏间接约束；规则必须把歧义、来源失效、权威变化、实际影响和最终复核列为语义扩展条件
- 验证: 静态合同检查最小闭包、扩展条件和最终完成集合；相近非触发场景不被要求全量读取

在 `delivery-workflow` 的执行原则与迭代合同中定义最小闭包；`task-table-manager` 保持既有压缩消费者职责，只在需要时引用交付 owner 的扩展判断，不复制完成标准或阶段语义。

## SOL-003 刷新验证证据并闭合项目计划

- 状态: confirmed
- 解决: GAP-003
- 满足: DES-005, AC-005, AC-006, UDES-001, UDES-002
- 依赖: SOL-001, SOL-002
- 风险: 仅通过静态检查不能证明模型行为；独立评估必须脱离仓库且不接触隐藏期望
- 验证: 受影响 skill 快速校验、定向合同测试、项目路由合同、独立 routing/policy/reference 证据，以及本轮阶段引用行为评估

更新静态合同与必要评估输入，把 References 阶段从单个硬编码 skill 泛化为声明式条件引用评估，同时覆盖治理与交付合同选择；按公开 skill 变化刷新三阶段 detached 证据，验证局部阶段、执行扩展、最终复核和简单非触发边界。最后逐项审计本轮目标和根需求覆盖，更新 `docs/plan.md`，提交并同步 Git；Codex 发布保留为需用户当次确认的已知部署差距。
