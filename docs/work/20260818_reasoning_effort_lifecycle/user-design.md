# 推理深度生命周期：用户设计

## UDES-001 深度设置与 Goal 解耦

- 状态: confirmed
- 来源: 用户在实验前提出若 Goal 只是生效载体则应探索，并在实验后明确无 Goal 也可临时设置
- 关联: REQ-001, AC-001

模型想改变深度时直接临时设置；不能把“是否有 Goal”继续当成允许设置的门槛。Goal 只有在实际需要自动进入下一轮时才承担续跑职责。

## UDES-002 用户固定档位是当前工作的优先约束

- 状态: confirmed
- 来源: 用户明确补充固定档位可能是额度耗尽后的合理使用方式
- 关联: AC-002

用户需要在一个对话中持续使用指定深度时，模型先按该档位工作，直到用户声明的期限结束或用户明确修改；不以模型自己的档位判断对抗用户选择。

## UDES-003 先开发验证，发布另行授权

- 状态: superseded
- 来源: AgentBase 每次 Publish 的用户授权合同，本轮未给出新的发布指令
- 关联: CON-002

本次只完成真源、规则、skill、脚本、测试和候选验证，不把修改安装到真实 Codex 根目录。

## UDES-004 主代理只为可预期长期阶段切档

- 状态: confirmed
- 来源: 用户明确选择“主 agent 继续原来的切换机制，不过是可预期长期任务难度时才切换”
- 关联: REQ-001, AC-006

主代理继续按实际判断负担形成目标档位，但不为孤立难题或短收尾切换 next-turn 配置；只有后继阶段可预期持续足够久时，才让档位变化承担切换和恢复成本。
