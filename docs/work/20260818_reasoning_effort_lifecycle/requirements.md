# 推理深度生命周期：需求分析

## REQ-001 让模型在真实工作中可靠调节 next-turn 深度

- 状态: confirmed
- 来源: 用户要求探索真实切换机制并按实验结果继续完善
- 关联: AC-001, AC-002, AC-003, AC-004, AC-005, AC-006

Codex 应能依据下一段工作的真实判断负担自主升降当前线程的 next-turn 推理深度，不把 Goal、任务形式、领域 skill 或当前档位是否已知误当成判断边界，并能以直接读回证明配置结果；状态查询与实际切换只在能改善完整工作质量或总体成本时发生。

## AC-001 无 Goal 时也允许自主临时切换

- 状态: confirmed
- 来源: 用户明确说明“无 goal 时也不需要用户授权，你要改思考深度就临时设置就行”
- 关联: REQ-001

用户没有固定深度且目标等级与当前配置不同时，模型可直接设置 next-turn 深度。设置只服务当前已识别工作；active Goal 只负责自动续轮，没有 Goal 时由下一次自然用户消息进入新配置。

## AC-002 用户固定深度保持优先

- 状态: confirmed
- 来源: 用户明确要求临时固定对话深度时先按用户要求执行，并指出可能存在额度耗尽后的合理使用需求
- 关联: REQ-001

用户指定的等级在其声明范围内压过模型自主升降；没有显式结束条件时持续到用户明确改变或释放。模型不审查用户额度理由，也不以质量偏好静默提高或降低档位。

## AC-003 长对话仍能结构化读回真实配置

- 状态: confirmed
- 来源: 本轮真实线程实验暴露 19 MB snapshot 的现有读回误判
- 关联: REQ-001

脚本必须在受支持帧上按真实 JSON 结构识别 conversation state 的 `latestThreadSettings.effort`，不依赖字段恰好落在固定尾部，不被对话正文中同名字样误导，并保持有界内存。

## AC-004 模型输出最小充分、机器输出完整稳定

- 状态: confirmed
- 来源: 项目 REQ-012 与本工具直接进入模型上下文的实际用途
- 关联: REQ-001

默认调用只返回判断切换是否成功所需的紧凑证据；显式机器视图继续返回完整结构化回执。两者由同一 IPC 结果投影，不建立第二事实源。

## AC-005 负担判断不得被内容路由或切换成本掩盖

- 状态: confirmed
- 来源: 用户指出长时间 skill 机制探索没有切换并要求按最优方式处理；当前对话直接证明当时没有运行状态读回
- 关联: REQ-001, AC-001

用户未固定档位时，在下一段实质工作前先独立判断目标档位。档位证据不足但错配可能实质影响质量或总体成本时才查询；只有实际不同且剩余工作足以摊销设置、结束当前轮、续轮等待与恢复成本时才切换。短小可在当前轮闭合的工作不为精确知道档位付出固定查询或切换成本。

## AC-006 自主切换只服务可预期长期阶段

- 状态: confirmed
- 来源: 用户要求主代理继续动态切换，但只在可以预期后续长期任务难度时切换
- 关联: REQ-001, AC-001, AC-005, UDES-004

自主切换除满足档位错配和净收益外，还必须有直接任务结构支持后继阶段会长期保持不同判断负担。孤立的高难问题、已经开始的当前轮以及复杂工作后的短机械收尾沿用当前档位，不为一次性局部负担承担 next-turn 中断与恢复成本。

## CON-001 不用持久状态或 Hook 模拟临时生命周期

- 状态: confirmed
- 来源: 项目唯一真源与辅助工具边界
- 关联: REQ-001, AC-001, AC-002

不把用户固定状态、临时基线或恢复义务写入任务表、Goal、Hook、项目文件或脚本状态文件。当前对话中的用户指令和经验证回执承担本轮短期上下文；无法可靠恢复已丢失的先前意图时不猜测。

## CON-002 原实施轮不发布到 Codex

- 状态: superseded
- 来源: 项目发布合同；用户当前只授权继续开发
- 关联: REQ-001

本轮形成仓库候选并执行部署 `Validate`，不执行真实 `Publish`；任何发布仍需用户针对当次操作重新明确同意。

## CON-003 本次允许发布更新后的推理与子代理合同

- 状态: confirmed
- 来源: 用户 2026-08-23 明确要求完善后发布
- 关联: REQ-001, AC-006

本次完成验证后允许按真实安装模式向当前 Codex 根目录 Publish 一次并读回状态；该授权不继承到以后发布。
