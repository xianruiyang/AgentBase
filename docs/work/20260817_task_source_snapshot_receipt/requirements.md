# Task 来源快照收据需求

## REQ-001 模型只处理完成当前动作所需的来源证据

- 状态: confirmed
- 来源: 用户确认采用“机器持有完整快照，模型只持有快照收据”的改进方案
- 关联: AC-001, AC-002, AC-003, AC-004

`taskctl` 应让模型读取实际上游正文并携带一个可定位的快照收据，不再把完整 `来源 ID → 指纹` 映射作为模型上下文或模型编写结果的一部分；机器消费者仍可取得完整、稳定且可验证的来源快照。

## AC-001 快照严格对应最终模型可见来源

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

快照只能包含最终 Token 预算投影后确实返回给模型的上游条目。预算移除任何条目时，同步移除其快照成员、标记不完整并提供可定位恢复信息。

## AC-002 结果以不可变引用保存机器来源证据

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

捕获的完整映射以内容寻址、不可变的机器资产保存；新结果只引用该资产。相同映射复用同一资产，模型结果输入不复制或修改指纹。

## AC-003 机器完整性和逐来源时效诊断不退化

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

机器视图可以读取完整映射；快照缺失、损坏、覆盖不足和逐来源陈旧保持可区分，不能退化成只有整体摘要哈希是否变化。

## AC-004 真实旧结果可读而新写入退出内联格式

- 状态: confirmed
- 来源: REQ-001
- 关联: REQ-001

现有内联 `source_snapshot` 结果继续只读兼容；新完成结果统一保存快照引用。旧调用提交的内联映射可由唯一写入口外部化，但不得让永久结果继续产生两种同责表示。

## CON-001 本版本边界

- 状态: confirmed
- 来源: 用户要求先不处理 handoff，并在此前版本中保持插件迁移独立
- 关联: REQ-001

本版本不维护 handoff，不实施插件迁移，不执行真实 Codex 发布。
