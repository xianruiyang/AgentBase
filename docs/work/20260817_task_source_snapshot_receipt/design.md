# Task 来源快照收据设计

## DES-001 快照唯一 owner

- 状态: confirmed
- 关联: REQ-001, UDES-001

`task-table-manager/taskctl` 继续唯一拥有执行来源闭包、指纹、持久化和时效诊断。`delivery-workflow/workctl` 只消费结果诊断摘要，不复制快照生成或比较语义。

## DES-002 最终投影后捕获

- 状态: confirmed
- 关联: AC-001, UDES-001

模型候选先按 Token 预算选择最终可见的 `upstream`，再从这些条目对应的指纹形成捕获映射。`context --capture` 将映射写为不可变快照并返回收据；普通查询不承诺产生可用于完成的持久快照。

## DES-003 内容寻址机器资产

- 状态: confirmed
- 关联: AC-002, AC-003, UDES-001

快照存放于任务工作区固定 `snapshots/` 目录，身份是规范化快照正文的 SHA-256。文件持有完整映射，结果持有 `source_snapshot_ref`；读取时校验路径身份、正文身份和内容，再按当前索引逐来源比较。

## DES-004 单向兼容

- 状态: confirmed
- 关联: AC-004

读取器接受历史内联映射或新引用，每个结果只能有一种权威表示。新 `complete` 使用显式引用；仅收到旧内联输入时由同一入口外部化并诊断，永久写入仍只产生引用。

## DES-005 捕获资产生命周期

- 状态: confirmed
- 关联: AC-002, DES-003

捕获成功后不自动删除暂未被结果引用的快照：执行中的模型可能仍持有该收据，CLI 无法仅凭当前结果表证明它已失效。内容寻址复用相同映射，避免重复资产；只有真实存储增长成为问题时，才基于“结果引用、活跃执行收据和明确保留期”设计独立回收合同，不用当前状态猜测并删除证据。
