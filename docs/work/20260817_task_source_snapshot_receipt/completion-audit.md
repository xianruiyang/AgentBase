# Task 来源快照收据完成审计

## 审计结论

本仓库开发候选已经在 Task Table Manager 的正式 owner 和结果合同层闭合来源快照职责：模型看到并传递最小收据，完整 ID—指纹映射由机器持有；捕获发生在最终模型预算投影之后，新结果只保存内容寻址引用。Delivery Workflow 只消费固定存储目录和结果诊断，没有形成第二套快照语义。捕获资产按内容去重但不自动删除，因为当前结果表不能证明执行中的收据已经失效；未建立可能误删证据的猜测式回收入口。

该结论不表示实际 Codex 已更新。本轮没有维护 handoff、迁移插件或执行 `Publish`。

## 正式 owner、消费者与旧路径退出

| 层 | 正式职责 | 当前状态 |
| --- | --- | --- |
| `task-table-manager/taskctl` | 选择执行来源闭包、在最终模型投影后捕获、内容寻址存储、结果引用、展开和时效诊断 | 唯一 owner，已实现并回归 |
| 模型 context/result 面 | 读取 `ref/count/complete`、语义异常和恢复入口；只编写结果语义 | 不再读取或复制完整指纹映射 |
| machine 面 | 读取稳定结果引用及按需展开的完整映射 | 保持完整结构化合同 |
| `delivery-workflow/workctl` | 初始化任务存储并消费任务结果摘要 | 已接入 `snapshots/`，未复制快照算法 |
| 历史内联结果 | 仅作为真实旧资产的读取兼容 | 保留；所有新写入单向退出到引用格式 |

结果不得同时含内联映射和引用；CLI 参数与结果文件提供不同引用时同样拒绝。该门禁只阻止无法机械判定唯一执行来源的写入，不替代模型对结果是否足以完成目标的判断。

## 验证与边界

[验证记录](verification.md)覆盖 78 项 Task Table Manager 回归、35 项 Delivery Workflow 回归和静态路由合同。测试同时覆盖原完整场景、预算裁剪变体、相近无捕获读取、去重、旧工作区、旧结果、新写入、缺失/损坏资产、陈旧来源以及重复诊断消除。

仓库候选已满足本子计划需求，但正式部署 `Validate` 前仍需刷新 detached Routing、Policy、References evidence；本轮尚未执行该外部独立评估。若收据成员与最终模型可见来源不一致，machine 展开或逐来源诊断退化，新结果重新产生内联映射，发现仍依赖旧写入格式的真实消费者，或未引用捕获资产出现可证实的长期增长，应重开本计划；最后一种情况需先定义活跃收据和保留边界，再考虑回收。任何向实际 Codex 根目录执行 `Publish` 的操作仍须用户针对该次发布明确同意。
