# Task 来源快照收据方案

## SOL-001 让模型预算投影决定捕获成员

- 状态: confirmed
- 解决: GAP-001
- 满足: AC-001, AC-002

重构模型拟合，使 `context` 的每个预算候选同步按当前 `upstream` 过滤来源映射。最终选择后，`--capture` 才持久化该映射并把模型字段替换为 `{ref,count,complete}`；无捕获查询只返回数量、完整性和捕获提示。

## SOL-002 建立不可变快照存储和结果引用

- 状态: confirmed
- 解决: GAP-002
- 满足: AC-002, AC-003
- 依赖: SOL-001

在 `snapshots/` 保存内容寻址机器资产，新增引用验证、原子写入、重复复用和读取校验。`complete --source-snapshot-ref` 把引用附加到语义结果；结果读取为机器视图展开完整映射，模型视图只保留收据摘要。

## SOL-003 保持诊断并单向退出旧写入

- 状态: confirmed
- 解决: GAP-002
- 满足: AC-003, AC-004
- 依赖: SOL-002

逐来源诊断消费已展开映射，并增加资产缺失、无效和身份不匹配诊断。历史内联结果直接读取；旧式完成输入由 `complete` 外部化为快照引用并返回兼容诊断，新结果不得同时保存引用和内联映射。

## SOL-004 闭合合同、消费者和原触发场景

- 状态: confirmed
- 解决: GAP-001, GAP-002
- 满足: REQ-001, AC-001, AC-002, AC-003, AC-004, CON-001
- 依赖: SOL-001, SOL-002, SOL-003

同步更新 task-table-manager 的正式合同、静态校验和受影响消费者测试；验证完整与预算裁剪上下文、去重、机器展开、缺失/损坏/陈旧、旧结果和旧完成输入，并确认 workctl 摘要继续由 taskctl 诊断语义驱动。只形成仓库候选，不发布 Codex。
