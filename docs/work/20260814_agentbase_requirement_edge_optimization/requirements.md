# AgentBase 根需求收益边缘持续优化：需求分析

## REQ-001 持续把项目根需求落实为 Codex 实际能力

- 状态: confirmed
- 来源: 用户当前持续目标与 `docs/requirements.md`
- 关联: AC-001, AC-002, AC-003, CON-001, CON-002

持续审查 AgentBase 项目真源、运行时规则、skill、辅助工具、验证与发布链，优先修正仍会妨碍项目根需求成为 Codex 实际行为的高收益差距。

## AC-001 每轮形成一个完整且可验证的改进

- 状态: confirmed
- 来源: 用户要求“每完成一次完整的优化后允许直接发布”
- 关联: REQ-001

每轮都应有直接证据确认差距，裁决正确职责与消费者，完成实现、必要影响闭包和最小充分验证；不得用文档表述、局部检查或修改数量代替实际改进。

## AC-002 完整改进发布到 Codex 并读回

- 状态: confirmed
- 来源: 用户授权每轮完整优化后直接发布到 Codex
- 关联: REQ-001

每轮通过项目发布合同与独立路由评估后，使用正式部署入口发布到当前 Codex 根目录，并读回项目候选、安装内容、发布清单和路由证据一致性。当前已启动任务不会追溯加载新规则。

## AC-003 迭代至剩余改进到达收益边缘

- 状态: confirmed
- 来源: 用户要求持续优化到收益边缘
- 关联: REQ-001

每轮发布后以新状态重新审查候选；只有剩余候选的预期质量或维护收益均不足以覆盖新增规则、Token、复杂度、迁移、验证和回归成本，且不存在未满足的明确根需求或适用验证失败时，才结束持续优化。

## CON-001 优化顺序继承项目基本准则

- 状态: confirmed
- 来源: `docs/requirements.md` CON-001
- 关联: REQ-001

先保证需求洞察、正确性、授权、安全、可维护性和完成证据，再降低 Token，最后提升速度；后两项不得损害前项。

## CON-002 只修改项目真源并使用正式入口

- 状态: confirmed
- 来源: 项目权威与发布约束
- 关联: REQ-001

改进只在 AgentBase 项目真源形成，不直接编辑 Codex 安装副本；CLI 继续只作辅助，发布只通过正式部署入口完成。
