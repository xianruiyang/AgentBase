# 权威职责生命周期与影响传播

## 目的与边界

本文件记录 AgentBase 对长期职责发现、公共能力形成、消费者接入、后续演化和穿透式修正的设计分析。它服务于全局规则与相关 skill 的维护，不是运行时规则源，也不随 skill 安装。

目标不是按代码相似度推动抽象，而是让同一语义职责具有可持续维护的权威 owner：模型在实现前识别职责，在当前消费者之间收敛决定路径，在 owner 后续变化时沿实际依赖传播修正，并证明旧语义已经退出。项目继续遵守“文档定义流程语义、模型裁决、CLI 只辅助查询与机械校验”的既定边界。

## 当前基础

现有链路已经包含以下能力：

- [`global/AGENTS.md`](../global/AGENTS.md) 以长期净收益、系统总成本、职责与权威收敛选择方案，并要求新证据推翻上游判断时返回最早失效层。
- [`change-governance`](../skills/change-governance/SKILL.md) 裁决 owner、正式入口、依赖方向、迁移和旧路径退出。
- [`delivery-workflow`](../skills/delivery-workflow/SKILL.md) 以稳定语义 ID 连接设计、现状、方案、任务和结果；`workctl impact` 沿显式反向引用递归返回潜在下游。
- [`task-table-manager`](../skills/task-table-manager/SKILL.md) 记录任务依赖、消费结果、上游来源指纹、陈旧诊断和反向失效反馈；`taskctl impact` 递归返回任务后继。
- CLI 不自动重置状态、批准语义或宣布完成，避免工具成为第二规则源。

这些机制分别覆盖了“执行反例推翻上游”“上游修订查询下游”和“结果来源可能陈旧”，但还没有形成连续的职责生命周期。

## 改进前确认的差距

本节记录本轮修改所依据的基线问题，用于解释后续设计选择，不描述改进后的当前实现状态。

### 识别发生得过晚

改进前的规则善于在职责错位、第二状态源、额外适配或公共能力缺口已经暴露后纠正，但没有充分要求模型在选择实现位置前先按稳定约束、状态与生命周期、失败边界、变化原因和当前消费者确定权威职责。若模型把请求表面、调用位置或文件边界当作归属，后续治理 skill 可能根本不会触发。

### 共同职责缺少语义判据

改进前的治理会比较 owner 和入口，却没有明确区分“共享同一稳定不变量与变化原因”和“仅实现形态相似”。这会同时留下漏合并和错误抽象两类风险。一个权威职责可以允许消费者边界上的策略差异或多个受控适配实现；职责收敛不等于强制物理代码只有一份。

### 建立公共能力与实际接入没有构成同一结果

交付文档和任务合同能够表达公共产出及消费者依赖，但改进前没有明确要求公共 owner、当前消费者接入、旧同责路径退出和直接验证共同闭环。只创建模块、接口或任务而没有消费者实际使用，仍可能被局部状态误表达为完成。

### 影响图依赖人工登记

`workctl impact` 只能遍历阶段文档中明确关系字段形成的语义图，`taskctl impact` 只能遍历任务合同声明的依赖图。真实调用、复制判断、适配、派生配置、生成内容、持久化数据和验证证据若未被模型发现并写回正式关系，就不会进入后续查询。工具返回的是已声明图上的候选，不是实际系统影响范围的证明。

### 影响候选没有完成闭包

改进前的 [`iteration.md`](../skills/delivery-workflow/references/iteration.md) 已要求逐项判断下游仍有效、更新、重做或重验，但没有明确要求所有候选都形成可恢复的持久裁决，并据此修订、重开、退休或重新验证任务与结果。影响查询可能退化成一次提醒，未检查对象也可能被静默当作不受影响。

### 结果来源版本记录时点不可靠

改进前的 `taskctl complete` 在结果未提供 `source_snapshot` 时读取完成时刻的当前上游指纹。任务可能依据更早版本执行，上游在任务读取之后、完成之前变化时，完成时自动生成的指纹不能证明工作实际使用了新版本。改进前的 `taskctl context` 又没有返回可直接携带进结果的来源指纹，因此跨轮或并发执行存在旧工作被误表达为新鲜结果的时间窗。

此外，来源时效主要覆盖任务显式列出的 `source_ids` 和结果 `evidence_for`；语义影响查询虽然可以递归，上游来源指纹却未自然覆盖传递祖先，两者边界不一致。

### 最终完成尚未覆盖职责演化闭包

最终目标继续只来自用户确认的 `REQ/AC/UDES`，这是正确边界。但改进前的完成合同没有充分要求：当本次方案改变长期 owner、正式契约、状态或共享行为时，还需证明直接影响范围内的消费者和完成证据已经与新语义一致。否则用户可见验收局部通过时，旧消费者、复制逻辑或陈旧证据仍可能保留。

## 目标思维模型

长期职责按以下顺序处理：

1. 从目标行为提取稳定约束、状态与生命周期、失败或持久化边界和变化原因。
2. 在授权影响范围内确认现有 owner、实际消费者、正式入口、派生产物和依赖方向。
3. 共享同一语义职责的当前消费者使用同一权威 owner；消费者特有策略保留在边界。仅表面相似或假设未来复用不建立公共职责。
4. 把 owner 能力、当前消费者接入、旧同责路径退出和验证设计成一个结果；若拆成任务，使用真实产出和消费依赖保持闭环。
5. owner 或契约变化前取得当前影响集合；变化后结合旧、新语义关系和实际系统重新确认直接与间接影响。
6. 对每个适用下游以证据裁决仍有效、更新、迁移、退出、重做或重验，并把结果写回其所属设计、方案、任务或结果记录。
7. 仍依赖旧语义、来源版本未知、未检查但适用或超出授权且影响当前结果的必要对象，使该变更不能声明完成。

影响传播在证据证明对象不再语义依赖该变化时终止，不按目录、文件或依赖层数任意截断，也不因长期收益扩展到与当前结果无关的历史清理。

## 正式职责分布

### 全局规则

全局 `AGENTS.md` 只保留始终需要的认知内核：长期行为先确定语义 owner；出现第二消费者、重复判断或新增适配时尽早返回上游；权威变化后沿实际依赖复核消费者和证据，未形成影响闭包不得完成。

### Change Governance

`change-governance` 只在 owner 不明确、需要新增共享职责、存在多个决定路径、跨消费者迁移或普通完成判断无法覆盖传播闭包时提供详细方法。已有唯一 owner 且依赖明确的普通实现不为形式完整触发治理。

### Delivery Workflow

`delivery-workflow` 在 `DES` 表达 owner、共同不变量、消费者差异和依赖方向，在 `OBS/GAP` 对照实际消费者与绕过路径，在 `SOL` 形成 owner 修正、接入、退出和验证结果。新证据或主动上游修订都要保存修改前影响集合，重新发现实际依赖，并把裁决写回现有阶段产物。

### Task Table Manager

`task-table-manager` 使用现有 `source_ids`、`dependencies.consumes`、`outputs`、状态和结果表达执行投影，不新增语义状态源。任务取得上下文时返回实际读取的传递上游指纹，结果携带该快照；完成时当前指纹只用于比较，不得替代实际输入版本。递归影响查询返回依赖路径和消费内容，但不自动判定失效或重置状态。

## CLI 与门禁边界

CLI 可以机械完成稳定 ID 索引、关系遍历、依赖路径展示、来源指纹采样、当前版本比较和陈旧诊断。它不得从相似代码、引用数量、任务状态或指纹变化推断共同职责、影响语义、更新必要性或完成结论。

来源缺失、关系覆盖不完整、陈旧结果和未闭合影响继续作为诊断。只有既有合同允许的路径、覆盖、锁、revision、资源、唯一定位和复核快照风险可以阻断当前命令。本次设计不新增语义硬门禁。

## 本轮落地结果

- 全局规则在方案选择前要求按稳定约束、生命周期、失败边界、变化原因和当前消费者确定权威职责，并把预期外消费者、重复决定路径和公共能力缺口视为返回上游重新裁决的信号。
- `change-governance` 明确共同职责的语义判据、公共能力形成条件和权威变化后的逐消费者持久裁决；已有唯一 owner 且依赖明确的普通实现不为形式完整触发。
- `delivery-workflow` 在设计、现状、方案、任务和最终复核中分别承载 owner、实际消费者、接入与退出、消费关系和影响闭环，不建立独立影响账本。
- `task-table-manager` 让执行上下文返回传递上游的实际指纹，结果原样携带该快照；完成时只比较当前版本并诊断缺失、不完整或陈旧，不再伪造完成时刻的新鲜快照。
- `workctl impact` 和 `taskctl dependents/impact` 返回首条传播路径；任务路径同时返回该边实际声明的消费内容。路径只帮助定位，不替模型判断影响语义。
- 路由合同加入职责形成、影响闭合和表面相似但不应合并的中文盲评场景；这些场景只存在于开发验证，不进入运行时规则或 skill 提示。

## 验证边界

静态合同验证规则内容、引用、触发边界和路由标签；脚本回归验证递归路径、来源快照记录时点和陈旧诊断；独立行为评估验证模型能识别共享职责、拒绝错误合并、传播权威变化、处理陈旧证据并守住授权边界。任何一层都不能替代真实任务中对实际消费者、旧路径退出和运行行为的验证。
