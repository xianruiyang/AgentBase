## 收敛后的机制

- Provider 两次均为 2 个命令，HJSON 为 3/5 个命令；四次合计 `345,210` Token。v5 的普通高级 skill、rg/fd 引用、LSP 引用与 help 误触发已基本退出，证明专项触发方向有效。
- containing 两次为 7/8 个命令、合计 `390,993` Token，单独占整批 53.11%。模型在唯一实现文件已经确定后，仍用多个宽泛 anchor 和 `-C` 窗口反复搜索同一文件，再追查 fingerprint 上游；两次产生 53,240 个工具 stdout 字符，一次查询还因错误候选路径 exit 1。
- 当前 2048 同预算闭环没有隐藏成本，但不足以完整容纳这些宽泛上下文查询。局部 8192 原型会返回近整文件的 19,711 字符且仍有续页，不能作为低成本修复。
- 剩余问题属于“已知文件正文仍被当作搜索任务”的模型调用选择。srcq 不能在不改变 rg 结果集合的前提下擅自返回整文件，也不能从任务自然语言猜所需函数；正确 owner 是一条更短、更显著的已知正文直读边界，而不是高预算、专用 containing 命令或 anchor 特例。

## 下一裁决

把全局源码路由压成一条：srcq 是文件/文本搜索入口；文件已知后正文直接有界读取且不再搜索重读；文本不足才升级；普通搜索不预加载高级说明；最终定位、全集与不存在结论保留必要限定。删除其余规划术语。`source-query` 继续保持专项，不增加 containing、fingerprint 或 benchmark 示例。新身份只在机制变化后运行。
