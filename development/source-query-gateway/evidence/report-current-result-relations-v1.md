日期：2026-09-04。仅属开发证据，供代码阅读迭代与复核，不进入 payload。数据来自正式 runner 的冻结输入、最终答案、逐请求 usage 与原始事件；[审计](audit-current-result-relations-v1.json)保存逐次指标和评分裁决，原始根为 `D:\AgentBaseBench\current-result-relations-v1\pilot-ready`。环境或语料变化后不得外推。

## 候选与边界

在当前中文内核的既有最终回复条款中，加入通用对象、关系、条件结果的紧凑表达规则，区分对象自身范围与关系发生位置；不改变查询规则、skills、工具、题面、24项 required 或旧最佳批量对照。没有加入项目路径、函数名、答案或语言配方。与前轮英文候选不同，本组回到当前中文基础，不叠加翻译变化。

固定 v23 TS、Luna medium/default、每侧两次、同 CLI/srcq、禁止受测子代理。仅由正式 preparer 复制各自 AgentBase-owned skills，不复制其他 skills 或源码工作区。独立静态复核确认仅一条回复规则变化；这不证明行为改善。

## 机制与下一动作

候选第一次的前两条裸 rg 命令、第二次的首条裸 rg 命令使用含引号的模式并失败，后续恢复；本组未单独复现 shell 错误类型。旧版无命令失败。候选第一次后续 stdout 已含宿主58/60，最终答复仍遗漏，因此表达规则没有可靠保留这些关系位置。请求和费用增加不能只归因于答复规则，命令错误与采样差异同时存在。

**候选不晋级，不扩全九题，不部署，生产内容不变。** 整体目标保持未完成。

只读入口检查确认：`experiment.py` 的子进程环境写入目标 `CODEX_HOME`（969–976），App Server 以该环境启动（1291–1315），thread/start 与 turn/start 使用题目工作目录（1381–1406）；没有显式 baseInstructions/developerInstructions 覆盖，两个 home 的 AGENTS 均小于配置的65536字节上限。[官方 AGENTS 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明默认从 CODEX_HOME 发现全局指令，缺少显式 instruction 参数本身不是故障；官方同时提供日志/会话记录的加载审计方式。该文档与正确配置不能反推历史请求实际消费的完整指令链，但现有证据也不支持“规则没加载”的结论，不据此改造 runner 或废弃旧实验。

后续已通过 CLI 自带 `debug prompt-input` 做无模型采样诊断：两侧全局 AGENTS 整篇文本均出现，非空行无缺失，见[加载诊断](audit-native-instruction-ingress-v1.json)。这直接覆盖当前原生发现/渲染路径，不重建历史 App Server 请求；没有据此新增门禁或改造 runner。后续把命令可靠性与答复遗漏分开处理，不把二者都归因于最终回复条款，也不继续以“未加载”解释当前反例。
