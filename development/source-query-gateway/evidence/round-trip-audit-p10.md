## 1. 证据与结论边界

- 审计对象：P9 最终 candidate identity `e32871ba9c0f8b19716e7b191260c29666939879215350baa4604d1bfd9c7ac4` 中三个相对历史上升的 case，各两次，共 6 个 run、28 次成功命令。

- 结论边界：以下“最少 10 次”是基于当时已知输入和证据依赖得到的反事实下界，只证明无需新增高层命令即可表达闭环；它不是模型实际采用该路径或 Token 已下降的验证结果。

分类中的“可合并”表示调用时所需输入已经已知，能够与同一闭环内的另一有界查询在一次模型决策中取得；“可删除”表示其没有增加回答所需事实，或后续事实已经由更早的适用结果直接覆盖；“保留”表示当前路径中存在真实范围、定位或正文职责。保留调用仍可收紧输出，不能据此把所有调用机械并行。

## 4. 第一阶段结论的证据上限

上述 28 次调用证明现有命令面能够表达答案，不证明默认输出已经把该能力交付成最低总成本路径。随后四个候选身份反复出现同一现象：`srcq` 已捕获完整结果，却先按固定页预算返回 `@more`；模型不知道当前页之后是否正好包含所需定义边界，因而改写锚点、分段重读或追加确认。规则层可以要求停止，但不能机械知道未展示结果的形状；把该缺口全部归为模型规划会把输出职责错放到常驻规则。

因此原 DEC-SQG-001 的“只改规则、不改工具”结论失效。`srcq` 仍不应新增替模型裁决语义的 `inspect`，但它必须利用自己独占的完整结果事实，在硬上限内把单一来源的小型证据闭环一次交付；规则只保留证据缺口、升级与停止原则。

### 5.3 新职责决策

1. 项目 `AGENTS.md` 保持真实生产约束并继续计入端到端成本；测试不能通过删除它伪造收益。
2. 普通 `srcq rg|fd` 在取得完整事实后，只有完整结果不超过 512 个证据单元且实际渲染仍落在原 2048 estimated-Token 总预算内时越过初始 80 项页限；rg 单一来源可把单行上限提高到 1024 字符重新评估，但不得提高总预算。多来源、过大、未知或显式控制面保持原预算与精确分页语义。8192 预算只保留为揭示分页机制的局部原型，不进入默认合同；v5 已证明它没有覆盖真实高成本命令链。
3. 全局规则和 `source-query` 删除“同层一次、首查锚点”等操作编排，只定义最小直接证据、最低充分工具层、截断后升级和证据充分停止。
4. 新候选先只运行六个受影响 run；只有质量全通过、命令不高于 20、总 Token 不高于 542,658 且无新失败机制，才运行 12 次封闭候选与 detached 审计。旧 v1-v4 结果不重跑。

## 6. 后续验证对早期门槛的修正

第 5.3 节第 4 项是当时基于 v3 数字形成的升级门槛，后续证据已使它失效：v3 没有通过封闭质量，且一次查询接触 benchmark 资产；无效低成本样本不能成为后续候选的硬目标。P10 因此继续以“先质量、再总 Token、最后速度”的需求顺序裁决，而不是追逐 `542,658`。

v5 证明 8192 estimated-Token 默认没有覆盖真实命令形状，反而与高级 skill 误触发共同形成 `823,177` Token；v7 把工具收回原 2048 总预算并将 skill 变为专项后，Provider 与 HJSON 已收敛，containing 仍重搜已知文件；v8 把搜索和正文读取分离后降至 `556,677` Token，但仍有语料污染与最终限定丢失。后续 identity 又分别验证权威范围、续页和规则审查非触发，完整 v19 仍因 AgentBase 纯只读任务误用“修改前读取 README”条款升至 `1,340,388` Token。该项目规则适用边界修正后，v20 相同受影响六次降至 `528,450` Token、20 次命令且不再读取根 README。

最终 v21 identity `0cfb891986cb89c96077427564f91720ed52619f82828e05fa84d420174859d5` 的六类 12-run 得到 required、行限和 evidence complete 12/12，总 Token `1,066,470`、45 次成功命令、耗时 `480.739 s`。相对 P9 同质量候选，总 Token 降低 `7.31%`，耗时上升 `32.38%`；按需求顺序采纳 Token 收益但不声称速度改善。detached audit 与确定性身份验真见 [audit-result-p10-v21.json](audit-result-p10-v21.json) 和 [capsule-verification-p10-v21.json](capsule-verification-p10-v21.json)。

最终职责仍与第 5.3 节的核心裁决一致：srcq 只在原总预算内交付机械可证有界的完整小结果；全局规则只表达权威范围、已知正文直读、按证据升级和充分即停；最近项目规则只修正自身修改前置阅读的适用范围。固定锚点、调用次数、阅读顺序和更大默认输出都已有反向样本，当前没有另一项共享失败或缺失能力足以改变方案，因而达到当前实验条件下的收益边缘。
