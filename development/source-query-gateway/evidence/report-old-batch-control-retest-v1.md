# 旧批量 Control：C# 两次复测

用户因 C# 失分较多要求核对方向，并明确只复测 C# 两次。本报告供候选研究与评分复核使用；[审计](audit-old-batch-control-retest-v1.json)保存逐项解释，原始事实由外部 summary、stdout 和 audit capsule 持有。仅属开发证据，不进入 payload；输入或环境改变后不外推。

## 是哪些错误

| 运行 | required | 答案缺口 |

| 第一次 | R8 | “读取失败则不入库”，漏发布失败状态 |
| 第一次 | R17，争议 | “实时值有效”，有限值边界未明确 |

两次的六个完整实现范围和七个指定直接调用位置均正确。这次失分主要是行为信息遗漏/精度不足，不能把29/31理解成找错了两个函数。两份工具输出都已包含有限值判断、读取失败发布和未知型号失败源码，缺口不是搜索没有取得这些证据。

独立复核也确认上轮两份 control 的既有扣分：部分复合行为缺失，第二份220、251行缺少从Reader切回Engine的明确身份；没有为了复测提高分数而改动历史记录。对存在真实语义歧义的条目保留评分区间，不能凭关键词自动替代审查。

## 身份与执行

- 与上轮逐项比较：corpus、整个C#工作区快照、Codex参数/可执行文件、网络投影、runner、价格参数、工具和control环境完全一致。只改变本次control-only调度和新的实际运行记录。
- AGENTS与历史最佳批量原件完全一致；按正式生命周期筛选的13个AgentBase skills、83个文件逐文件内容一致。没有复制其他skills、home或源码工作区。
- Luna medium/default、HTTP-only、v23、禁止受测子代理。两次usage完整、postflight无异常；capsule验证6个原始文件通过。
- 两次都有真实批量调用，最多3条。第一次走srcq及续页，并把skill别名误拼成 `skills/r0/source-query/SKILL.md`，发生一次路径读取失败；第二次裸用rg、3次请求结束。因此同一旧规则环境也不保证相同工具路径与成本。

## 对研究方向的影响

旧control没有稳定坏到24/31，也没有稳定保证满分。可见配置和源码不变，本次正确度与执行路径仍变化；不能将一次低分直接归因于新规则退化，更不能据此否定批量机制。

后续仍保留用户逐题质量与价格门槛，但应区分代码定位能力、答案完整性和评分歧义；旧control的单轮分数不是固定能力常数。当前更直接的共同缺口是“已读到但未完整回答”，而不是一概需要更多搜索。此次只完成获授权的两次复测，不追加候选、其他题、规则修改或部署。
