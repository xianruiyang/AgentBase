# 意图重解释触发条件：纯定位标准下的单因素实验

2026-09-04。使用方：后续代码阅读研究和用户复核。逐项成绩、价格与来源由[审计数据](audit-intent-trigger-v1.json)维护；原答案、逐请求 usage、环境身份归外部正式 capsule。仅属开发研究，不进入部署。输入、模型或规则发生变化后，本报告不证明新环境效果。

## 结论

候选没有达到逐题至少持平的要求，停止晋级，不扩到完整九题，不修改正式规则、skill、srcq 或安装态。候选在 C# 两次满分，TS 改善但未全对，规则来源题退步。不能用总分上升抵消单题退化，也不能因 C# 改善就认定原规则是确定根因。

本轮没有在候选中加入路径、行号、实现范围、调用点、语言、项目或题目答案提示。只将当前全局首条目标规则的“重组意图”收窄到歧义、冲突、错误前提或实现设想与结果不一致会改变动作时；明确且无冲突的用户要求直接作为任务合同。原规则并不授权忽略需求，本实验测试的是表达与触发范围对实际行为的影响，而非认定它的规范语义必然错误。

## 实验身份与判别顺序

- Control 为当前 srcq 入口已修复的完整全局正文及当前 13 个 AgentBase-owned skills；不是历史旧最佳批量版。
- Candidate 与 control 仅一条全局规则不同。正文 `o200k_base` 为 4,877 → 4,887 Token；批量条款、skill、srcq 0.7.0、题面与 v24 评分均不变。
- 独立 Codex，GPT-5.6 Luna、medium、low verbosity、default service tier、HTTP-only；受测模型禁止创建子代理，执行只读任务合同。只有 AgentBase-owned skills 被复制，认证沿正式 home preparer 使用 hardlink，不复制内容。
- C# 先进行双方各两次；候选 26/26、不低于本轮 control 且超过历史筛选参考 25/26，均价涨幅小于 50%，随后保持候选不变，在独立 home 中并行运行 TS 与规则来源两组配对，各两次。不因中途结果改题、改分或更换候选。
- 三个 shard 内均为 candidate1 → control1 → control2 → candidate2。每个配对使用同一 workspace、corpus、工具与 skill 身份，只允许 `AGENTS.md` 不同；不将跨 shard 的环境身份伪装为一个整体实验身份。

## 错误发生在哪一步

| 直接证据 | 支持范围 |
| --- | --- |
| 先前入口修复 C# 两次所漏 Reader 22 与 58 均已在相应工具输出出现 | 这两处不是单纯搜索覆盖不足，不能靠再补同一证据解释全部问题 |
| 本轮 control1 将 Engine 实现范围写成 43–88、188–240；control2 将后者写成 188–240，但工具输出已有闭合位置 | 至少这些错误发生在已有证据到最终答案的转换中；不能据此断言某条规则造成了错误 |
| TS control 两次都漏注册 58、委派 60、移除监听 180；candidate1 缺 60/180，candidate2 只缺 60 | 候选有改善，但仍以外层范围或语义说明代替了题面请求的部分位置；不修改规则去复述这些题目字段 |
| 规则来源 candidate1 的第一个工具只枚举 `AGENTS.md`；后续五次查询/读取全限定在根与 global AGENTS，没有查询 `skills/source-query/SKILL.md` | 这是过早收窄候选来源导致的搜索覆盖缺口，不是把已读 skill 在最终答案删掉。不能把所有失败统称为输出压缩 |

同一组实验仍包含两类不同失败：已见证据没有准确进入答案，以及搜索范围过早关闭。仅限制“重组意图”没有同时解决两者。后续应分别用通用机制做消融，先核对候选范围如何形成与“证据充分即停”的实际使用；不能直接把精确位置、指定文件或答案字段补入全局规则/skill，也不提高输出档或追加无条件自查循环来掩盖问题。

- 不回写旧实验，不部署、不发行，不将这个未通过跨题要求的候选变为生产规则。下一候选须改变实际待证因素，不能仅重复相同输入期待全对。
