使用方：后续根因研究与人工复核。报告解释结论，[逐次审计](audit-causal-rules-skills-v1.json)保存原始答案、逐项失败、价格、真实批量与工具返回定位；原始事实位于 `D:\AgentBaseBench\causal-rules-skills-v1` 的正式 experiment、summary、JSONL 和 capsule。均为开发证据，不进入 payload；摘要可重核，输入变化后不外推。

## 实验合同

本次不追加“要保留事实”等补偿提示，也不把 high 当成修复。完整原文交叉组合：历史最佳批量 AGENTS / 当前生产源码 AGENTS × 历史 / 当前 AgentBase 自有 skills，各两次，共八次。历史 AGENTS＋历史 skills 是同轮旧整环境参照；两个混合格只是诊断，不冒充用户定义的 control。

仅 v23 C# 采样链题，31 个 required、最多 12 行；Luna medium、显式 low、default、HTTP-only、CLI 0.151.0，受测模型禁止子代理，原工作区按只读任务合同使用。运行器 sandbox 为 danger-full-access，不能称为操作系统级只读隔离。未改题目、oracle、正式规则、skills、工具或部署。

正式 preparer 每个 home 只复制 13 个 AgentBase 自有 skills、83 个文件，不复制其他 skills 或项目源码。当前 AGENTS 来自仓库，与最初当前态冻结样本逐行一致；skills 来自上一轮已验冻结环境，没有把实验提示装回安装态。两对各按当前1、旧1、旧2、当前2顺序，双对并行；pair 内只允许 AGENTS.md 不同，配置显式 low。

两个 manifest 的 corpus、workspaces、codex、runtime_environment、runner、token_pricing、tool_versions 投影相同；tool_versions 为空，不把它的相等冒充 srcq 二进制校验，srcq 入口由 preparer 验证。两侧 postflight 无异常，两个 capsule 均校验 12 个原始文件。八次全保留，没有按结果追加采样。

## 已经缩小的故障范围

### 1. 查询入口变化比答案总分更一致

当前 AGENTS 四次全部裸用 rg，旧 AGENTS 四次中三次经过 srcq。该方向跨两个 skills 背景成立。旧版“发现/搜索只用”被压成当前“发现仅用”等查询表述，是可操作的优先嫌疑；不是据单词相似直接宣判。

既有[仅恢复查询条款诊断](report-current-query-boundary-v2.md)提供独立局部支持：恢复旧条款后两次都走 srcq，压缩条款侧多数裸 rg。但是那次恢复后来源题正确度下降，分别出现未消费分页、未扩到 skill 的问题。因此“入口遵循受措辞影响”与“漏答根因已经解决”必须分开，不能原样重跑已失败候选。

### 2. 高频遗漏不是该条事实没查到

八次记录的工具返回都包含 Engine 第 225 行的失败发布、213 行的 UID 失败发布，以及 Reader 第 24 行的有限值判断。其中七份答案漏掉读取失败时的“发布”结果，只有 E 表达了它。定位记录见审计的 tool_return_evidence，检查只取 commandExecution 的 aggregatedOutput，不拿最终答案或内部推理冒充源码返回。

这排除了“这些漏答都由查询没有取得该事实造成”。仍未解释为何事实没有进入最终答案：理解、证据选择、压缩表达、指令交互和随机波动尚未分离，也不能据 stdout 断言模型确实理解或注意到了它。旧、新规则都发生，不是新版独有。

### 3. 分数不是独立错误的数量

F 的 20/31 中，源码路径只写省略号，造成六个定义 required 与文件绑定项连带失败；六个数值范围实际有五个正确，另一个 Read 写 18–51 而非 18–52。不能报告成“六个实现都找错”。

A 则把分支压成“UID失败＋行号、采集失败＋行号”等，缺少题目要求的动作和结果，并缺两处 Read 调用位置。B 有一个真实定义末行错误、一处 Read 调用误归属并漏 Test 调用。C、D 额外提及未绑定完整文件身份的 Program.cs。质量问题必须区分定位错误、文件表达和行为遗漏，不改既定分母来掩盖任何一类。

R17 仅 A、F、E 的“有效/成功实时值”保留有限性争议上界；C、H、G 还缺采用/返回实时结果，不是单词解释争议。主审校正了首评遗漏的复合条件，不以评审票数取代答案原文。

### 4. 没有证据说“读了新 skill 正文导致退化”

两套自有 skills 有 12 个文件变化，其中 3 个 SKILL.md 正文、9 个其他文件；description 变化限 execution-governor、reasoning-governor。实际八次没有读取这些改动正文，只在 C、H、F 读取了未变的 powershell-usage。description 仍可影响路由，但不能把未加载的正文当作直接上下文负担或已证原因；source-query 正文也未变。

### 5. 批量仍发生，命令错误并非全部漏答的解释

八次中七次存在同请求多工具项，最大批量均为 3；只有 A 没有真实工具批量，其第一条 shell 拼接两个命令不计作多工具请求。所有工具项闭合。

C 将 Windows 通配路径直接交给 rg，返回 os error 123；F 的嵌套 PowerShell 丢失 foreach 变量，随后恢复查询。B 的一次 exit 1 是 csproj 查询无匹配，不算调用错误。无命令错误的运行也遗漏行为，不能把总问题都归为 argv 或批量失效。

## 本轮裁决与下一步

- 本轮八次诊断完成，未产生合格的新候选，未部署；九题整体目标仍未完成。
- 原始 AGENTS 确有行为影响，但答案质量没有单因素、单方向结论。允许删除/替换原有改动，不预设新版必须保留；也不由这八次反向宣布新版全面更好。
- 下一项应先固定同一组充分源码证据，保留 medium/low 和相同题面、oracle，比较证据之后的答案生成，消去自主检索差异；若差异消失再回查检索/上下文路径，若仍存在再缩小原有条款消融。该实验只定位机制，不能替代端到端资格。
- 本轮不继续扩跑、不再加答案提醒、不提高输出档、不因一次低分全量回退。完整失败样本和评分敏感性已保存。
