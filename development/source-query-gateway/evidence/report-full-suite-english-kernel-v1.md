## 已确认的失败与评分边界

- 规则来源：候选第一次漏掉仓库 `skills/source-query/SKILL.md`，3/4 低于 4/4。第二次两项均在；额外列出真实参考文件不是隐藏的“只能两项”要求，不扣分。
- TS：候选两次分别漏 command 分派与 init payload ID 区分，或注册/委托发生位置及 command 分派。43/48 低于 45/48。旧版错误的闭合行及未说明 Disposable 未保留也按相同标准扣分。实体范围不替代具体调用/注册位置；覆盖准确发生位置的有界范围可以接受。
- C#：候选 60/62 高于旧版 55/62，但两次合计费用增加 15.21%。缺读取失败发布与调用位置仍扣分；语义相同的实时值/缓存说明不要求关键词。候选 `/D:/...` 可唯一映射完整文件身份，按 v23 接受；这不认证其原生路径复制可用性。
- C++ 与其他源码题的完整范围、调用和行为按既定 oracle 评分，没有因候选不同而增删要求。

三个 runner 的声明范围 postflight 均无异常；capsule 分别核验 36、20、28 个原始文件。这证明归档完整与声明范围内未漂移，不能弥补上述 UE 输入遗漏。UE 的 `public_command_edge.md` 仅作为匹配路径出现；CMD/Pak 仅出现在查询参数，未返回源码正文，不把它们误报为正文消费。
