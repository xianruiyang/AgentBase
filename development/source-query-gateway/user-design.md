# 统一源码查询网关用户设计

## 文档职责

本文件只记录用户已经明确提出的技术设计选择，作为 `docs/requirements.md` 中 `REQ-012` 的用户设计来源。模型形成的职责、接口和实现边界位于 [design.md](design.md)，实施顺序位于 [plan.md](plan.md)。

## UDES-SQG-001 建立统一包装入口

- 状态: confirmed
- 来源: 用户要求要么裁撤现有包装，要么认真做成统一包装，并进一步选择先设计完整方案
- 关联: REQ-012, AC-044

rg、fd 与 ast-grep 的模型侧包装能力应合并为一个统一入口，不再分别维护低质量或重复的包装协议。

## UDES-SQG-002 完整兼容全部原生指令

- 状态: confirmed
- 来源: 用户明确要求“直接完全兼容 rg、fd、astgrep 的所有指令”
- 关联: REQ-012, AC-040, AC-046

统一入口不能只实现常用参数子集。底层工具在受支持版本中可以表达的命令、选项、特殊模式、交互、输出和写入行为都必须能够通过统一入口调用；包装层不得用自己的简化语法替代原生命令语义。

## UDES-SQG-003 根据实际结果选择低 Token 输出

- 状态: confirmed
- 来源: 用户明确要求“在输出方面，根据实际情况，尽可能使用最短 Token 的方式输出”
- 关联: REQ-012, AC-041, AC-043, CON-001

包装层应观察 backend、命令语义和实际结果形状，在不损失当前结论所需信息的前提下，自适应选择更低 Token 的结果表示，而不是把固定 JSON、YAML 或文本格式用于所有查询。

## UDES-SQG-004 fd 结果优先使用目录树

- 状态: confirmed
- 来源: 用户明确要求 fd 文件输出采用目录树方式避免大量重复头
- 关联: REQ-012, AC-042

fd 返回大量共享目录前缀的文件或目录时，使用可还原完整路径的目录树表示，避免每条记录重复输出相同根路径和目录头。目录树只改变表示，不以抽样替代完整结果。

## UDES-SQG-005 包装质量以 sgy 为基线

- 状态: confirmed
- 来源: 用户要求若保留包装，就认真完善到与 sgy 同等质量
- 关联: REQ-012, AC-046

统一包装应具备稳定接口、真实引擎兼容、完整测试、错误边界、安装发布和来源证明，不接受继续向当前薄弱脚本追加启发式特例作为正式方案。
