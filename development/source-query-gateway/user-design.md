# 低成本源码查找分支用户设计

## 1. 文档职责

本文件只记录用户为实现 [requirements.md](requirements.md) 明确指定的技术选择。它们约束候选设计，但不能替代对质量、端到端总 Token 和速度的结果验收。

## UDES-SQG-001 使用统一包装能力

- 状态: confirmed
- 来源: 用户要求要么裁撤现有包装，要么认真做成统一包装
- 关联: REQ-SQG-001

以现有 sgy 实现为成熟基线构建统一包装，由正式 Source Query Gateway 承载 rg、fd 与 ast-grep 的模型侧包装能力，不继续维护质量不足或职责重复的独立包装协议。历史实现和实验仍可使用 `sgy` 标识，正式产品与命令身份按 UDES-SQG-010 原子迁移。

## UDES-SQG-002 完整兼容原生命令

- 状态: confirmed
- 来源: 用户明确要求完整兼容 rg、fd 与 ast-grep 的所有指令，并在 2026-08-16 明确否定后端版本门禁
- 关联: REQ-SQG-001, AC-SQG-001

包装不以简化语法取代底层工具，也不得因 rg、fd 或 ast-grep 的版本字符串不同而拒绝可启动的后端；原生命令、参数、stdin、TTY、输出、退出和副作用语义都应能够调用。精确版本只标识测试与诊断证据，不形成运行许可名单。rg/fd 的普通模型入口在 backend 后直接接受原生 argv，不要求额外的 `exec`、`--`、view、limit、heading 或 receipt 配方；网关自己的可选输出控制位于不会与原生参数冲突的独立命名空间。原生兼容平面保持上述语义，不因自动压缩改变命令行为；实际输出不能安全结构化时使用无损透传、显式产物或只读安全降级，不把未知版本伪装成空结果。AST 继续遵守 UDES-SQG-006 的既有 sgy 命令与 argv 边界，不为表面对称改写。

## UDES-SQG-003 根据实际结果选择低 Token 输出

- 状态: confirmed
- 来源: 用户要求根据实际情况尽可能使用最短 Token 的输出
- 关联: REQ-SQG-001, AC-SQG-002

证据查询平面依据命令语义、当前所需证据和实际结果形状选择更短的充分表示，不把固定 JSON、YAML 或文本格式用于所有查询。面向模型、机器消费和原生协议的输出必须分离：模型默认视图以最低充分上下文为目标，机器视图保留稳定结构化合同，原生或产物视图保持字节与副作用语义。`auto` 只能在语义等价、可还原当前必需证据的表示中选择，不得为缩短输出改变结果集或原生副作用。

`auto` 是普通调用的内置职责而不是要求模型填写的 view。工具必须先取得并分类真实结果，再生成单行、heading、分组正文、紧凑路径树及“目录树 + 文件 heading + 位置叶子”等候选，依据实际渲染成本和理解结构选择最低充分表示；同文件多位置优先消除路径重复，多文件共享长目录时再压缩公共目录，离散单位置不为树形增加层级。内部默认上下文预算负责安全分页，模型无需先给结果数量或正文长度设限；确有定向输出需要时仍可显式覆盖。

所有可能进入模型上下文的输出族都应整体审查，不等用户逐字段指出冗余。普通成功且完整的结果只显示干净的工具证据正文，不包 JSON/YAML envelope，不附 `result_total`、`complete`、backend、engine version、mode、view、字节数、重复 argv、完整查询身份、空集合、固定 schema、结束标记、转义说明或其他可从命令、退出状态和默认协议推出的事实。只有缺少某项信息会使模型误判、漏读、无法续页或无法恢复时，才在证据之后附相应最短异常信息；诊断或机器消费者通过显式视图取得完整事实。

## UDES-SQG-004 fd 优先使用可逆目录树

- 状态: confirmed
- 来源: 用户要求 fd 文件输出采用目录树避免重复路径头
- 关联: REQ-SQG-001, AC-SQG-002

fd 或 rg 文件/位置结果存在共享目录前缀时，在确实更短的条件下使用可还原全部路径的紧凑基数树：单子链用 `/` 合并，分叉才换行缩进，根只出现一次；rg 的文件叶子可继续承载同文件 heading 和位置叶子。查询已经限定对象类型时不逐项重复类型，空集合与固定转义说明不进入正常模型结果。目录树只是自动规划器的一种候选，不以抽样替代完整结果；多根、混合类型、歧义字符和 machine round-trip 由明确的最小标记或显式机器视图承担。

## UDES-SQG-005 包装质量以 sgy 为基线

- 状态: confirmed
- 来源: 用户要求若保留包装，就做到与 sgy 同等质量
- 关联: REQ-SQG-001, AC-SQG-001

新增能力应具备稳定接口、真实引擎兼容、明确错误边界、自动化测试、安装发布和来源证明，不把启发式特例堆叠为正式协议。

## UDES-SQG-006 AST 沿用现有 sgy 设计

- 状态: confirmed
- 来源: 用户明确要求 ast-grep 方面继续沿用 sgy 的设计
- 关联: REQ-SQG-001, AC-SQG-001

当前 sgy 的 AST 命令结构、argv 边界、profile、cache、fingerprint、`process containing`、`group-locations`、rewrite preview/apply、TTY/LSP、artifact、诊断和发布链继续作为正式基线。机器兼容与安全写入合同继续保留 safe YAML 等既有协议；模型默认投影可以在不改变 AST 结果、范围、缓存、位置和写入语义的前提下移除正文与捕获的重复表示，并只展示当前判断需要的捕获。统一化不得把 AST 迁入另一套命令模型，也不得用 rg/fd 的需求削弱其边界；产品前缀按 UDES-SQG-010 从 `sgy` 原子改为 `srcq` 不得改变上述 AST 语义。

## UDES-SQG-007 通过外部监控运行隔离 agent 对照

- 状态: confirmed
- 来源: 用户要求把既有 Token 测试固化为可重复利用的、通过监控隔离 agent 测试内容的流程
- 关联: REQ-SQG-001, AC-SQG-004

每个测试回合使用无对话历史的新鲜隔离 agent；协调方只负责按冻结输入启动、监控事件流、限时、保存原始结果和结束进程，不在运行中提示或修正被测 agent。对照 agent 不得看到另一环境的输出或聚合结论，质量复核由独立审计角色在运行完成后执行。调优用例和最终封闭验收用例分离，防止把测试答案写入查询规则后再对同一批用例验收。

## UDES-SQG-008 测试流程只保留在项目内

- 状态: confirmed
- 来源: 用户明确要求项目测试不与发布到 Codex 的内容混合
- 关联: REQ-SQG-001, AC-SQG-004, CON-SQG-003

隔离 agent 测试流程及其全部输入、执行器和结果只在 AgentBase 仓库的开发边界内维护，不嵌入发布 skill、srcq/sgy 运行时或 Codex 安装目录。

## UDES-SQG-009 srcq 作为正常 Windows 命令安装和卸载

- 状态: confirmed
- 来源: 用户明确要求统一网关具备正常安装和卸载能力，并能像 Python 一样在 PowerShell 中直接调用；后续确认正式命令为 `srcq.exe`
- 关联: REQ-SQG-001, AC-SQG-001, CON-SQG-002

srcq 应作为独立的 Windows 用户级 CLI 安装并进入用户 `PATH`，使 PowerShell、Codex 与其他消费者都能直接调用 `srcq.exe`，不依赖项目目录、Codex 根目录或某个 skill 的私有路径。正式生命周期必须覆盖安装、状态查询、升级和卸载；升级失败可恢复，卸载只移除安装器管理的文件与 `PATH` 项，不破坏无关用户状态。skill 不再捆绑或回退到另一份私有 srcq/sgy 运行时。

## UDES-SQG-010 正式产品和命令使用 srcq

- 状态: confirmed
- 来源: 用户确认产品名为 Source Query Gateway、唯一命令为 `srcq.exe`，当时限定为先讨论需求与设计
- 关联: REQ-SQG-001, CON-SQG-002

正式产品名为 `Source Query Gateway`，唯一对外命令为 `srcq.exe`。当前 `sgy` 仅是尚未迁移的实现与历史证据身份；正式迁移应在安装发布前原子更新可执行文件、安装目录、状态、包、归档、skill、文档和验证，不保留 `sgy.exe` 兼容别名或双轨运行时。

## UDES-SQG-011 LSP 能力渐进展示

- 状态: confirmed
- 来源: 用户明确要求 `vscode-lsp-mcp` 不再常驻展示全部工具，改为按真实需要渐进展示，必要时可采用类似 srcq 的形式或合并进 srcq
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-005

未使用 LSP 的任务不展示全量语义工具合同；进入 LSP 后也只展示当前缺失能力，不为了了解工具范围而一次展开全部定义。优先验证 Codex 宿主原生延迟工具发现；若它不能稳定降低实际上下文成本，候选设计可把只读 LSP 源码语义查询合并到 `srcq lsp`，但不因此将重命名应用、Code Action 应用、格式化应用、命令执行或调试控制并入源码查询职责。

## UDES-SQG-012 查询工具按任务与 Provider 成本分层路由

- 状态: confirmed
- 来源: 用户要求研究结合全部工具的最低 Token 路径，并明确要求只降低慢 LSP/`workspace_symbols` 的优先级而非绝对禁用
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003, AC-SQG-006

已知文件可直接有界读取；需要 rg、fd 或 ast-grep 的查询一律调用 srcq，不再让模型裸用这些底层工具。已知名称、少量命中和天然有界内容由 srcq 自动选择轻量执行与输出投影；全集、不存在证明、未知大结果、分页、高重复输出和语法结构仍由同一入口升级到相应完整性或 AST 能力；只有结论依赖真实符号身份、类型、精确引用或层级时使用 LSP。小项目、已热索引或 clangd 等性能可接受的 Provider 仍允许 `workspace_symbols`；大型 UE 项目或已观测到昂贵的 Provider 先用 srcq 缩小位置后再定向调用 LSP。

## UDES-SQG-013 常驻路由和 Skill 保持根本且精炼

- 状态: confirmed
- 来源: 用户要求规则从根源编写、尽可能精炼并降低模型使用时 Token，且认为模型能力足以承担裁决，不需要依赖正反例堆叠
- 关联: REQ-SQG-001, AC-SQG-002, AC-SQG-004, AC-SQG-005, AC-SQG-006

常驻全局路由只表达证据层级、成本选择、升级和停止边界，不枚举某批 benchmark 任务的答案端点、正反例或工具全量参数。统一 skill 主文只负责触发边界和引用选择；普通 rg/fd 调用不加载 heading、tree、view、limit、receipt 或预算配方，AST、LSP、安装、诊断及显式 machine/native 控制才按需读取详细协议。模型基于当前请求和证据裁决查询语义，工具只基于真实结果选择语义等价表示，不以输出规划替代模型的证据裁决。

## UDES-SQG-014 外部适配优先，源码改造只作有证据的升级路线

- 状态: confirmed
- 来源: 用户允许在套壳实现遇到实质困难时拉取 rg、fd 等上游源码改造，但要求当前仍优先套壳
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003, UDES-SQG-001, UDES-SQG-002, UDES-SQG-005

默认继续以外部进程、稳定协议和结果后置投影适配已验证的 rg、fd 与 ast-grep，不因实现麻烦、代码复杂、局部性能不理想或内部实现更整洁而引入上游源码分叉。只有直接反例证明正确性、完整兼容、最低充分输出或资源边界中的必要目标无法在外部边界可靠实现，根因又确定位于上游可执行文件或公开协议内部，并且有界适配方案已经验证不足时，才暂停当前实现并重新裁决源码改造。

源码改造不是静默 fallback。即使技术证据满足升级门槛，也必须先向用户说明阻塞反例、根因、已排除的外部方案、拟改造范围和长期维护代价，并取得用户针对该次源码升级的明确同意；讨论、建议、既有实施授权或用户未反对都不能代替该次同意。未获同意不得拉取、复制、内嵌或分叉上游源码。获准启用后仍由 `srcq.exe` 作为唯一公开入口，只做 Windows 定向的最小改动，固定上游版本与来源，并补齐许可证、构建、测试、供应链、更新同步、漏洞响应、回退和退出方案。不得同时暴露改造版与系统裸工具形成第二运行时或第二行为真源。

## UDES-SQG-015 query 页尾使用 cursor 与完整 `@next` 命令

- 状态: confirmed
- 来源: 用户 2026-08-20 明确选择第一种方案并要求迭代到模型友好
- 关联: REQ-SQG-001, AC-SQG-009

保留现有不透明 cursor 和 snapshot 机制，不改为 offset + length，也不新增 `srcq more`。query model 页尾由 `@more` 说明剩余数量，由 `@next` 携带完整可执行命令；以正常独立 Codex 能沿同一 snapshot 成功取得下一页作为友善度验收。

## UDES-SQG-016 关系工具内部组合 rg 与 AST

- 状态: confirmed
- 来源: 用户 2026-08-30 要求制作一组以更快速度达到近似 LSP 效果的新工具，并明确其内部利用 rg 与 AST
- 关联: REQ-SQG-002, AC-SQG-010, AC-SQG-011, AC-SQG-013

定义、引用和调用树作为 `srcq` 的一组正式只读查询能力，由 rg 生成有范围与完整性边界的候选，再由 AST 对声明、定义、使用、调用、作用域和外层 owner 进行结构分类。模型不负责手工串联多次底层命令或维护中间候选状态；LSP 保留为歧义确实影响结论时的精确后备，而不是普通查询的默认入口。

## UDES-SQG-017 关系工具优先覆盖 ast-grep 语言集合

- 状态: confirmed
- 来源: 用户补充该能力不只适用于 LSP/C++，应尽可能适配更多语言且至少适配 AST 已适配语言
- 关联: REQ-SQG-002, AC-SQG-012

正式设计不得把 C++ 节点名称、UE 约定或单一语言语义写成公共合同。ast-grep 已适配语言必须进入同一能力发现和查询表面；语言差异由受版本和验证约束的适配层承担。某一关系不适用于语言或尚不能可靠判断时，工具明确表达 capability 与原因，不用通用空结果伪装已适配。

## UDES-SQG-018 关系查询使用真实源码宇宙而非当前目录

- 状态: confirmed
- 来源: 用户指出实际源码可能不在当前工作区，VS Code 可连接其他目录中的库，UE 查询会进入引擎源码
- 关联: REQ-SQG-002, AC-SQG-014

关系工具内部解析当前符号实际所属的项目、编译单元、依赖与本地源码根，并允许一次查询跨项目根、编辑器 workspace folder 和外部库源码。模型不应先手工寻找所有外部目录再逐个调用，也不应因自动范围未知而默认搜索整个磁盘。已有编译和依赖元数据优先作为只读输入；发现范围仍不完整时，模型只获得会改变下一动作的缺失根或显式补根动作，而不是冗长的全部 include path、系统目录和解析日志。

## UDES-SQG-019 目录参数默认可省略并支持显式组合

- 状态: confirmed
- 来源: 用户要求无目录输入时仍具备基础能力，并允许模型灵活设置和感知目录以取得最佳适配
- 关联: REQ-SQG-002, AC-SQG-015

普通定义、引用和调用树查询默认不填写目录：工具根据源码位置或当前目录自动形成可用范围并直接返回关系证据。需要控制时，同一入口支持重复目录、文件或外部源码根，并明确区分“在自动范围上追加”“只使用指定范围”和“从已选范围排除”；不能用一个含义随输入变化的 `path` 参数混合这些行为。

模型不需要为正常查询预读范围说明。跨根命中、用户主动限定、自动解析不完整或零结果依赖范围解释时，结果才显示紧凑范围摘要和一条完整可执行的调整动作；完整机器面继续保留每个根的绝对路径、来源与覆盖状态。

## UDES-SQG-020 常用语言尽量达到 C++ 同等级候选效果

- 状态: confirmed
- 来源: 用户 2026-09-01 明确要求 Go、Python、Rust、JavaScript、TypeScript 尽量做到与 C++ 相同的解析效果
- 关联: REQ-SQG-002, AC-SQG-010, AC-SQG-011, AC-SQG-012, AC-SQG-013, AC-SQG-014, AC-SQG-015, AC-SQG-016

Go、Python、Rust、JavaScript 与 TypeScript 不应长期停留在只按短名扫描的 generic 候选层。各语言在源码语法和现有项目元数据能够直接证明时，应取得与当前 C++ 快速路径同类的限定定义候选、显式接收者类型、唯一直接或成员调用递归、真实 callable owner 和项目源码范围；实现复用同一查询、缓存、图遍历与输出 owner，但由语言适配器承担包、模块、导入、类型声明和调用语法差异。

“相同效果”指语言等价的可用导航结果和证据等级，不要求把不同语言伪装成相同 grammar，也不把候选提升为编译器语义。重载、trait/interface 或动态分派、函数值、宏或代码生成、运行时属性和其他不能由当前静态源码唯一证明的关系继续返回 `ambiguous` 或 `semantic-unknown`；工具不得为补齐这些语义隐式启动编译器、解释器、包管理器、构建或联网下载。
