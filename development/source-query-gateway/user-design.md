# 低成本源码查找分支用户设计

## 1. 文档职责

本文件只记录用户为实现 [requirements.md](requirements.md) 明确指定的技术选择。它们约束候选设计，但不能替代对质量、端到端总 Token 和速度的结果验收。

## UDES-SQG-001 使用统一包装能力

- 状态: confirmed
- 来源: 用户要求要么裁撤现有包装，要么认真做成统一包装
- 关联: REQ-SQG-001

以现有 sgy 实现为成熟基线构建统一包装，由正式 Source Query Gateway 承载 rg、fd 与 ast-grep 的模型侧包装能力，不继续维护质量不足或职责重复的独立包装协议。历史实现和实验仍可使用 `sgy` 标识，正式产品与命令身份按 UDES-SQG-010 原子迁移。

## UDES-SQG-002 完整兼容原生命令

- 状态: confirmed
- 来源: 用户明确要求完整兼容 rg、fd 与 ast-grep 的所有指令
- 关联: REQ-SQG-001, AC-SQG-001

在明确支持的精确版本内，包装不以简化语法取代底层工具；原生命令、参数、stdin、TTY、输出、退出和副作用语义都应能够调用。原生兼容平面保持上述语义，不因自动压缩改变命令行为；不能安全结构化的模式使用透传或显式产物。

## UDES-SQG-003 根据实际结果选择低 Token 输出

- 状态: confirmed
- 来源: 用户要求根据实际情况尽可能使用最短 Token 的输出
- 关联: REQ-SQG-001, AC-SQG-002

证据查询平面依据命令语义、当前所需证据和实际结果形状选择更短的充分表示，不把固定 JSON、YAML 或文本格式用于所有查询。面向模型、机器消费和原生协议的输出必须分离：模型默认视图以最低充分上下文为目标，机器视图保留稳定结构化合同，原生或产物视图保持字节与副作用语义。`auto` 只能在语义等价、可还原当前必需证据的表示中选择，不得为缩短输出改变结果集或原生副作用。

所有可能进入模型上下文的输出族都应整体审查，不等用户逐字段指出冗余。普通成功且完整的结果只显示干净的工具证据正文，不包 JSON/YAML envelope，不附 `result_total`、`complete`、backend、engine version、mode、view、字节数、重复 argv、完整查询身份、空集合、固定 schema、结束标记、转义说明或其他可从命令、退出状态和默认协议推出的事实。只有缺少某项信息会使模型误判、漏读、无法续页或无法恢复时，才在证据之后附相应最短异常信息；诊断或机器消费者通过显式视图取得完整事实。

## UDES-SQG-004 fd 优先使用可逆目录树

- 状态: confirmed
- 来源: 用户要求 fd 文件输出采用目录树避免重复路径头
- 关联: REQ-SQG-001, AC-SQG-002

fd 返回共享目录前缀时，在确实更短的条件下使用可还原全部路径的紧凑基数树：单子链用 `/` 合并，分叉才换行缩进，根只出现一次；查询已经限定对象类型时不逐项重复类型，空集合与固定转义说明不进入正常模型结果。目录树不以抽样替代完整结果；多根、混合类型、歧义字符和机器 round-trip 由明确的最小标记或显式机器视图承担。

## UDES-SQG-005 包装质量以 sgy 为基线

- 状态: confirmed
- 来源: 用户要求若保留包装，就做到与 sgy 同等质量
- 关联: REQ-SQG-001, AC-SQG-001

新增能力应具备稳定接口、真实引擎兼容、明确错误边界、自动化测试、安装发布和来源证明，不把启发式特例堆叠为正式协议。

## UDES-SQG-006 AST 沿用现有 sgy 设计

- 状态: confirmed
- 来源: 用户明确要求 ast-grep 方面继续沿用 sgy 的设计
- 关联: REQ-SQG-001, AC-SQG-001

当前 sgy 的 AST 命令结构、argv 边界、profile、cache、fingerprint、`process containing`、`group-locations`、rewrite preview/apply、TTY/LSP、artifact、诊断和发布链继续作为正式基线。机器兼容与安全写入合同继续保留 safe YAML 等既有协议；模型默认投影可以在不改变 AST 结果、范围、缓存、位置和写入语义的前提下移除正文与捕获的重复表示，并只展示当前判断需要的捕获。统一化不得把 AST 迁入另一套命令模型，也不得用 rg/fd 的需求削弱其边界；产品前缀按 UDES-SQG-010 从 `sgy` 原子改为 `srcq` 不得改变上述 AST 语义。

## UDES-SQG-007 通过外部监控运行隔离 agent 对照

- 状态: confirmed
- 来源: 用户要求把既有 Token 测试固化为可重复利用的、通过监控隔离 agent 测试内容的流程
- 关联: REQ-SQG-001, AC-SQG-004

每个测试回合使用无对话历史的新鲜隔离 agent；协调方只负责按冻结输入启动、监控事件流、限时、保存原始结果和结束进程，不在运行中提示或修正被测 agent。对照 agent 不得看到另一环境的输出或聚合结论，质量复核由独立审计角色在运行完成后执行。调优用例和最终封闭验收用例分离，防止把测试答案写入查询规则后再对同一批用例验收。

## UDES-SQG-008 测试流程只保留在项目内

- 状态: confirmed
- 来源: 用户明确要求项目测试不与发布到 Codex 的内容混合
- 关联: REQ-SQG-001, AC-SQG-004, CON-SQG-003

隔离 agent 测试流程及其全部输入、执行器和结果只在 AgentBase 仓库的开发边界内维护，不嵌入发布 skill、srcq/sgy 运行时或 Codex 安装目录。

## UDES-SQG-009 srcq 作为正常 Windows 命令安装和卸载

- 状态: confirmed
- 来源: 用户明确要求统一网关具备正常安装和卸载能力，并能像 Python 一样在 PowerShell 中直接调用；后续确认正式命令为 `srcq.exe`
- 关联: REQ-SQG-001, AC-SQG-001, CON-SQG-002

srcq 应作为独立的 Windows 用户级 CLI 安装并进入用户 `PATH`，使 PowerShell、Codex 与其他消费者都能直接调用 `srcq.exe`，不依赖项目目录、Codex 根目录或某个 skill 的私有路径。正式生命周期必须覆盖安装、状态查询、升级和卸载；升级失败可恢复，卸载只移除安装器管理的文件与 `PATH` 项，不破坏无关用户状态。skill 不再捆绑或回退到另一份私有 srcq/sgy 运行时。

## UDES-SQG-010 正式产品和命令使用 srcq

- 状态: confirmed
- 来源: 用户确认产品名为 Source Query Gateway、唯一命令为 `srcq.exe`，当时限定为先讨论需求与设计
- 关联: REQ-SQG-001, CON-SQG-002

正式产品名为 `Source Query Gateway`，唯一对外命令为 `srcq.exe`。当前 `sgy` 仅是尚未迁移的实现与历史证据身份；正式迁移应在安装发布前原子更新可执行文件、安装目录、状态、包、归档、skill、文档和验证，不保留 `sgy.exe` 兼容别名或双轨运行时。

## UDES-SQG-011 LSP 能力渐进展示

- 状态: confirmed
- 来源: 用户明确要求 `vscode-lsp-mcp` 不再常驻展示全部工具，改为按真实需要渐进展示，必要时可采用类似 srcq 的形式或合并进 srcq
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-005

未使用 LSP 的任务不展示全量语义工具合同；进入 LSP 后也只展示当前缺失能力，不为了了解工具范围而一次展开全部定义。优先验证 Codex 宿主原生延迟工具发现；若它不能稳定降低实际上下文成本，候选设计可把只读 LSP 源码语义查询合并到 `srcq lsp`，但不因此将重命名应用、Code Action 应用、格式化应用、命令执行或调试控制并入源码查询职责。

## UDES-SQG-012 查询工具按任务与 Provider 成本分层路由

- 状态: confirmed
- 来源: 用户要求研究结合全部工具的最低 Token 路径，并明确要求只降低慢 LSP/`workspace_symbols` 的优先级而非绝对禁用
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003, AC-SQG-006

已知文件、已知名称、少量命中和天然有界内容优先直接读取或受限原生 rg/fd；全集、不存在证明、未知大结果、分页或高重复输出使用 srcq 的有界查询能力；文本不能可靠表达语法结构时使用 AST；只有结论依赖真实符号身份、类型、精确引用或层级时使用 LSP。小项目、已热索引或 clangd 等性能可接受的 Provider 仍允许 `workspace_symbols`；大型 UE 项目或已观测到昂贵的 Provider 先用低成本工具缩小位置后再定向调用 LSP。

## UDES-SQG-013 常驻路由和 Skill 保持根本且精炼

- 状态: confirmed
- 来源: 用户要求规则从根源编写、尽可能精炼并降低模型使用时 Token，且认为模型能力足以承担裁决，不需要依赖正反例堆叠
- 关联: REQ-SQG-001, AC-SQG-002, AC-SQG-004, AC-SQG-005, AC-SQG-006

常驻全局路由只表达证据层级、成本选择、升级和停止边界，不枚举某批 benchmark 任务的答案端点、正反例或工具全量参数。统一 skill 主文只负责触发边界和引用选择，rg/fd、AST、LSP、安装与诊断的详细协议仅在进入对应路径时按需读取。模型基于当前请求和证据裁决路径，CLI、包装器和 skill 不以隐式分类替代语义判断。
