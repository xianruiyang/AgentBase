# 低成本源码查找分支需求

## 1. 文档职责与范围

本文件只定义这一候选分支要为模型带来的用户结果和验收顺序，不修改 `docs/requirements.md`，也不表示分支已经进入 AgentBase 主线。用户明确指定的技术选择见 [user-design.md](user-design.md)，模型设计见 [design.md](design.md)，实施任务见 [plan.md](plan.md)。

## REQ-SQG-001 以最低充分成本查找到所需内容

- 状态: confirmed
- 来源: 用户明确说明“根本需求是，让模型可以在保证质量的情况下，用尽可能少 Token，然后用尽可能快的速度，查找到所需的内容”
- 关联: AC-SQG-001, AC-SQG-002, AC-SQG-003, AC-SQG-004, AC-SQG-005, AC-SQG-006, AC-SQG-007, AC-SQG-008, CON-SQG-001, CON-SQG-002, CON-SQG-003

模型应能针对实际代码查找目标，取得足以继续理解、判断或修改的正确内容；在质量充分的候选路径中选择端到端总 Token 更低者，在质量与 Token 成本均不变差时选择完成更快者。工具统一、输出格式和底层实现都只是实现手段，不构成独立完成目标。

## AC-SQG-001 所需内容正确且充分

- 状态: confirmed
- 来源: REQ-SQG-001 对“保证质量并查找到所需内容”的原子化
- 关联: REQ-SQG-001

在文本、文件、结构和真实符号语义等适用任务中，模型获得的对象、正式源码范围、文件与行/列或完整范围、正文、关系和完整性足以支持当前结论；不得因截断、遗漏、陈旧快照、同名或发布/构建/缓存副本、错误符号身份或工具转换把局部结果误作所需内容。不存在证明和全集结论必须覆盖当前声明的权威范围。质量至少不低于不使用候选能力时的同目标路径，并用任务语义而非词面命中率判断。

## AC-SQG-002 质量充分后最小化端到端总 Token

- 状态: confirmed
- 来源: REQ-SQG-001 对“用尽可能少 Token”的原子化
- 关联: REQ-SQG-001, AC-SQG-001

Token 成本按模型完成查找所实际消耗的完整链路核算，包含规则与 skill 加载、工具请求和回执进入上下文、模型输入与输出；cached input 和 reasoning output 作为所属项分列，不重复计入总量。不以包装器 stdout 字节、局部格式长度或单一样本替代；所有会进入模型上下文的查询、分页、诊断、默认值、缓存、后处理和产物回执都必须按其真实使用方审查，只有会改变当前判断、定位、继续查询或失败恢复的工具证据才可进入模型默认输出。正常成功且完整时默认只输出干净的证据正文，不附加 envelope、schema、字段名、统计、完成标记或格式说明；机器可解析、内部已有或“以后可能有用”本身不构成展示理由。只有质量同等充分的路径才比较 Token，能无损停止时不增加查询、解释或工具回合。

## AC-SQG-003 质量与 Token 不退化后最小化耗时

- 状态: confirmed
- 来源: REQ-SQG-001 对“然后用尽可能快的速度”的原子化
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002

速度按从开始查找到模型取得充分内容的端到端耗时比较。只有质量与总 Token 均不变差时才以更低耗时为优；不得用并发、缓存或提前停止隐藏不完整结果，也不得用更快抵消质量或 Token 退化。

## AC-SQG-004 收益结论可隔离复核和重复利用

- 状态: confirmed
- 来源: 用户要求把既有测试固化为通过监控隔离 agent 执行的可重复流程
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003

质量、总 Token 和耗时结论来自受控对照：测试语料、代码快照、模型配置、工具环境、唯一候选差异、运行顺序和计量口径均被记录；每次样本由新鲜隔离 agent 执行并由外部监控完整保存事件、退出、用量和失败路径，结果再由不接触候选实现决策的独立审计复核。调优语料与最终封闭评估语料分离，不得把样例预期答案反向写成常驻规则后再用同一语料证明收益。历史基线可在输入身份不变时直接复用，身份变化时必须标记不可直接比较而不是静默重跑或拼接。

## AC-SQG-005 语义工具按需渐进展示

- 状态: confirmed
- 来源: 用户明确要求 `vscode-lsp-mcp` 不再以全部工具常驻展示，而是在必要时渐进展示
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003

未进入 LSP 路径的任务不应承担全部语义工具名称、说明和输入 Schema 的模型上下文成本。只有真实符号身份、类型、精确引用、层级或 Provider 诊断会改变结论时，才渐进发现并展示当前缺失能力的最小工具合同；后续能力仅在新的必要证据出现时继续展开。渐进展示不得降低输入校验、读写授权边界、预览/应用安全性或结果充分性；实际收益以端到端总 Token 和新增工具回合共同验收，不以 UI 中显示数量替代。

## AC-SQG-006 查询路径按证据与环境动态选择

- 状态: confirmed
- 来源: 用户要求结合所有可用工具研究最低 Token 查找路径，并明确指出 LSP/工作区符号在小项目或不同 Provider 下不应被绝对禁用
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003

模型应根据当前仍缺的证据、结果规模和完整性要求、项目大小、工具/Provider 的实际冷暖成本、已有定位与可复用状态，在直接读取已知文件、统一网关和 LSP 之间选择当前质量充分且总成本最低的路径。所有 rg、fd 与 ast-grep 查询由 srcq 统一接管，不保留面向模型的裸命令快路径；已知名称、文件和少量结果由 srcq 在内部选择足够轻的执行与输出模式，全集、不存在证明、语法结构和真实符号身份分别升级到能直接证明它们的最低层级。LSP 和 `workspace_symbols` 可以因当前 Provider 昂贵或失败率高而降低优先级，但不做脱离项目与 Provider 证据的永久禁用。已取得请求所需的充分证据时立即停止，不先调用 help、doctor、capabilities 或额外查询仅为了解工具。

选择统一网关后，普通调用只需表达原生命令能够表达的查询对象、范围和语义；不得要求模型在看到结果前预判应使用 heading、路径树、flat、grouped、locations、结果上限或正文预算。模型明确需要机器结构、原生字节或某种定向证据视图时仍可覆盖默认规划。

## AC-SQG-007 查询边界、失败与完整性可直接解释

- 状态: confirmed
- 来源: REQ-SQG-001 对“保证质量”与“尽可能少 Token”的共同约束
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002

每次查询必须能在当前证据需要的精度上区分：查询范围与快照身份、原生成功/无匹配/错误/超时/不可用、结果集是否完整、当前展示是否完整、正文是否被截断，以及是否可以沿同一快照续页。这些事实先由工具内部与退出状态可靠持有，不等于都要写入 stdout。默认模型输出只表达所选证据视图实际存在且不能从调用、退出状态或固定协议推出的差异；不适用的维度省略，正常成功与完整不逐次复述。只有分页、截断、错误、歧义、诊断或机器消费确有需要时才增加相应最短信息；字段省略的默认语义必须由稳定协议定义，不得将真正“未知”隐式解释为“完整”或“成功”。

## AC-SQG-008 普通查询不要求模型编排展示协议

- 状态: confirmed
- 来源: 用户明确要求模型按移除专项 skill 后的原生直觉调用，不必携带 heading、输出限制等关键词，由工具依据真实结果自动选择最佳返回形式
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-006, AC-SQG-007

普通 rg/fd 查询应允许模型沿原生命令直觉通过 srcq 表达查询，不先加载或回忆包装器的 `exec`、argv 分隔、view、limit、receipt、heading 或预算配方；AST 同样只经 srcq 的既有安全入口执行。工具必须在取得真实结果后，从单行 locator、文件 heading、路径树、路径树与位置 heading 组合、正文分组、必要分页和原生等效文本等语义等价候选中选择当前最低充分成本的表示，并自行使用安全默认上下文预算。裸输出不是简单查询的默认答案，只在对当前真实结果确实最低充分时由 srcq 选择相同效果。显式输出指令只承担调用方有意指定 machine、native、artifact 或定向证据投影的覆盖，不是普通查询正确使用的前置条件。

## CON-SQG-001 分支保持独立

- 状态: confirmed
- 来源: 用户要求刚刚形成的需求只作为分支计划，不混入总体项目
- 关联: REQ-SQG-001

本分支的需求、用户设计、模型设计、计划和实验结论只在本目录维护。用户后续明确要求完整实现后，允许把已经验证的职责迁入 README 主索引、全局规则和正式 skill；未达到的收益证据必须继续标明边界，不得因已接入项目就宣称满足根本收益。Codex 安装态仍须针对当次发布另行取得明确同意。

## CON-SQG-002 只维护 Windows

- 状态: confirmed
- 来源: 继承 AgentBase 项目平台约束
- 关联: REQ-SQG-001

候选工具、测试、基准、安装和发布设计只以 Windows 宿主为正式范围。

## CON-SQG-003 测试资产不进入 Codex 发布内容

- 状态: confirmed
- 来源: 用户明确要求项目测试只保留在项目内，不与发布到 Codex 的内容混合
- 关联: REQ-SQG-001, AC-SQG-004

本分支的测试、fixture、benchmark 协议、语料、runner、monitor、原始事件、结果和审计都只属于仓库开发资产。Codex payload 只能包含模型实际运行查询能力所需的规则、skill、工具和运行时资源；发布构建与增量安装必须排除上述开发资产，并移除受管理范围内旧版遗留副本。
