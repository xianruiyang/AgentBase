# 低成本源码查找分支需求

## 1. 文档职责与范围

本文件只定义这一候选分支要为模型带来的用户结果和验收顺序，不修改 `docs/requirements.md`，也不表示分支已经进入 AgentBase 主线。用户明确指定的技术选择见 [user-design.md](user-design.md)，模型设计见 [design.md](design.md)，实施任务见 [plan.md](plan.md)。

## REQ-SQG-001 以最低充分成本查找到所需内容

- 状态: confirmed
- 来源: 用户明确说明“根本需求是，让模型可以在保证质量的情况下，用尽可能少 Token，然后用尽可能快的速度，查找到所需的内容”
- 关联: AC-SQG-001, AC-SQG-002, AC-SQG-003, AC-SQG-004, AC-SQG-005, CON-SQG-001, CON-SQG-002, CON-SQG-003

模型应能针对实际代码查找目标，取得足以继续理解、判断或修改的正确内容；在质量充分的候选路径中选择端到端总 Token 更低者，在质量与 Token 成本均不变差时选择完成更快者。工具统一、输出格式和底层实现都只是实现手段，不构成独立完成目标。

## AC-SQG-001 所需内容正确且充分

- 状态: confirmed
- 来源: REQ-SQG-001 对“保证质量并查找到所需内容”的原子化
- 关联: REQ-SQG-001

在文本、文件、结构和真实符号语义等适用任务中，模型获得的对象、位置、范围、正文、关系和完整性足以支持当前结论；不得因截断、遗漏、陈旧快照、错误对象或工具转换把局部结果误作所需内容。质量至少不低于不使用候选能力时的同目标路径，并用任务语义而非词面命中率判断。

## AC-SQG-002 质量充分后最小化端到端总 Token

- 状态: confirmed
- 来源: REQ-SQG-001 对“用尽可能少 Token”的原子化
- 关联: REQ-SQG-001, AC-SQG-001

Token 成本按模型完成查找所实际消耗的完整链路核算，包含规则与 skill 加载、工具请求和回执进入上下文、模型输入与输出；cached input 和 reasoning output 作为所属项分列，不重复计入总量。不以包装器 stdout 字节、局部格式长度或单一样本替代；只有当前判断必需的规则、正文、回执和元数据才进入上下文。只有质量同等充分的路径才比较 Token，能无损停止时不增加查询、解释或工具回合。

## AC-SQG-003 质量与 Token 不退化后最小化耗时

- 状态: confirmed
- 来源: REQ-SQG-001 对“然后用尽可能快的速度”的原子化
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002

速度按从开始查找到模型取得充分内容的端到端耗时比较。只有质量与总 Token 均不变差时才以更低耗时为优；不得用并发、缓存或提前停止隐藏不完整结果，也不得用更快抵消质量或 Token 退化。

## AC-SQG-004 收益结论可隔离复核和重复利用

- 状态: confirmed
- 来源: 用户要求把既有测试固化为通过监控隔离 agent 执行的可重复流程
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003

质量、总 Token 和耗时结论来自受控对照：测试语料、代码快照、模型配置、工具环境、唯一候选差异、运行顺序和计量口径均被记录；每次样本由新鲜隔离 agent 执行并由外部监控完整保存事件、退出、用量和失败路径，结果再由不接触候选实现决策的独立审计复核。历史基线可在输入身份不变时直接复用，身份变化时必须标记不可直接比较而不是静默重跑或拼接。

## AC-SQG-005 语义工具按需渐进展示

- 状态: confirmed
- 来源: 用户明确要求 `vscode-lsp-mcp` 不再以全部工具常驻展示，而是在必要时渐进展示
- 关联: REQ-SQG-001, AC-SQG-001, AC-SQG-002, AC-SQG-003

未进入 LSP 路径的任务不应承担全部语义工具名称、说明和输入 Schema 的模型上下文成本。只有真实符号身份、类型、精确引用、层级或 Provider 诊断会改变结论时，才渐进发现并展示当前缺失能力的最小工具合同；后续能力仅在新的必要证据出现时继续展开。渐进展示不得降低输入校验、读写授权边界、预览/应用安全性或结果充分性；实际收益以端到端总 Token 和新增工具回合共同验收，不以 UI 中显示数量替代。

## CON-SQG-001 分支保持独立

- 状态: confirmed
- 来源: 用户要求刚刚形成的需求只作为分支计划，不混入总体项目
- 关联: REQ-SQG-001

本分支的需求、用户设计、模型设计、计划和实验结论只在本目录维护。用户明确采纳且实施证据达到根本需求前，不写入总体需求、README 主索引、全局规则、正式 skill 或 Codex 安装态。

## CON-SQG-002 只维护 Windows

- 状态: confirmed
- 来源: 继承 AgentBase 项目平台约束
- 关联: REQ-SQG-001

候选工具、测试、基准、安装和发布设计只以 Windows 宿主为正式范围。

## CON-SQG-003 测试资产不进入 Codex 发布内容

- 状态: confirmed
- 来源: 用户明确要求项目测试只保留在项目内，不与发布到 Codex 的内容混合
- 关联: REQ-SQG-001, AC-SQG-004

本分支的测试、fixture、benchmark 协议、语料、runner、monitor、原始事件、结果和审计都只属于仓库开发资产。Codex payload 只能包含模型实际运行查询能力所需的规则、skill、工具和运行时资源；发布构建与增量安装必须排除上述开发资产，并移除受管理范围内旧版遗留副本。
