# 统一源码查询网关分支需求

## 1. 文档职责与范围

本文件只定义统一源码查询网关这一候选分支的用户需求和验收边界，不修改 `docs/requirements.md`，也不表示该分支已经进入 AgentBase 总体项目主线。模型设计见 [design.md](design.md)，实施任务见 [plan.md](plan.md)。分支继承项目既有的质量、授权、Windows 平台、验证和按次发布约束。

## 2. 根本目标

### R-SQG-001 形成可长期维护的统一包装能力

- 状态: confirmed
- 来源: 用户要求要么裁撤现有包装，要么认真做成统一包装

rg、fd 与 ast-grep 的模型侧能力由同一个可维护工具承载，共享真正相同的执行、结果压缩、完整性、诊断和发布职责；backend 特有语义不得为形式统一被抹平。

### R-SQG-002 完整保留原生命令能力

- 状态: confirmed
- 来源: 用户明确要求完整兼容 rg、fd 与 ast-grep 的所有指令

在明确支持并真实验证的精确版本内，原生命令、参数值与顺序、stdin、TTY、stdout、stderr、退出状态和副作用语义都能通过包装调用。不能安全结构化的模式使用透传或显式产物，不得因包装未知而失去能力。

### R-SQG-003 选择最短充分输出

- 状态: confirmed
- 来源: 用户要求根据实际情况尽可能使用最短 Token 的输出

包装依据 backend、命令语义、调用方所需证据和实际结果形状，只在语义等价的表示间选择预计 Token 更低者。必要路径、范围、正文、捕获、诊断和完整性不得为缩短输出而删除；真实 Codex 总 Token 与答案质量决定收益。

### R-SQG-004 fd 使用可逆目录树消除重复路径

- 状态: confirmed
- 来源: 用户要求 fd 文件输出采用目录树避免重复头

fd 结果在目录树确实更短时共享根与目录前缀，同时保留根身份、对象类型、稳定顺序和可无歧义还原的完整路径。目录树只压缩表示，不以抽样冒充完整结果。

### R-SQG-005 包装质量达到 sgy 基线

- 状态: confirmed
- 来源: 用户要求若保留包装，就做到与 sgy 同等质量

新增 rg、fd 能力必须具备稳定接口、真实引擎兼容、明确错误边界、自动化测试、安装发布和来源证明，不继续把启发式特例堆叠为正式协议。

### R-SQG-006 AST 继续沿用现有 sgy 设计

- 状态: confirmed
- 来源: 用户明确要求 ast-grep 方面继续沿用 sgy 的设计

当前 sgy 的 AST 命令结构、argv 边界、profile、safe YAML、cache、fingerprint、`process containing`、`group-locations`、rewrite preview/apply、TTY/LSP、artifact、诊断和发布链是 AST 正式基线。统一化只可在保持这些可观察合同的前提下复用内部公共职责，不把 AST 迁入新命令模型，也不以 rg/fd 的较简单需求改写其边界。

## 3. 共同验收约束

### A-SQG-001 结果可复核

转换结果可区分底层版本、查询身份、原生退出、总量、展示量、省略量、结果完整性和正文完整性；转换失败、未知格式、缓存陈旧或预算不足不得表现为成功空结果。

### A-SQG-002 简单查询不承担无收益固定成本

天然有界且不需要压缩、完整性或复用的一次性查询可走受限原生快路径。统一能力只有在同一任务中提供必要质量、压缩、完整性或复用收益时才应触发。

### A-SQG-003 质量、Token、速度依次裁决

先证明查询和答案质量、授权、安全及可维护性不退化，再比较端到端总 Token；前两者均不变差时才比较速度。局部 stdout 字节或单一样本不代表整体收益。

### A-SQG-004 分支独立

需求、设计、计划和实验结果只在本目录维护。分支获用户明确采纳并达到实施完成门槛前，不写入总体需求、README 主索引、全局规则、正式 skill 或 Codex 安装态。
