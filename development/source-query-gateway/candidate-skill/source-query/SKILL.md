# Source Query

## 路由

按当前仍缺的证据选择最低充分层级：

1. 已知文件正文，或唯一文件与锚点已经定位后的连续正文：直接有界读取，不用匹配全文件的查询重读。
2. 文件发现或文本查询：直接调用 `srcq fd <native argv...>` 或 `srcq rg <native argv...>`；普通查询不加载 backend 协议，也不预选 view、tree、heading、limit 或预算。
3. 全集或不存在证明先从项目正式来源确定权威源码根，再读取 [rg-fd.md](references/rg-fd.md)；分页、特殊原生模式或显式 machine/native/artifact 也读取该文档。
4. 文本证据仍不能确定语法边界、候选歧义、控制流或结构关系，或任务明确需要 rule/rewrite：只经 `srcq` 的既有 AST 入口执行，并读取 [ast.md](references/ast.md)。
5. 结论依赖真实定义身份、重载、类型、精确引用、层级或 Provider 诊断：读取 [lsp.md](references/lsp.md)，只发现当前缺失的最小 LSP 能力。

项目大小、Provider、冷暖状态和已有定位会改变相邻层级的成本；它们只影响优先级，不形成永久禁用。证据充分后立即停止，不为了解工具先调用 help、doctor、capabilities 或无关查询。

## 运行与证据边界

- PATH 中的 `srcq.exe` 是唯一运行时。正常查询直接调用；只有命令不可用或 srcq 安装身份错误时返回安装、升级或开启新终端的恢复动作，后端版本字符串差异不触发恢复，也不搜索项目构建目录、Skill、插件或 Codex 缓存中的私有副本。
- 先限定可靠的源码根、目录、文件类型、glob、pattern 或符号；发布、构建、缓存和同步副本只有被当前项目指定为权威范围时才纳入全集，局部页不得外推。
- 只把支撑当前判断的位置、范围、正文、关系和限制带入上下文；需要续页时沿用同一 snapshot 和精确 cursor。
- AST 不替代必要正文阅读；无匹配后先从实际源码取得会改变下一次查询的语法证据，没有新证据就返回文本路径，不连续改写 pattern 试探。LSP 不重复文本或 AST 已证明的事实。修改类能力仍受上位授权约束，包装器和工具选择不创建写入或进程许可。
