# Change Governance

只在触发条件命中时，用与结论相称的直接证据收敛原因、职责、入口、迁移和完成边界。继承适用 `AGENTS.md` 的目标、授权、工具、通用验证和安全规则；不扩大实施授权，也不维护第二套全局完成术语。

## 选择参考

- bug 或故障链路的根因、系统机制、反复失效、差距或上游判断会改变动作时，完整读取 [causal-analysis.md](references/causal-analysis.md)。
- 多个入口或第二状态源的方案裁决、职责或权威入口变化、共享职责形成、跨消费者影响传播、迁移兼容、原型转正、临时路径风险评审或绕行退出条件时，完整读取 [lifecycle-and-entry.md](references/lifecycle-and-entry.md)。
- 维护 `project-metadata.md`、`file-metadata.md` 或重构同类长期状态记录时，完整读取 [records-and-metadata.md](references/records-and-metadata.md)。
- 需要证明反复失效、循环依赖或其他已修复机制确实改变，裁决测试 oracle，设计共享阻断门禁，或执行跨契约完成审计时，完整读取 [verification-and-gates.md](references/verification-and-gates.md)。
- 同一任务跨越多个边界时读取所有对应文件；不要加载无关参考。

## 工作流

1. 先确认触发条件、用户结果、授权层和待裁决对象；规格已经完整且不存在治理判断时，退出本 skill 并按普通实现流程处理。
2. 只维护会改变方案、动作或完成结论的判断，标记认识状态，并预先确定能够推翻假设的证据。
3. 对命中本 skill 的长期资产，先确认本次影响范围内的正确职责、权威入口、实际消费者、派生产物和依赖方向；按稳定约束、状态与生命周期、失败边界和变化原因裁决共同职责，比较不会制造平行入口、同步源或下游特例的真实选择。
4. 使实施动作能追溯到目标、已确认原因或必要验证；权威职责变化时从 owner 向实际消费者传播，逐项形成仍有效、更新、迁移、退出或重新验证的持久结果；新证据推翻上游判断时停止依赖它的下游工作并返回最早失效层。
5. 按选中的参考验证机制、入口、迁移退出条件或门禁语义，只把直接证据覆盖的范围报告为已验证。
6. 完成审计只覆盖用户明确要求的目标与生命周期，不把普通任务的结束动作升级为跨契约审计。

## 输出边界

- 分开表达差距事实、原因判断、解决方案、执行任务和验证证据。
- 区分直接事实、结构上必然的推断和建议；不把实现、文档或检查作为其自身正确性的独立证明。
- 明确局部修复、临时绕行、未验证范围、复发条件和退出条件。
