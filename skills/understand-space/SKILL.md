# 空间理解

当任务正确性依赖空间语义、空间关系、布局或坐标转换时使用本 skill。正文偶然出现位置、区域、层级、页面等词，或只是机械修改已明确字段时不触发。**Transform First** 是命中后的内部处理方法：即使用户没有提到 transform，也要把相关空间信息规范化为带维度、坐标系和语义主体的可比较表达。二维和三维只是在维度、方向基、投影和可用自由度上不同；核心规则相同。

## 基本不变量

1. 一个完整空间状态至少包含：`subject`、`dimension`、`frame`、`spatial_value/transform`、`time/state`、`basis_evidence`。
2. 没有坐标系的位置、旋转、缩放、轴、方向、距离、尺寸、区域、像素坐标、屏幕坐标、层级关系或方位词都不是完整信息。
3. 坐标系名称不是坐标系事实。不同软件之间、同一软件内部、UI 显示、文件存储、运行时读回和 API 写入可能使用不同坐标系。
4. 只有同一坐标系、同一维度、同一时间/状态、同一语义层级下的 transform 才能直接比较、组合、插值或判断方向。
5. 用户描述方位时使用的是语义坐标系 `Fsemantic`；它由用户语境决定，不必等于任何软件实际坐标系。
6. 软件或 API 接收的是写入坐标系 `Fwrite`；必须先在 `Fsemantic` 中构造目标，再转换到 `Fwrite`。
7. 验收必须回到用户语义：读回结果应转换到 `Fverify`，通常是 `Fsemantic` 或可明确映射到 `Fsemantic` 的坐标系。

## 基本记法

- `D`：空间维度，通常是 `2` 或 `3`。
- `F = (O, e1, ..., eD)`：坐标系，包含原点和 `D` 个基向量。
- `T(A @ F, t)`：对象、点、区域、组件、控制句柄、代理对象、相机或视图 `A` 在状态/时刻 `t` 下、坐标系 `F` 中表达的 transform。
- `M(Fa -> Fb)`：把 `Fa` 坐标系表达转换到 `Fb` 坐标系的变换。
- `Fsemantic`：从用户语境推断出的语义坐标系。
- `Fwrite`：目标软件、节点、文件或 API 要求写入的坐标系。
- `Fread`：读回数据实际所属的坐标系。
- `Fverify`：最终比较和验收使用的坐标系。

本文所有矩阵公式统一使用一套内部记法：齐次坐标列向量、变换左乘，组合式从右向左作用；`T(A @ F)` 表示把 `A` 的局部坐标表达映射到 `F`，`M(Fa -> Fb)` 表示把 `Fa` 中的坐标表达映射到 `Fb`。这只是本 skill 的规范化记法，不是对目标软件或 API 的事实声明。目标系统若使用行向量右乘、相反的映射方向、不同存储布局或不同组合顺序，必须先根据已验证约定转换矩阵表示和乘法顺序，不能直接套用本文公式。

二维 transform 通常包含平移、旋转、缩放、剪切、锚点/枢轴、裁剪或层级偏移。三维 transform 通常包含平移、旋转、缩放、父级层级、相机投影、深度和可见性。不要把其中任何一个字段脱离坐标系单独判断。

## 坐标系事实调查

动手前先列出 `frame_inventory`。不要按软件名、空间名、经验或 UI 颜色推断坐标系事实。

每个涉及坐标系都要尽量确认：

- 维度、原点、基向量方向、手性或二维方向约定、单位和缩放约定。
- 旋转表示、角度正方向、欧拉角顺序、矩阵行列约定、四元数约定和 transform 组合顺序。
- transform 是世界、局部、父级、组件、视图、屏幕、画布、页面、图像像素、资源导入、运行时、文件存储还是 API 自定义空间。
- UI gizmo、面板数值、文件内容、运行时读回、截图视角和 API 写入是否同属一个坐标系。
- 二维系统是否存在 y 轴向下、左上角原点、设备像素比、滚动偏移、缩放级别、锚点、pivot、布局约束或裁剪区域。
- 三维系统是否存在轴交换、手性翻转、单位缩放、预旋转、父级补偿、冻结变换、烘焙、相机投影或深度遮挡。
- 当前操作是否依赖特定帧、视口、布局状态、父级层级、约束状态、求解状态或缓存状态。

输出结论必须能说明：涉及哪些坐标系、各自实际状态是什么、它们之间如何转换、哪些仍不确定。

## 语义坐标系解析

把用户的空间语言先解析成 `Fsemantic`，再谈软件轴或写入值。

- 用户明确给出主体时，以该主体、视图、屏幕、页面、画布、对象或任务目标建立语义坐标系。
- 用户省略主体时，根据当前任务对象、上文、视角、交互焦点、动作目的和结果验收目标推断；证据不足时标记不确定。
- 二维常见语义方向是 `right/left/up/down`、顺时针/逆时针、内/外、靠近/远离、上层/下层。
- 三维常见语义方向是 `front/back/right/left/up/down`、绕轴旋转、靠近/远离相机、内/外、上层/下层。
- `front/right/up` 或二维 `right/up` 必须有依据：主体设计方向、运动方向、相机/屏幕视图、页面流向、参考状态、用户显式指定或可读回的空间关系。
- 不要把世界轴、屏幕轴、局部轴、导入轴、代理对象轴、约束轴、布局轴或 gizmo 方向直接当成用户语义方向。

方位词只表示 `Fsemantic` 中的方向。二维没有天然“前方”；只有当主体朝向、运动方向、视图方向或用户语境定义了 `front` 时，才可使用前/后。

## 空间处理流程

处理任何空间描述、判断或操作时按固定顺序推进：

1. `subject`：确定被操作对象和参考主体。
2. `dimension`：确认任务是在二维、三维，还是三维投影到二维后验收。
3. `frame_inventory`：确认涉及坐标系的事实和转换关系。
4. `Fsemantic`：解析用户语义坐标系和方向基依据。
5. `current @ Fsemantic`：把当前空间状态转换到语义坐标系理解。
6. `target @ Fsemantic`：在语义坐标系中构造目标空间表达；需要操作时再规范化为 transform。
7. `conversion_chain`：写出 `Fsemantic -> ... -> Fwrite`。
8. `target @ Fwrite`：需要写入时按 API 约定转换并写入。
9. `readback @ Fread`：读回实际结果和状态。
10. `readback @ Fverify`：转换到验收坐标系，做数值和视觉语义检查。

任一步缺少维度、坐标系、转换链、主体语义或读回证据时，不要继续扩大操作范围。

## 比较、转换与规范化

比较前必须统一维度和坐标系。空间关系可以是点、向量、区域、边界盒、投影或 transform，但都必须先规范化到明确坐标系：

`delta_p @ F = p(A @ F) - p(B @ F)`

在上述列向量左乘记法下，比较姿态时使用相对 transform，不要直接比较角度或欧拉角表面数值：

`T(A relative_to B) = inverse(T(B @ F)) * T(A @ F)`

在同一记法下，跨坐标系转换必须显式写出：

`T(A @ Fb) = M(Fa -> Fb) * T(A @ Fa)`

点、方向、法线或区域不要混用：

- 点受平移、旋转、缩放影响。
- 方向不受平移影响。
- 二维区域需要区分位置、尺寸、锚点、pivot、边界盒、裁剪和层级。
- 三维法线在非均匀缩放下需要按逆转置逻辑处理。

缩放也要带坐标系和组合顺序；不要把屏幕缩放、布局缩放、世界缩放、局部缩放、父级缩放和资源导入缩放混为一谈。

## 方向与关系判断

方向判断使用投影，不使用裸轴增量。

先把目标、主体和方向基转换到 `Fverify`：

`d = p(target @ Fverify) - p(subject @ Fverify)`

二维常用：

`right_amount = dot(d, right @ Fverify)`

`up_amount = dot(d, up @ Fverify)`

三维或已定义朝向的二维主体可再使用：

`front_amount = dot(d, front @ Fverify)`

判断区域关系时，先明确比较对象是点、中心点、边界盒、轮廓、多边形、投影包围盒还是可见像素区域。判断“重叠、包含、对齐、间距、靠近、遮挡、出框”时，必须使用同一坐标系下的对应几何量。

## 代理控制对象与结果对象

很多空间系统不是直接修改最终结果，而是通过控制点、句柄、驱动器、约束、节点、父对象、中间组件、布局系统或求解器影响结果对象。此时至少区分：

- `Fsemantic`：用户意图所在的语义坐标系。
- `Fcontrol`：代理控制对象自身或 API 可写入的坐标系。
- `Fresult`：最终结果对象被观察、读回或验收的坐标系。

先在 `Fsemantic` 中定义目标，再通过明确转换链写入 `Fcontrol`，最后在 `Fresult` 或 `Fsemantic` 中验收结果。代理对象数值正确但最终结果语义错误，仍然失败。

## 视觉与读回验收

验收不能只看命令成功或数值变化。必须同时检查：

- 读回 transform 是否属于预期维度、坐标系和状态。
- 读回结果转换到 `Fverify` 后，投影量、相对 transform 或区域关系是否满足语义目标。
- 二维图像或 UI 是否显示正确的位置、方向、对齐、尺寸、层级、裁剪和可见区域。
- 三维图像是否显示正确的空间方位、姿态、相机视角、深度关系、遮挡和投影结果。
- 若视觉和读回矛盾，先定位坐标系、布局刷新、截图、投影、求解或读回链路问题，不要选择性相信其中一个。

## 最小输出模板

处理空间任务时，输出或内部记录至少包含：

- `subject`：被操作对象。
- `dimension`：二维、三维，或三维到二维投影。
- `frame_inventory`：涉及坐标系、实际状态、转换关系和未知项。
- `Fsemantic`：用户语义坐标系及依据。
- `current @ Fsemantic`：当前空间状态。
- `target @ Fsemantic`：目标空间状态；需要操作时说明对应 transform。
- `Fwrite` 与 `conversion_chain`：如需写入，写清实际写入空间和转换路径。
- `readback_check`：读回来源、读回坐标系和比较方式。
- `visual_check`：图像上应看到的语义关系。
- `result`：通过、失败或不确定；失败时写明是哪一层坐标系、维度或语义关系出错。

## 硬停止条件

遇到以下任一情况，先补证据或做坐标转换：

- 位置、方向、距离、尺寸、区域、布局关系、层级关系、旋转、缩放、轴或 transform 没有标注维度和坐标系。
- 坐标系名称被当成坐标系事实。
- 用户语义坐标系、软件坐标系、屏幕/画布/页面空间、UI 展示空间、文件存储空间、读回空间或 API 写入空间被混为一谈。
- 未查清涉及坐标系实际状态，就直接描述、转换、比较、插值、操作或验收空间关系。
- 使用矩阵公式却没有声明向量方向、映射方向和组合顺序，或把本文列向量左乘公式直接用于其他 API 约定。
- 不同维度、不同坐标系、不同时间/状态、不同语义层级的 transform 被直接比较或组合。
- 方位词没有绑定主体，或方向基依据不明。
- 代理对象、局部轴、导入轴、约束轴、布局轴或 gizmo 方向被直接当作用户语义方向。
- 视觉结果、读回 transform 和用户语义互相矛盾。
