# 空间理解

命中后先把空间信息规范化为带主体、维度、坐标系、状态和证据的表达，再按目标比较、计算、操作或验收。不要把某个软件或 API 的轴、矩阵和组合约定当作通用事实。

## 按需读取

- UI、网页、画布、图像、屏幕、视口、锚点、裁剪或二维布局任务，完整读取 [two-dimensional-layout.md](references/two-dimensional-layout.md)。
- 世界/局部/父级/组件空间、姿态、相机、导入轴、手性或三维遮挡任务，完整读取 [three-dimensional-transform.md](references/three-dimensional-transform.md)。
- 任务涉及跨坐标系转换、相对 transform、矩阵约定、代理控制对象、数值读回或视觉验收时，完整读取 [frame-transform-verification.md](references/frame-transform-verification.md)。
- 同一任务跨越多个类别时读取所有对应文件；机械修改已经确认的单一字段和值时退出本 skill。

## 核心不变量

1. 完整空间状态至少包含 `subject`、`dimension`、`frame`、`spatial_value/transform`、`time/state` 和 `basis_evidence`。
2. 位置、旋转、缩放、轴、方向、距离、尺寸、区域、像素或屏幕坐标没有坐标系就不是完整信息；坐标系名称也不等于其实际约定。
3. 只有同一维度、坐标系、时间/状态和语义层级下的表达才能直接比较、组合或插值。
4. 用户意图位于语义坐标系 `Fsemantic`；软件写入位于 `Fwrite`；读回数据属于 `Fread`；验收统一到 `Fverify`。需要修改时，先在 `Fsemantic` 构造目标，再转换写入并读回验收。
5. 用户的前后左右、上下、内外和远近必须绑定主体与方向基证据；世界轴、屏幕轴、局部轴、导入轴、约束轴或 gizmo 方向不能自动替代用户语义。
6. 代理控制对象数值正确不代表结果对象正确；最终判断回到用户可观察的结果关系。

## 处理顺序与适用步骤

只执行当前目标所需的步骤。只读比较或计算使用给定输入与适用证据，不构造待写目标、不执行写入或为计算结果调用运行时读回；判断真实系统状态时仍须取得实际状态证据。视觉验收按下节选择。

1. `subject`：确定操作对象、参考主体和结果对象。
2. `dimension`：确定二维、三维或三维投影到二维。
3. `frame_inventory`：列出当前动作涉及的坐标系及必要约定，不要求补齐无关空间或旋转参数。
4. `Fsemantic`：根据主体、视图、交互焦点和用户目标确定语义方向基；证据不足时标记未知。
5. `current @ Fsemantic`：把当前状态转换到语义坐标系理解。
6. `target @ Fsemantic`：需要修改时，在语义坐标系中构造目标位置、区域、关系或 transform。
7. `conversion_chain`：需要转换时明确实际来源到目的坐标系的映射，包括适用的单位、轴、手性、父级和组合顺序；写入路径的目的坐标系为 `Fwrite`。
8. `target @ Fwrite`：只在用户已授权操作且转换链明确时写入。
9. `readback @ Fread`：写入后从正式入口读回实际结果，不把命令成功或 UI 显示值当作结果本身。
10. `result @ Fverify`：把计算或读回结果统一到验收坐标系，检查目标要求的数值关系或视觉语义。

任一步缺少会改变动作或结论的主体、维度、坐标系事实、转换链或读回证据时，先补证据，不扩大操作范围。

## 比较与验收

- 比较前先统一维度、坐标系和状态；区分点、方向、法线、区域、边界盒、投影和完整 transform。
- 方向关系使用相对位移在已验证方向基上的投影，不用裸轴增量。
- 姿态关系使用相对 transform，不直接比较欧拉角表面值。
- 区域关系先说明比较的是中心、边界盒、轮廓、多边形、投影包围盒还是可见像素。
- 纯几何、坐标转换或数值状态目标使用适用的计算或实际数值读回验收；目标包含实际画面中的位置、裁剪、遮挡、投影或可见性时取得视觉证据，并保留证明转换或数值约束所需的读回。两者都适用却矛盾时调查坐标系、布局刷新、投影、求解、截图或读回链路，不选择性相信其中一个。

## 最小结果表达

只报告适用且支撑结论的内容，不为固定字段表补空值；缺失的必要证据须明确说明。

- `subject` 与 `dimension`
- `frame_inventory` 与未知项
- `Fsemantic` 及方向基依据
- 比较或计算的输入与结果；修改时的 `current @ Fsemantic` 与 `target @ Fsemantic`
- 发生转换时的 `conversion_chain`；需要写入时的 `Fwrite`
- 适用的数值、读回或视觉检查及证据
- `result`：通过、失败或不确定，并指出失败所在的维度、坐标系、状态或语义关系

## 硬停止

- 不同维度、坐标系、状态或语义层级被直接比较或组合。
- 坐标系只有名称，缺少当前判断必需的原点、轴、单位、手性/二维方向、旋转或组合约定证据。
- 方位词没有主体，或用户语义方向被软件轴、局部轴、代理对象或 gizmo 直接替代。
- 使用矩阵公式却未声明向量方向、映射方向和组合顺序。
- 视觉结果、读回状态和用户语义互相矛盾。

出现硬停止条件时先补证据或完成转换；不能补齐时限定结论，不伪造确定值。
