# 坐标系、转换与结果验收

## 记法

- `D`：二维或三维。
- `F = (O, e1, ..., eD)`：包含原点和方向基的坐标系。
- `T(A @ F, t)`：在状态 `t` 下，把对象 `A` 的局部坐标映射到 `F` 的齐次仿射变换矩阵；不是位置、欧拉角等姿态参数本身。
- `M(Fa -> Fb)`：同一几何对象从 `Fa` 坐标表达转换到 `Fb` 坐标表达的矩阵。

本文统一用齐次坐标列向量、变换左乘、组合从右向左作用。它只是内部规范化记法。目标 API 使用行向量右乘、相反映射方向或其他组合顺序时，先转换记法，不能直接套用公式。

## Frame inventory

每个相关坐标系按当前动作确认必要约定；以下为候选事实，不是全部必填项：

- 维度、原点、基向量、手性或二维方向、单位和缩放。
- 旋转表示、正方向、欧拉顺序、矩阵行列、四元数和组合顺序。
- 所属语义层：世界、局部、父级、组件、视图、屏幕、画布、像素、导入、存储、运行时或 API 自定义。
- UI/gizmo、面板值、文件内容、API 写入、运行时读回和截图是否同属一个空间与状态。

坐标系名称不能替代这些事实。输出需说明已确认约定、转换来源和未知项。

## 统一与转换

以下公式中的变换必须使用上述映射方向、同一状态和兼容维度。目标 API 使用反向映射时先取得相应逆变换；涉及求逆的矩阵必须可逆，例如零缩放造成的奇异变换不能套用逆变换公式。

`T(A @ Fb) = M(Fa -> Fb) * T(A @ Fa)`

相对姿态：

`T(A relative_to B) = inverse(T(B @ F)) * T(A @ F)`

相对位移：

`d = p(target @ Fverify) - p(subject @ Fverify)`

方向投影：

`right_amount = dot(d, right @ Fverify)`

`up_amount = dot(d, up @ Fverify)`

已定义前向时：

`front_amount = dot(d, front @ Fverify)`

不要混用点、方向、法线和区域：点受平移影响，方向不受平移影响，法线在非均匀缩放下需要目标系统对应的逆转置处理，区域还包含边界、裁剪和投影语义。

## 代理控制对象

系统通过控制点、句柄、驱动器、约束、节点、父对象、布局系统或求解器影响结果时，至少区分：

- `Fsemantic`：用户目标所在空间。
- `Fcontrol`：代理控制对象或 API 可写入空间。
- `Fresult`：最终结果对象的观察空间。

需要修改时先构造 `target @ Fsemantic`，经明确转换写入 `Fcontrol`，最后在 `Fresult` 或 `Fsemantic` 验收。只读判断结果时取得结果对象的适用证据，不触发写入；控制值正确但结果语义错误仍为失败。

## 读回与视觉证据

- 读回结果必须标注主体、坐标系、状态/帧和来源。
- 转换到 `Fverify` 后，用投影量、相对 transform 或区域关系检查目标。
- 目标需要视觉证据时，说明影响判断的相机/视口、缩放、裁剪、深度和刷新状态；不为纯数值目标强制取得画面。
- 命令成功、字段改变、控制器值、单张截图或单个中间层结果只能证明各自直接覆盖的范围。
- 数值与视觉冲突时先定位坐标转换、布局刷新、投影、求解、截图或读回链路，不选择性采信。
