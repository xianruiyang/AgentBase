# 三维 Transform 与视图

## 需要确认的事实

只确认影响当前动作或验收的事实；纯数值变换不要求无关的相机与可见性状态：

- 世界、局部、父级、组件、骨骼、约束、导入、文件存储、相机/视图和 API 自定义空间。
- 原点、轴方向、手性、单位、缩放、预旋转、冻结变换和父级补偿。
- 旋转表示、角度正方向、欧拉顺序、四元数约定、矩阵存储与 transform 组合顺序。
- 相机投影、深度范围、视锥、遮挡、可见性、求解状态和缓存状态。

## 语义方向

- `front/right/up` 必须来自主体设计朝向、运动方向、相机视图、参考姿态、用户指定或可读回关系。
- 世界轴、局部轴、导入轴、骨骼轴、控制器轴和 gizmo 方向可能不同，先转换到 `Fsemantic`。
- “靠近相机”“物体前方”“世界上方”属于不同方向基，不能混用。

## Transform 处理

以下为修改真实系统的顺序；仅对给定数据计算或比较时，完成适用转换与验收即可。只读检查真实系统仍需取得实际状态证据，但不执行写入。

1. 读取当前父级层级、约束和实际求解后的 transform。
2. 在 `Fsemantic` 中定义目标位置与姿态。
3. 明确轴交换、手性翻转、单位缩放、预旋转和父级逆变换的顺序。
4. 写入 API 所需的 `Fwrite`，不要把 UI 展示值直接当成存储或运行时值。
5. 读回结果对象的世界/结果空间，而不只读控制器或中间节点。

## 接触、穿插与功能区域

- 模型物体之间，以及物体与墙体、地面、地形等环境边界之间，避免违反目标语义的穿透、悬浮和错位。先区分分离、接触、嵌入或设计上允许的相交；装配嵌合、入土和其他有依据的重叠不能一律消除，也不能通过拉开所有物体破坏接触关系。
- 功能区域是具有用途和边界的空间，如通道、门洞、操作区或运动所需空间；任务以“语义空间”描述此类区域时，应与表达用户方向意图的坐标系 `Fsemantic` 区分。按当前任务确认区域边界、允许占用和必要净空，避免物体异常侵入；运动任务还要考虑实际动作扫过的范围，不能仅看静止姿态。沿用已有约束；缺失且会改变摆放时补证据，不虚构通用净空尺寸。
- 包围盒相交只用于定位候选，不单独证明实际几何穿透；包围盒不相交也不证明通道净空、运动范围或视线要求成立。按目标采用实际几何、适用碰撞查询、距离或相关视角核实，碰撞代理与可见网格不等价时分别判断。

## 用户可见面与深度冲突

- 用户可见区域避免无用途的重复面、共面或近共面覆盖。深度缓冲的精度有限：覆盖同一屏幕位置的表面若深度过于接近，计算与量化后可能无法稳定区分前后，产生闪烁或斑纹，即 Z-fighting。它与实体穿透、正常前后遮挡或透明排序问题分别判断，不能只按重叠面积推断。
- 深度分辨能力取决于实际投影、近远裁剪面、深度格式与映射方式；世界空间中的固定间隔不保证所有视距都无冲突。先检查重复几何与实际表面间距，再按当前渲染配置核对相关因素，不把“缩短远裁剪面”或“反向深度”当作无条件修复。
- 优先消除已证冗余或错误的几何覆盖；有意的贴面装饰、分层表面按目标渲染器支持的机制处理。不能统一给物体加固定偏移、关闭深度检测或换视角隐藏问题，以免破坏接触、遮挡和用户目标。

## 三维验收

- 用统一坐标系下的相对位置、相对姿态、边界或投影关系验证。
- 目标包含实际画面中的位置、遮挡、投影或可见性时，检查相关相机视角、深度和画面关系；世界 transform 正确不保证画面语义正确。纯数值目标按相应坐标关系验收，不引入无关渲染检查。
- 非均匀缩放下区分点、方向和法线；法线按目标 API 的逆转置等价规则处理。
- 动画、约束、Control Rig、物理或其他求解器参与时，记录验收帧与求解状态。
- 穿插与净空按允许的接触关系、区域边界及适用容差验收；可见面冲突按用户实际使用的视角与距离检查，运动或视角变化会改变结果时覆盖相应变化。单张静态截图不证明没有动态穿插或深度闪烁，隐藏面未出现在画面中也不证明功能区域可用。
