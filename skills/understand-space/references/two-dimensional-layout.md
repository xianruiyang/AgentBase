# 二维布局与屏幕空间

本文件由 `understand-space` 维护，供模型确定布局、截图与目标入口之间的空间关系；软件默认值见 [软件速查](software-coordinate-systems.md)。API 事实来自下列官方来源（2026-09-08 核对），实际窗口、视口、DPI 与截图元数据由对应入口持有。环境改变后重取受影响状态，不把旧截图映射另存为长期配置。

## 需要确认的坐标系

只确认当前比较、转换、写入或验收涉及的项目：

- 页面、画布、布局容器、局部控件、视口、桌面、窗口、客户区、截图与设备像素是否是不同空间。
- 原点位置、x/y 方向、滚动偏移、视口偏移、缩放级别和设备像素比。
- 锚点、pivot、父级布局、约束、自动尺寸、边距、padding、裁剪和层级偏移。
- UI 面板值、布局计算值、截图像素和 API 写入值分别属于哪个空间与刷新状态。

## 屏幕空间不是单一坐标系

| 对象 | 原点与范围需绑定到 | 典型混淆 |
| --- | --- | --- |
| 虚拟桌面 / 单台显示器 | 整个显示器布局，或指定显示器的矩形 | 主屏左上不一定是整个桌面左上；副屏坐标可为负 |
| 窗口 / 客户区 | 窗口外框，或不含边框与标题栏的内容区 | 客户区 `(0,0)` 不是桌面 `(0,0)`；工具栏还可能占用客户区 |
| 应用视口 / 嵌入面板 | 实际内容矩形、相机、目标显示器或子视图 | 窗口尺寸不等于视口尺寸；黑边、分屏、编辑器面板和渲染缩放会改变映射 |
| 浏览器页面 / 视口 | 文档、布局视口、视觉视口或具体 iframe | 页面滚动、缩放、嵌套 frame 的偏移不能当成同一个平移 |
| 截图 / 模型看到的图像 | 捕获对象、裁剪矩形、原始图像尺寸及后续缩放 | 展示缩略图的像素不能直接作为原图或桌面位置 |
| 归一化屏幕位置 | 明确的参考矩形、原点和归一化合同 | `[0,1]` 不说明归一化的是整个显示器还是某个视口，也不等于纹理 UV |

[Windows 窗口坐标](https://learn.microsoft.com/en-us/windows/win32/gdi/window-coordinate-system) 区分屏幕与客户区；[虚拟桌面](https://learn.microsoft.com/en-us/windows/win32/gdi/the-virtual-screen) 允许主屏左侧或上方出现负坐标。不能为使坐标非负而截断或擅自改原点。

## DPI、缩放与截图映射

- 区分物理像素、DIP（设备无关像素）、CSS px 和工具自定义坐标。Windows API 的返回值可能受调用线程的 DPI awareness 与虚拟化影响；多显示器可有不同 DPI，不能给整个桌面统一乘一个比例，也不能对已是物理像素的值再次缩放。[Windows DPI 合同](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)
- 浏览器的页面缩放、设备像素比与视觉视口缩放分别核对。布局视口和视觉视口可能不同，`visualViewport` 的偏移与 scale 按实际 API 解释；不要无依据重复叠乘缩放。[CSSOM View](https://www.w3.org/TR/cssom-view/#the-visualviewport-interface)
- 从截图定位时，优先使用捕获或操作工具已声明的坐标合同。否则先确认原图尺寸、裁剪起点、缩放、留白及目标区域；只有已证为同轴的缩放和平移时，才用 `p_target = origin + scale * p_image`，其中 `origin` 以目标坐标计，`scale` 是目标单位与图像单位的逐轴比例。若输入坐标是缩略图像素，先还原图像映射；工具已接收截图坐标时不再转换成桌面坐标。
- 窗口移动、跨屏、DPI 改变、滚动、视口调整或截图重采样后，只更新受影响映射。操作前需要的对象身份与坐标应来自同一有效状态；实际操作仍按对应工具协议，不因取得屏幕坐标获得操作授权。

## 屏幕点、可见性与交互

- 屏幕上落入同一位置，不证明物体可见、控件可点击或选择射线命中它。按目标区分投影范围、实际遮挡/裁剪、可见区域和输入命中对象；包围盒中心不一定属于可见或可命中的区域。
- 仅一个屏幕 `(x,y)` 通常不能唯一恢复三维点；还需对应相机、视口及深度、指定平面或实际命中约束。射线不是命中结果，深度缓冲值也不直接等于相机距离；例如 [Unity ScreenPointToRay](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Camera.ScreenPointToRay.html) 返回世界空间射线。投影和深度约定沿用 [裁剪与视口](clip-viewport-uv.md#裁剪与视口)。

## 语义方向与区域

- `right/left/up/down` 以用户当前页面、画布、屏幕或主体方向为基准，不把 y 轴向上或向下当作默认事实。
- 二维没有天然的“前方”；只有主体朝向、运动方向、页面流向或用户语境明确时才定义前后。
- 判断重叠、包含、出框、对齐、间距或靠近前，说明比较的是中心点、布局框、边界框、轮廓、多边形、裁剪后区域还是可见像素。
- 层级高低、绘制顺序和几何位置是不同关系；不要用 z-order 代替遮挡或空间包含判断。

## 写入与刷新

仅修改真实布局时执行；只读几何计算按已确认输入直接比较与验收。

1. 在 `Fsemantic` 中定义目标关系，例如“按钮右边缘与卡片右边缘相距 16 CSS px”。
2. 确认 `Fwrite` 接收绝对位置、相对偏移、锚点、约束还是布局参数。
3. 处理 CSS 像素、设备像素、缩放、滚动和父级 transform。
4. 写入后等待影响目标结果的布局刷新，读取实际几何量；目标涉及画面语义时还须等待渲染刷新并取得截图或其他适用视觉证据。

## 验收

- 纯计算检查输入、转换和所得几何关系；真实布局状态读回任务实际使用的布局框、变换后边界或其他几何量及其坐标系。
- 目标包含画面语义时，视觉检查覆盖所要求的位置、方向、尺寸、对齐、间距、层级、裁剪或可见区域；纯几何或数值目标不要求截图。
- 数值正确但截图错误时，检查刷新时机、媒体查询、缩放、滚动、字体重排、裁剪和父级 transform。
- 截图看似正确但读回错误时，检查相机/视口裁切、像素比、临时动画状态和读错节点。
- 屏幕映射用实际相关的已知位置或独立参照核对偏移与尺度；混合 DPI、裁剪缩放或窗口迁移只在任务涉及这些变化时验证。静态图上的位置正确不证明后续输入命中；有交互目标时按工具能力读回实际作用对象或结果。
