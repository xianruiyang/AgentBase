# 任务执行与恢复

## 选择当前工作

1. 直接从任务文档与当前证据选择工作；任务较多时可用 `taskctl next` 取得有界候选和诊断。
2. 需要压缩上下文时可用 `taskctl context --id <ID> --budget <chars>` 读取任务合同、直接依赖结果、必要上游条目、直接下游消费者和 `source_snapshot`；结果必须携带这份实际输入快照，截断时先按返回 ID 补齐，不在完成时用当前版本代替。
3. 根据用户优先级、真实依赖、并行冲突和当前能力选择任务。CLI 排序只是建议。
4. 若任务合同不足以执行，修订最早缺失的阶段产物或任务合同，不创建占位结果。

## 状态

```text
todo → claimed → in_progress → review → done
                   ↘ blocked
任意状态 → retired
```

- 上图是默认表达，不是 CLI 强制状态机。非典型流转或文档定义的扩展状态会原样保存并返回诊断，但不代替模型根据真实工作作出判断。
- `claim` 记录 owner 意图；不同任务可以并行领取。owner 不一致是协调诊断；每次状态写入都必须基于调用方刚读到的 state revision，缺少或冲突才阻断写入。
- `start` 表示开始实际工作。
- `note` 更新简短进度、阻塞原因或下一动作，不保存运行日志。
- 非空阻塞原因默认把任务表达为 `blocked`；原因与状态不一致时报告诊断并保留信息，不为了形式一致丢失原始记录。
- `complete` 记录模型已经做出的完成判断；从 `todo/claimed/blocked/done` 等非典型状态调用时返回诊断，但只要结果记录可结构化保存就不由 CLI 拒绝。
- `reopen` 和 `release` 分别记录完成结论失效与领取结束；对当前状态或 owner 的不一致返回诊断。
- `retired` 用于上游方案变化、任务被替代或不再属于当前范围；保留原合同、结果和退出原因。

CLI 对已有合同和状态写入统一使用 CAS：先读取当前记录，再把其 revision 作为对应 `--expected-*-revision` 传回；缺少或冲突都会拒绝本次写入。它只防止并发覆盖，不证明 owner、流转或工作内容正确。owner 不一致和不同任务的 mutation scope 重叠都只返回协调诊断。

## 并行与下游消费

- `hard` 依赖完成前，下游仍可做不消费其结果的分析、取证或准备，但不得假装前置产出已经成立。
- 公共产出与消费者接入分成任务时，消费者通过 `dependencies[].consumes` 指出实际使用的产出；建立但无人消费的公共层不是完成结果。
- 完成任务时把后继真正需要的结论写进 `outputs`；原始日志、截图和大型文件保存在项目适合的位置，只登记路径和简要用途。
- `context` 加载直接依赖结果和任务来源的传递语义祖先，并返回直接下游；需要完整后继影响时使用递归 `impact`，再从实际系统补齐任务图未登记的消费者。
- 新证据推翻上游设计或方案时，在结果的 `invalidated_source_ids` 中记录，并回到 `$delivery-workflow` 修订；CLI 不批量重置任务。
- 上游修订后逐项判断递归后继任务与既有结果：仍有效的重新验证，需要修改的更新或重开，被替代的退休；来源快照缺失、不完整或陈旧的结果不能直接沿用为当前证据。

## 推理与领域 skill

任务的 `reasoning_hint` 和 `suggested_skills` 只帮助开始工作。执行中按下一段真实不确定性和后果使用 `$reasoning-governor`，按修改对象触发对应领域 skill；不受任务文件固定。

## 进度报告

`taskctl status` 固定返回所有任务状态数量，并可读取交付链索引中的上游未决数量以及结果验证摘要。报告时说明：

- 哪些任务完成、进行、评审、阻塞或待办；
- 哪些关键上游条目仍为 open/unknown；
- 多少结果包含验证，哪些仍有未决问题。

这些指标互不替代，不合成误导性的总体百分比。

最终复核直接遍历当前执行周期经用户确认的 Markdown 目标，并检查当前约束与全部 DCR。范围较大时可运行 `completion-context`；它尝试在内存中从当前文档重建索引，并保留 DCR 的原始状态，快照或缓存漂移只返回诊断。分页时保存首页 snapshot ID，每次续页只选择一个结果流并传回该流上一页返回的精确游标；快照变化、续点无法识别，或续页时当前 Markdown 无法重建以核对快照时，从第一页重审。本次方案改变长期 owner 或契约时还要复核递归影响中的适用消费者和结果来源时效；任务全部 `done`、结果带验证或中间阶段审核通过，都不能单独得出整体完成。
