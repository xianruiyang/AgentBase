# 确定操作交接

本参考供派发者使用；operator 的执行、异常和返回边界由角色指令维护，不再加载本编排流程。

当前派发者（根主代理或所属 experiment）给出已确认对象、允许动作、步骤或正式入口、判定依据，以及自己最终需要的信息；运行态查询附上影响配置加载的原工作目录、配置根与已知启动参数，未知且影响对象定位时先补取证。按需补日志位置、时限和已有恢复步骤，写入另给文件所有权与恢复依据。不传整段探索历史，不强制填固定表格。

- 日志使用已有目录或本次临时文件；优先选择支持静默/摘要输出的入口，完整输出按需落盘，不要求 operator 通读全部日志或把它回传。
- 默认向当前派发者最终集中交付。只有需要派发者及时动作的阻塞、风险或预先约定的交接点才中途回传，不以每个阶段完成作为汇报理由；实验内普通失败不直接转报根主代理。
- 当前派发者按结果与关键来源接纳，根主代理保留最终验收；信息不足时通过 `followup_task` 向原 operator 追问缺口，活跃时用 `send_message`。复用其上下文，不默认重新执行、另建代理或重读全部日志。

原始日志是执行证据，精简交付只是导航；必要时从日志恢复细节。保留到接纳与必要追问结束，之后沿项目已有生命周期处理，不另建永久账本。委派不增加操作权限，也不把非必要清理或未覆盖的故障修复变成 operator 的任务。
