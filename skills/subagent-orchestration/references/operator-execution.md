# 确定操作交接

本参考供派发者使用；operator 的执行、异常和返回边界由角色指令维护，不再加载本编排流程。

主代理给出对象、允许动作、步骤或正式入口、判定依据，以及自己最终需要的信息；按需补日志位置、时限和已有恢复步骤，写入另给文件所有权与恢复依据。不传整段探索历史，不强制填固定表格。

- 日志使用已有目录或本次临时文件；优先选择支持静默/摘要输出的入口，完整输出按需落盘，不要求 operator 通读全部日志或把它回传。
- 默认最终集中交付。只有需要主代理及时动作的阻塞、风险或预先约定的交接点才中途回传，不以每个阶段完成作为汇报理由。
- 主代理按结果与关键来源验收；信息不足时通过 `followup_task` 向原 operator 追问缺口，活跃时用 `send_message`。复用其上下文，不默认重新执行、另建代理或重读全部日志。

原始日志是执行证据，精简交付只是导航；必要时从日志恢复细节。保留到接纳与必要追问结束，之后沿项目已有生命周期处理，不另建永久账本。委派不增加操作权限，也不把非必要清理或未覆盖的故障修复变成 operator 的任务。
