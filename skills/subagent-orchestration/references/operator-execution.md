# 重复执行与长时观察交接

本参考供派发者使用；operator 的执行、异常和返回边界由角色指令维护，不再加载本编排流程。

根主代理一次交清可复用规则：对象与允许动作、每次可变的输入、步骤或正式入口、结果判定、停止与异常条件，以及最终需要的信息。自行循环时明确继续条件与资源边界；长时观察给出信号来源、检查间隔或事件等待方式，按判定区分正常结束、失败与仍在等待。写入另给文件所有权与恢复依据，按需附日志位置、时限和已有恢复步骤。不传整段探索历史，不强制填固定表格。

规则仍适用时，用 `followup_task` 给原 operator 本轮输入和所需结果，无需重新创建或重述整套规则；规则变更只补差异。预期未来可复用不等于已授权自行执行未来工作，当前触发或循环仍按委派范围推进。

连续操作、等待、既定检查和汇总留在同一执行段；在约定停止条件或需要派发者查看视觉结果、解释新现象、选择修复方向时交接。不按每个脚本、截图或采样拆派，也不以省略必要检查或日志缩短执行。

运行态观察保持原调用的工作目录、配置根和影响加载的启动参数；无法复现时返回缺口，换环境后的结果仅作为标明差异的对照。

- 日志使用已有目录或本次临时文件；优先选择支持静默/摘要输出的入口，完整输出按需落盘，不要求 operator 通读全部日志或把它回传。
- 任务完成或停止时，通过最终回复向根主代理集中交付。仅在任务仍需继续、且根主代理必须立即采取动作时使用 `send_message`；普通进度与阶段结果合并到最终交付。
- 根主代理按结果与关键来源接纳并负责最终验收；信息不足时通过 `followup_task` 向原 operator 追问缺口。复用其上下文，不默认重新执行、另建代理或重读全部日志。

原始日志是执行证据，精简交付只是导航；必要时从日志恢复细节。保留到接纳与必要追问结束，之后沿项目已有生命周期处理，不另建永久账本。委派不增加操作权限，也不把非必要清理或未覆盖的故障修复变成 operator 的任务。
