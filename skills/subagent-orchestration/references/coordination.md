# 成本与交接控制

## 是否委派

只有以下条件同时成立才委派：子问题有独立输入、输出和停止边界；结果能让主代理减少读取、搜索或试错；交接与复核成本低于预计节省；子代理失败不会扩大授权或污染生产状态。任务很短、结果高度依赖主代理持续判断、双方必然重复读取同一上下文或正式实现本身才是主要工作时，主代理直接完成。

## 协作拓扑

```text
主代理目标与授权
├─ evidence：只读取证
│  └─ 主代理逐项接纳 F/X/N/U
├─ experiment：只消费已接纳证据与待判假设
│  └─ 主代理裁决可行路径
└─ 主代理：正式设计、实现、验证、状态、Git、发布与完成
```

默认串行使用最小链路。只有两个子问题相互独立、没有共享未证前提、不会触碰同一状态且各自结果不决定对方输入时才并行；主代理继续的本地工作也不得与子代理重复。子代理不得再生成后代代理。

派发时使用最小 capsule，不默认继承整段对话；引用稳定文件、ID 或快照，避免复制原文。跟进消息只传递新的目标修正、已接纳证据 ID 或反例；无需改变任务时等待结果，不通过反复催促制造重复输出。

主代理接收后先检查身份、范围、快照、直接引用、反例和未知，再决定接纳、补证、转入实验或停止。任何子代理的“完成、全部、唯一、无问题”都只是待审主张；只有主代理复核且实际消费者证据覆盖后才能进入完成结论。
