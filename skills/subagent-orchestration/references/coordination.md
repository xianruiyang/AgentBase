# 创建、等待与交接

## 派发

用户明确分工优先，其余按 `SKILL.md` 的默认职责选择。已知位置的直接阅读、明确实现和成熟单条命令不绕行委派；范围无法分开、结果必须依赖主代理持续裁决或当前接口不可用时，由主代理说明限制并处理必要部分，不为形式拆分。

固定角色 `evidence`、`experiment`、`advanced-experiment`、`operator` 的 `fork_turns` 显式使用 `"none"`，避免继承主线程全历史及模型档位。任务说明只提供当前问题、权威来源或已知线索、工作范围、预期产物；涉及写入再补具体文件所有权、恢复依据和禁止动作。时限、迭代或输出预算只在会限制实际工作时明确，不固定填写空字段或另建交接账本。

在自行开展拟委派的搜索或试错前调用 `spawn_agent`。成功返回才算已派发；失败则按直接错误调整或接手，不声称已创建，不空等。普通和高级 experiment 可直接在当前实验范围内按需创建一层 `evidence` 分担搜索，无需另行申请嵌套权限；不得创建其他角色。evidence 与 operator 不得创建子代理，也不能通过创建或分叉用户任务绕过角色边界。

## 并行与等待

只并行输入独立、写入不冲突且结果不互相依赖的工作。主代理只继续独立且属于当前任务的必要内容；暂无此类工作时直接等待已创建的子代理，不为保持忙碌新增调查、门禁或修改。等待使用现有等待工具，不忙轮询、不催促未变化状态。等待超时本身不是新证据；没有新消息、必要独立工作或已达到的约定时限、异常条件时继续等待，不重新推演同一状态或重复催报。遵守宿主的等待时长与沟通要求，不把单次工具超时当成任务停滞。

有多个结果时优先处理会推翻共同前提的反例；暂停依赖失效前提的工作，再回到所属目标、设计或任务裁决。不要在已有结果尚未接纳时继续铺开依赖它的新分支。

operator 与 experiment 在有意义的阶段完成、关键发现或耗时明显超预期时，通过现有父子代理消息接口简报进展、偏差和下一步。主代理收到后简查目标、范围与方向，需纠偏就及时反馈，不重新审计每一步。正常进展无需逐阶段等批准；只有需要重裁或授权的偏离才暂停相关工作。无变化不反复汇报，不另建进度日志。

## 接纳

- evidence 的位置供直接委派方阅读；分析或实现依赖的关键原文必须读到，无需复读整段搜索过程。根主代理保留目标、架构和最终验收裁决；experiment 向其交付时带回影响方案与验收的关键来源，根主代理核查决定性证据，不机械重读全部调查材料。缺证据时给原 evidence 具体缺口继续查，不诱导它为已有猜测寻找支持。
- experiment 的实现供主代理审核职责、接口、依赖与验证。合格部分可以直接接纳，有问题的部分修订或拒绝，不以“主代理定稿”为由重写一遍。
- operator 的结果按给定对象、动作与判定复核，例外交回主代理，不要求它自行补充设计。

不强制逐条编号或输出接纳清单；有争议、跨步骤引用或需要恢复时才记录对应位置和裁决。复用未失效的验证，主代理最终修改只重验受影响部分；未知和未覆盖范围不得被局部成功掩盖。Git、发布和整体完成仍由主代理负责。
