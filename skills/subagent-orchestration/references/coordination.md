# 成本与交接控制

## 是否委派

用户明确不使用子代理时不进入委派。用户明确要求使用时，该要求允许主代理选择合适角色，但不扩大原任务的操作和外部影响授权；子问题无法安全分离时不为满足形式而强行拆分。

用户未指定时，以下条件同时成立才默认委派：只读取证、可逆操作实验或合同已确认的有界执行是当前必要工作；子问题有独立输入、输出和停止边界；结果能让主代理减少读取、搜索、串行试错或难脚本化操作；交接、复核和返工成本低于预计节省；子代理失败不会扩大授权或污染范围外状态。任意一项不成立，或任务很短、结果高度依赖主代理持续判断、双方必然重复读取同一上下文、操作可以直接可靠脚本化、探针无法安全恢复，或结果不会改变裁决或交付时，主代理直接完成。整体任务以正式实现为主不单独排除实验；只要其中的操作性问题可以独立有界且委派净收益成立，仍可委派该实验，再由主代理正式实现。

## 协作拓扑

```text
主代理目标与授权
├─ evidence：只读取证或观察既有执行
│  └─ 主代理逐项接纳 F/I/X/N/U
├─ experiment：消费当前事实/输入、已接纳证据（如有）与待判假设
│  └─ 主代理裁决可行路径与实验补丁
├─ operator：消费冻结输入、既定规则与 oracle
│  └─ 主代理接纳有界执行结果或首个例外
└─ 主代理：目标、设计、正式验收、状态、Git、发布与完成
```

默认串行使用最小链路。用户要求并行，或用户未指定且至少两个子问题各自满足默认委派条件时，只有它们相互独立、没有共享未证前提、不会触碰同一状态、各自结果不决定对方输入且并发净收益成立时才优先并行；主代理继续的本地工作也不得与子代理重复。子代理默认不生成后代；只有用户、父代理或适用规则明确要求当前任务嵌套委派时才可例外。

派发固定配置的 `evidence`、`experiment` 或 `operator` 时，`fork_turns` 必须显式且只能为 `"none"`；省略、`"all"` 或任何正整数都不得用于这三种角色。平台省略该参数时默认全历史 fork，`"all"` 会继承主代理模型与推理深度并绕过角色配置。通过最小 capsule 引用稳定文件、ID 或快照；上下文无法准确压入 capsule 时由主代理处理，不改用通用角色继承上下文或伪装固定角色。跟进消息只传递新的目标修正、事实/输入变化、已接纳证据 ID 或反例；无需改变任务时等待结果，不通过反复催促制造重复输出。没有用户、父代理或适用规则对当前任务的明确嵌套要求时，子代理需要拆分就停止并把边界交还父代理；即使允许嵌套，也不得创建用户任务或分叉线程。

返回也使用最小决策包：结论先行，只列非空原子项、直接证据、精确定位、关键反例、决策未知和恢复状态；不复述请求、过程、工具噪声、原始日志或多份同义总结。完整产物留在稳定位置，主代理只有在某项会改变接纳或下一动作时才按定位续读。输出预算不足时明确省略范围和恢复入口，不以截断后的沉默冒充完整覆盖。

主代理接收后先检查身份、范围、快照、直接引用、反例和未知，再决定接纳、补证、转入实验、修订执行结果或停止。任何子代理的“完成、全部、唯一、无问题”都只是待审主张；只有主代理复核且实际消费者证据覆盖后才能进入完成结论。`operator` 遇到路径、规则或 oracle 未知时不得自行转成实验；它停止后由主代理决定是否另派 `evidence` 或 `experiment`。
