# 静态证据包

`evidence` 只负责回答一个有界事实问题。主代理在派发前给出：问题与它将影响的决策、权威范围及其来源、稳定快照或版本依据、必须覆盖的关系或维度、明确排除项、允许的只读入口、停止条件和输出预算。范围本身未知时，把“确认权威范围”设为首个问题，不要求代理同时证明全集。

## 交付结构

```text
证据包
├─ 问题、范围与快照依据
├─ 覆盖树
│  ├─ [D] 直接观察
│  ├─ [I] 由已列观察必然推出的推断
│  ├─ [X] 反例
│  └─ [?] 仍未知
├─ Fxx 原子事实与精确来源
├─ Xxx 关键反例及失效范围
├─ Nxx 否定检查、查询范围与截断状态
├─ Uxx 会改变决策的未知项与最低成本下一检查
└─ 受支持的有界陈述
```

- 每个 `Fxx` 写明观察对象、实际值、环境或版本、精确文件/符号/行或稳定产物位置，以及它直接支持的范围；推断必须列出所依赖的事实 ID。
- 每个 `Xxx` 写明被推翻的声明、直接观察和依赖失效范围。反例优先于汇总，不埋在普通备注中。
- 每个 `Nxx` 写明权威范围依据、实际查询、排除条件、结果、是否完整和是否截断。只有范围权威且查询完整时，否定结果才可支持“不存在”；否则只陈述“在已查范围内未发现”。
- 每个 `Uxx` 只保留会改变主代理下一动作或完成结论的未知，并给出能区分候选的最低成本检查。不会改变决策的剩余信息不进入包。
- 不附原始长日志、重复源码、数字置信度或重新叙述完整历史。最终陈述的对象、范围和确定性不得超过已列 `F/I/X/N`。

## 主代理接纳

主代理逐项记录当前上下文中的接纳结果，例如 `accepted: F01, F03, X01`，并为拒绝项说明来源陈旧、范围不符、属于推断或缺少直接引用等原因。只有已接纳 ID 可以进入后续方案或 `experiment` capsule；包的总结、覆盖树状态和代理自称“完成”都不能整体替代逐项复核。

需要修改后认证时，由主代理或独立消费者取得新证据；原 `evidence` 代理不得实现并认证同一变更。
