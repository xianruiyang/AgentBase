# 静态证据包

`evidence` 只负责回答一个有界事实问题。它可以读取静态来源，也可以观察已经启动的进程、任务、日志或外部状态直到给定终止条件；不得启动、修改、重试、终止或恢复被观察对象，状态未变化时不重复汇报。主代理在派发前给出：问题与它将影响的决策、权威范围及其来源、稳定快照或版本依据、必须覆盖的关系或维度、明确排除项、允许的只读入口、观察终止条件与时限、停止条件和输出预算。范围本身未知时，把“确认权威范围”设为首个问题，不要求代理同时证明全集。

## 稀疏交付结构

```text
证据包
├─ 结论：当前证据支持的最窄回答
├─ Fxx：直接事实、精确来源与支持范围
├─ Ixx：必要推断及其依赖的事实 ID
├─ Xxx：关键反例与失效范围
├─ Nxx：必要的否定检查、范围与完整性
└─ Uxx：会改变决策的未知与最低成本下一检查
```

- 只输出非空节点。范围与快照未偏离 capsule 时不重复全文，只在结论或事实定位中保留必要身份；覆盖关系由 `F/I/X/N/U` 的支持范围组成，不再另写同义总结。
- 每个 `Fxx` 写明观察对象、实际值、环境或版本、精确文件/符号/行或稳定产物位置，以及它直接支持的范围；推断必须列出所依赖的事实 ID。
- 每个 `Xxx` 写明被推翻的声明、直接观察和依赖失效范围。反例优先于汇总，不埋在普通备注中。
- 已有反例足以推翻 capsule 的共享前提并决定父代理下一动作时，先返回该反例与失效范围；除非 capsule 明确要求完整影响清单，否则不继续枚举依赖该前提的平级问题。
- 每个 `Nxx` 写明权威范围依据、实际查询、排除条件、结果、是否完整和是否截断。只有范围权威且查询完整时，否定结果才可支持“不存在”；否则只陈述“在已查范围内未发现”。
- 每个 `Uxx` 只保留会改变主代理下一动作或完成结论的未知，并给出能区分候选的最低成本检查。不会改变决策的剩余信息不进入包。
- 不附原始长日志、重复源码、工具过程、数字置信度或重新叙述 capsule 与完整历史。来源过大时只给稳定位置、精确片段身份和最低成本续读入口；最终陈述的对象、范围和确定性不得超过已列 `F/I/X/N`。

## 主代理接纳

主代理逐项记录当前上下文中的接纳结果，例如 `accepted: F01, F03, X01`，并只为影响下一动作的拒绝项说明原因。只有已接纳 ID 可以进入后续方案或 `experiment` capsule；包的结论和代理自称“完成”都不能整体替代逐项复核。

需要修改后认证时，由主代理或独立消费者取得新证据；原 `evidence` 代理不得实现并认证同一变更。
