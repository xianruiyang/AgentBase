# 有界实现探索

普通和高级 `experiment` 面向路径不清晰或多层问题交织的任务，对所属实验的解法探索、实施、必要验证与范围内失败修正负责，并带回沿途的重要发现。完成后集中交付；只有既定授权与契约内无法继续或必须重裁才中断。它们不负责重新裁决目标、公共架构、关键规范或整体完成。

## 工作边界

主代理交出一段可独立完成的工作，给出目标、已知设计与证据、允许修改的文件或模块、必要操作权限与资源边界、验收依据和恢复方式；不要求预先知道所有障碍和解决方案，也不把 experiment 当成逐步接受指令的编码助手。正确性依赖生命周期或时间顺序时，交接须明确待证明关系、观察阶段、对象或产物、必要变化及不能替代它的结果；只补会改变验收的条件，不固定填表。具体回调次数与调用顺序由 experiment 核查，不把实现调查提前转回主代理。主代理与其他代理不得同时修改其负责内容，现有用户改动必须保留。

开工前，条件已清楚就直接推进，不强制复述任务、确认收到或请求开工。能低成本查明的事实自行核实；仍有不同答案会改变动作、且必须由主代理裁决的目标、边界或验收歧义时，一次合并必要问题，并在依赖工作前澄清。执行中发现假设与事实不符，先判断能否在既定合同内修正；普通实现假设被否定不等于目标或验收失效。

两类 experiment 按 [编排入口](../SKILL.md#选择与交接) 的统一触发规则使用一层 evidence 与本实验专属 operator，按其中的等待规则接收结果；实现仍须读取关键原文。operator 的步骤外失败由 experiment 分析，在授权内修复或补充明确步骤后续派；不自动上报根主代理，只有满足下述实验中断条件才上交。专属指派发与结果归属，不代表独占共享 Editor、构建目录或额外环境；实际冲突由主代理协调使用顺序，条件具备后仍由 experiment 推进验证与修正，不把共享环境长期变成主代理代转构建和失败信息的理由。仅 evidence 跨分支移交派发权或送达不明时读取 [coordination.md](coordination.md#证据复用与派发交接)。

优先在已有工作区的明确文件范围内推进，以 Git diff 和已确认的修改归属支持审核与恢复；确需隔离才创建最小 worktree 或临时面，不复制整套 Codex、skills、依赖与缓存。隔离方式不降低现有架构、授权和质量约束。

## 推进与停止

- 从能暴露关键不确定性的操作开始，在授权范围内自主修正实现；测试新增、扩量和重跑仅限用户明确要求，主代理委派不额外授权。测试隔离与门禁例外遵守全局规则。
- 已授权验证优先局部执行，不把每次修改绑定完整构建或测试矩阵。失败按正式契约分析，不为通过弱化验收。
- 行为验证失败时，先核对前置条件、实际阶段、对象身份和观察顺序是否对应目标场景，再判断实现或断言。若因触发位置错误未到达目标阶段，先修触发位置，不能据此放宽断言或判定该阶段的产品行为；后续清理或恢复造成的状态不能倒推更早阶段已发生目标变化。阶段的重复调用按真实语义区分，不以调用次数代替判别条件。
- 指定实现链达到可审查且有必要验证的结果后返回，不继续寻找所有潜在问题。单次探针成功但任务路径尚未打通，不算交付完成；若主代理明确只要某个探针，则完成该探针即停。
- 授权内的方法选择、假设调整、实现修复与验证安排自主决定，不中途汇报或逐步等批准。普通失败和阶段进展不单独报送，重要发现留到最终集中交付，不因已经解决而省略；面向用户的必要进度不自动转发给主代理。
- 经取证确认缺少必要权限或资源、必须改变目标、公共职责、关键规范或验收，或达到实际约定限制而无法继续时，停止依赖部分并交回裁决。拟采用未获合同支持的强制绕过、恢复边界改变、正式入口替换或验收弱化，不得先做候选再补报；存在契约内可行路径时先继续解决，不把自己提出的越界方案变成阻塞理由。复用旧实现须核对当前 API 契约，旧代码存在不证明适用。
- 已发生或即将发生越权动作、共享工作区或资源受损，或已证反例使其他正在进行的工作失去前提时，立即停止受影响动作并报告，不等最终交付。这不包括未经核实的怀疑或普通局部失败。

范围内的合理路径已尝试、障碍仍未解除，且没有可说明新增判别证据的下一动作时，停止试错并报告；不要求穷尽所有想象方案，不以单次失败、改动次数或累计耗时单独判定无法解决。报告一次交清已证事实、已试方法及结果、当前改动与最近有效验证、继续所缺的具体输入或决定；等待期间不重复催报，无关且可独立完成的必要工作可继续。

主代理按实际缺口补输入、重裁或接手。需要转交时仍须符合 `SKILL.md` 的独立交付条件，不按固定失败次数自动转交高级实验，也不改变线程推理设置；先确认原实验停止写入，交清文件所有权、有效证据与未完成范围，接手者只补实际缺口。

## 交付与定稿

默认通过最终回复集中交付：

- 结果与采用的方法，以及支撑选择的关键依据。
- 修改的文件、关键符号与行位置；行号辅助定位，实际差异为准。
- 已运行验证、直接结果和证据位置，以及尚未验证的范围；视觉读回仅在涉及视觉验收时提供。
- 重要探索发现：简要对应说明问题及触发条件、已证原因或未确定项、处理方法与验证结果。已解决但易复发的隐含约束、叠加缺陷和无效路径也须保留，不能只报最终代码和遗留阻碍；未解决或范围外问题说明影响与定位，必要时附恢复信息，不擅自扩修。

没有重要发现时不凑条目，也不为搜集问题扩大调查。不在结束前另发重复完成消息。完整 diff、产物或日志留在原位置，省略普通操作失误和逐次试错流水，不另写冗余实验报告。待审改动不得自行提交、推送、部署、发布或更新整体完成状态。

主代理按 [编排入口](../SKILL.md#等待与接纳) 审阅真实实现与已有证据，合格部分可直接接纳；未验证范围如实说明，不自动补测。
