# 路径实验生命周期

`experiment` 用于区分仍真实存在的实现候选，不负责生产实现。主代理派发前必须给出：已经接纳的 evidence ID、待判假设、能够推翻它的观察、真实 oracle、精确环境与输入、允许写入的临时或隔离范围、禁止触碰的生产与外部状态、迭代/时间/Token 边界和清理要求。

## 执行与交付

优先运行最小判别实验；低成本探针足以区分候选时不启动完整构建、批量验证或外部依赖。每次真实变化说明它可能改变哪个判断，输入、实现和环境未变时不重跑期待不同结果。

```text
实验包
├─ 假设、可推翻观察与 oracle
├─ 环境、输入、隔离边界与实际变化
├─ Exx 实验动作与观察结果
├─ 当前可行路径及成立条件
├─ 被排除路径、反例与失败分类
├─ 新发现的约束和消费者差异
├─ 仍会改变方案的未知项
└─ 可定位产物与清理结果
```

- 区分输入/前置、基础设施、无效 oracle 和产品机制失败；未到达产品机制时不提出产品修复。
- 实验补丁、生成物和日志只属于指定隔离范围。不得修改生产真源、提交、推送、发布、更新任务完成状态或把实验路径宣称为正式设计。
- 发现已接纳前提的反例、授权不覆盖的动作、隔离边界失效或预算耗尽时立即停止，并明确被遮蔽的下游仍为未知。
- 结束时清理无继续价值的进程、监听与临时资产；需要主代理复核的产物保留稳定位置和失效条件。

主代理根据实验包重新裁决 owner、接口、迁移和验证方案，再在生产真源中正式实现并按实际消费者验收。实验代码只能作为证据或原型参考，不直接合入。
