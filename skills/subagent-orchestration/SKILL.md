# Subagent Orchestration

子代理降低只读取证、可逆探索或有界执行的成本，不转移主代理的目标、授权、设计、正式验收、完成、Git、发布与外部写入责任。用户明确要求使用或不使用子代理时先遵守该边界；当前代理为主代理且用户未指定时，子问题独立有界、可与主线程有用工作并行且节省的 Token 或墙钟时间高于交接、复核和返工成本，就先实际创建对应角色再继续不重叠工作，否则主代理直接完成。计划、skill 选择、文字声称和空等待不构成创建。子代理默认自己完成收到的有界任务或把拆分需要返回父代理；只有用户、父代理或适用规则明确要求当前任务继续嵌套委派时，才可在该要求内创建后代。这是可由当前边界和成本证据推翻的主代理默认选择，不是无条件 fan-out。

## 角色路由

- 事实未知且可通过只读来源取得时，选择 `evidence`，完整读取 [evidence-packet.md](references/evidence-packet.md) 与 [coordination.md](references/coordination.md)。仅观察已启动进程、任务或日志也属于该角色。
- 需要通过实际修改或运行的可回滚最小探针确认路径、暴露错误或真实约束，或连续实现中的前一问题会遮蔽后续问题、逐点修改后做昂贵验证将形成串行试错时，选择 `experiment`，完整读取 [experiment-lifecycle.md](references/experiment-lifecycle.md) 与 [coordination.md](references/coordination.md)。这不以任务是否陌生、静态证据是否穷尽、是否已有初步路径为前提。
- 目标、规则、范围、允许动作和验收 oracle 已确认，只剩一次性非标准工作或难以脚本化的简单重复执行时，选择 `operator`，完整读取 [operator-execution.md](references/operator-execution.md) 与 [coordination.md](references/coordination.md)。启动、等待并分析输入已冻结的正式构建属于该角色；为找出修复路径而修改后反复构建仍属于 `experiment`。
- 同一链路先取证后实验时，主代理先逐项接纳 evidence ID，再把已接纳事实与仍待判假设交给 `experiment`。静态取证不是实验的强制前置；`operator` 遇到未知或反例时退回主代理裁决，不自动改派角色。

具体模型与推理档位只由 Codex 自定义代理配置维护。本 skill 只使用 `evidence`、`experiment`、`operator` 的稳定语义身份，不以模型名选择职责，也不把当前模型能力写成长期规则。

## 共同合同

1. 创建固定配置的 `evidence`、`experiment` 或 `operator` 时，`fork_turns` 必须显式且只能为 `"none"`；省略、`"all"` 或任何正整数都不得用于这三种角色。平台省略该参数时默认全历史 fork，`"all"` 会继承主代理模型与推理深度并绕过角色配置。所需上下文只通过最小 capsule 传入；若最近未持久化事实无法在 capsule 中准确表达，由主代理继续处理，不改用通用角色继承上下文或伪装固定角色。capsule 只包含当前问题、权威范围或输入快照、允许动作、必要输出、可推翻观察、停止条件与成本边界；不复制完整对话和无关历史。返回只保留能改变主代理决策或限定结论的非空原子项、精确定位和恢复入口，不复述 capsule、过程、原始日志或重复总结。
2. 默认只启动一个子代理；用户明确要求并行，或用户未指定且至少两个子问题各自满足默认委派条件时，只在工作流相互独立、不修改同一状态、没有共享未证前提且结果无需先后裁决时优先并行；否则串行最小链路。主代理等待期间只做不重叠工作。
3. 子代理默认不得调用 `spawn_agent` 继续委派；只有用户、父代理或适用规则明确要求当前任务嵌套委派时，才按该要求创建独立有界的后代并继续遵守本合同。该例外不授权 `fork_thread`、`create_thread` 或其他用户任务与分叉入口。没有明确嵌套要求而任务需要拆分或超出 capsule 时，停止并返回父代理。前提、授权或范围失效时立即停止；主代理只在新证据改变任务时发送修正，不用追问诱导同一输入产生不同答案。
4. 主代理按来源、对象、范围、快照和直接性接纳或拒绝返回项；未接纳项保持待审，不进入方案、实验、正式实现或完成结论。
5. 反例推翻共享前提时，立即熔断依赖它的子代理与主代理动作，写回已有 owner 后重裁。子代理输出不扩大授权，不替代实际消费者验证。

实验补丁不因子代理生成或局部通过而自动成为生产改动。`operator` 的实际结果也只在给定范围和 oracle 内成立。主代理逐项复核证据、职责、输入快照、契约和 dirty 边界，选择接纳、修订或拒绝，再承担正式验收与完成判断；不得让同一子代理认证自己改变后的职责或整体结果。
