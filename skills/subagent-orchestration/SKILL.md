# Subagent Orchestration

子代理只降低取得候选证据的成本，不转移主代理的目标、授权、设计、正式实现、完成与外部写入责任。只有子任务能够独立有界，并且预期节省的 Token 或墙钟时间高于交接、复核和返工成本时才委派；否则主代理直接完成。

## 角色路由

- 需要静态证据、当前状态或影响地图时，选择 `evidence`，完整读取 [evidence-packet.md](references/evidence-packet.md) 与 [coordination.md](references/coordination.md)。
- 需要以低成本实验区分实现路径和真实约束时，选择 `experiment`，完整读取 [experiment-lifecycle.md](references/experiment-lifecycle.md) 与 [coordination.md](references/coordination.md)。
- 同一链路先取证后实验时读取三份引用；主代理先逐项接纳 evidence ID，只把已接纳事实与仍待判假设交给 `experiment`。

具体模型与推理档位只由 Codex 自定义代理配置维护。本 skill 只使用 `evidence`、`experiment` 的稳定语义身份，不以模型名选择职责，也不把当前模型能力写成长期规则。

## 共同合同

1. 派发 capsule 只包含当前问题、权威范围或输入快照、允许动作、必要输出、可推翻观察、停止条件与成本边界；不复制完整对话和无关历史。
2. 默认只启动一个子代理；只有工作流相互独立、不会修改同一状态且结果无需先后裁决时才并行。主代理等待期间只做不重叠工作。
3. 子代理不得继续委派。前提、授权或范围失效时立即停止；主代理只在新证据改变任务时发送修正，不用追问诱导同一输入产生不同答案。
4. 主代理按来源、对象、范围、快照和直接性接纳或拒绝返回项；未接纳项保持待审，不进入方案、实验、正式实现或完成结论。
5. 反例推翻共享前提时，立即熔断依赖它的子代理与主代理动作，写回已有 owner 后重裁。子代理输出不扩大授权，不替代实际消费者验证。

主代理从实验结果重新形成可维护方案并自行实现；不得直接合入实验补丁或让同一子代理认证其结果。
