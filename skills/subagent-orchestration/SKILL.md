# Subagent Orchestration

继承全局的用户优先、主代理正式质量责任与按角色限定的委派边界。本 skill 维护分工的实际入口和交接；实验中的 evidence 只承担只读取证，不扩大实施范围，也不转交目标、架构、关键文档治理或最终验收。

## 默认分工

按当前缺口选择角色，不固定串联全部角色；不要求先证明主线程有其他事可做。

- **证据定位值得独立交接：`evidence`。** 实施前定位调用链与原生契约，验证前定位 fixture、测试 API、注入点与断言，修改后定位受影响调用方与旧路径；已知部分文件仍可委派补齐来源和关系，不要求从未知目录开始。也可发现工具能力、命令与用法；按问题选来源，不限于文件检索或因执行查询就转交其他角色。主要交付路径、行范围及简要阅读导航；实际消费者读取原文并分析，根主代理保留正式裁决。读取 [evidence-packet.md](references/evidence-packet.md)。
- **可独立推进且探索量较大的实现：`experiment`。** 目标、修改范围和验收可明确交接，预计需要较长的修改、运行和探索，且主代理能将整段工作交出直到最终审查时使用；不要求先穷尽静态证据或亲自试错。预计十来分钟可闭合的小任务通常直接做，时长只是成本线索，不设机械门槛；委派须能减少主代理的实际工作，而非让双方重复理解、试错和决策。读取 [experiment-lifecycle.md](references/experiment-lifecycle.md)。
- **满足同一独立交付条件的困难或视觉实验：`advanced-experiment`。** 用于普通 experiment 的速度优先配置不足以可靠处理的复杂因果、跨接口推理，或必须直接检查截图、渲染等视觉反馈的实现；难度高不单独构成委派或升级理由。沿用 [experiment-lifecycle.md](references/experiment-lifecycle.md)。
- **步骤与判定已确定：`operator`。** 完成有界简单操作、重复执行或已冻结命令的运行与观察；一条成熟命令或已有可靠脚本能直接闭合时，主代理执行即可。读取 [operator-execution.md](references/operator-execution.md)。
- **直接实施与最终验收：主代理。** 维护目标、架构和关键文档，直接完成短小实现、依赖连续上下文或需要自己持续裁决的探索，并审核接纳委派结果。不为了“一次做对”长时间预想本应由操作确认的问题。

用户未指定委派时，简短查询即可闭合的问题自行处理；未知范围、候选筛选或核对契约所需的来源定位值得独立交接时才委派，不要求主代理先查完。已知位置不等于证据齐全；材料已充分且未失效时不重复取证，不把修改后取证设为固定复核。按具体证据缺口派发，不泛泛要求“再找问题”，也不按工具名称、调用次数或实现时长机械判断。子代理自行查询必要帮助，不再拆出微小子任务。

## 创建与交接

实际委派前读取 [coordination.md](references/coordination.md)。用简短任务说明交代问题、范围、必要输入、预期产物和会改变动作的限制；不为每次委派填写固定字段表或建立额外记录。具体模型和档位只由自定义角色配置维护。

普通和高级 experiment 可在当前实验内按需创建或续用一层 `evidence`，无需另行授权；不能创建其他角色，`evidence` 与 `operator` 不得继续委派。已有证据、跨分支派发权和结果送达按 [coordination.md](references/coordination.md#证据复用与派发交接) 处理。

先真实派发，再继续独立必要工作或等待；不同时代做同一个子问题。结果按 [coordination.md](references/coordination.md#接纳) 审核，子代理自称完成不代替主代理验收。
