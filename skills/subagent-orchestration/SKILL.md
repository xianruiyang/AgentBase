# Subagent Orchestration

子代理只降低取得候选证据的成本，不转移主代理的目标、授权、设计、正式实现、完成与外部写入责任。用户明确要求使用或不使用子代理时先遵守该边界；用户未指定时，静态取证或可逆操作实验已是后续决策的必要输入、子问题独立有界且节省的 Token 或墙钟时间高于交接、复核和返工成本时，默认使用对应角色，否则主代理直接完成。这是可由当前边界和成本证据推翻的默认选择，不是绝对创建义务。

## 角色路由

- 需要静态证据、当前状态或影响地图时，选择 `evidence`，完整读取 [evidence-packet.md](references/evidence-packet.md) 与 [coordination.md](references/coordination.md)。
- 需要通过实际修改或运行的可回滚最小探针确认路径、暴露错误或真实约束，或连续实现中的前一问题会遮蔽后续问题、逐点修改后做昂贵验证将形成串行试错时，选择 `experiment`，完整读取 [experiment-lifecycle.md](references/experiment-lifecycle.md) 与 [coordination.md](references/coordination.md)。这不以任务是否陌生、静态证据是否穷尽、是否已有初步路径为前提。
- 同一链路先取证后实验时读取三份引用；存在 evidence 包时主代理先逐项接纳 evidence ID，再把已接纳事实与仍待判假设交给 `experiment`。没有独立 evidence 阶段时，主代理可直接给出已确认的当前事实与输入快照；静态取证不是实验的强制前置阶段。

具体模型与推理档位只由 Codex 自定义代理配置维护。本 skill 只使用 `evidence`、`experiment` 的稳定语义身份，不以模型名选择职责，也不把当前模型能力写成长期规则。

## 共同合同

1. 派发 capsule 只包含当前问题、权威范围或输入快照、允许动作、必要输出、可推翻观察、停止条件与成本边界；不复制完整对话和无关历史。返回只保留能改变主代理决策或限定结论的非空原子项、精确定位和恢复入口，不复述 capsule、过程、原始日志或重复总结。
2. 默认只启动一个子代理；用户明确要求并行，或用户未指定且至少两个子问题各自满足默认委派条件时，只在工作流相互独立、不修改同一状态、没有共享未证前提且结果无需先后裁决时优先并行；否则串行最小链路。主代理等待期间只做不重叠工作。
3. 子代理不得继续委派。前提、授权或范围失效时立即停止；主代理只在新证据改变任务时发送修正，不用追问诱导同一输入产生不同答案。
4. 主代理按来源、对象、范围、快照和直接性接纳或拒绝返回项；未接纳项保持待审，不进入方案、实验、正式实现或完成结论。
5. 反例推翻共享前提时，立即熔断依赖它的子代理与主代理动作，写回已有 owner 后重裁。子代理输出不扩大授权，不替代实际消费者验证。

实验补丁不因子代理生成或局部通过而自动成为生产改动。主代理逐项复核其证据、职责、契约和 dirty 边界，选择重写、修订后接入或拒绝，再承担正式实现、验证和完成判断；不得让同一子代理认证其结果。
