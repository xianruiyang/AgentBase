# Execution Governor

本 skill 是复杂工作运行期间“下一动作”的唯一控制 owner。它不维护新的计划、任务表或完成状态，也不替代领域实现；目标、授权、正式文档和任务记录仍由各自真源维护。

## 协同边界

- 需要形成或修订需求、设计、方案和持久任务投影时使用 `$delivery-workflow`；本 skill 只提供当前证据前沿、证明路径和失效关系。
- 已有任务表需要查询、记录依赖或更新执行状态时使用 `$task-table-manager`；CLI 不决定哪个判断应先验证。
- 根因将改变长期 owner、正式入口、共享契约、迁移或争议 oracle 时使用 `$change-governance`；普通的批量收敛、故障遮蔽和低成本探针由本 skill 处理。
- 本 skill 先按不确定性、后果、可逆性和验证负担判断下一段工作的最低充分推理档位；只有当前线程配置会改变后续动作时才使用 `$reasoning-governor` 读回或设置。next-turn 设置不能改善已经开始的当前轮。
- 实施继续按修改对象选择源码、PowerShell、C++、空间或其他领域 skill。

## 按需引用

- 多个动作共享前提、需要选择首个消费者、多维组件将形成组合用例、批量执行或把控制结果投影为任务依赖时，完整读取 [decision-frontier.md](references/decision-frontier.md)。
- 出现失败、重试、遮蔽、基础设施与产品结果混写、昂贵验证、成批编写 fixture/示例/测试，或用户对原因和成本提出质疑时，完整读取 [failure-and-cost.md](references/failure-and-cost.md)。
- 只读裁决组合覆盖且不设计、生成或运行昂贵动作时只读决策前沿引用，不读失败与成本引用。
- 同时命中时读取两者；不要为单一已确认动作预加载引用。

## 控制循环

1. 确认当前用户结果、授权范围、直接约束和已经取得的有效证据；用户要求的数量或覆盖范围不自行决定执行顺序。
2. 找出当前结果路径上最早尚未验证、且成立与否会改变多个后续动作或完成结论的判断；同一声明可能跨维度变化时，先形成组合覆盖依据，识别会改变机制、oracle、生命周期或边界的维度、等价证据、真实交互、代表 case、扩量触发和实际未覆盖范围。没有这类判断时沿已确认依赖执行，不制造形式化前置。
3. 选择能改变该判断、经过真实消费者且完整成本最低的证据。实现、配置、mock、文档或同一生产者生成的布尔量只证明自身范围。
4. 上游设计、owner、契约和依赖已经确认时，按该完整设计先深度优先完成一个正式可用结果切片：实现这项结果跨层所需的共享职责与消费者差异、真实消费者和有效 oracle。本次只选择一个结果，不降低正式实现质量，也不让首个结果重新定义或替代既定设计；共同前提和该结果未成立前，只实现、编写 fixture 或测试它直接需要的内容，其他平级组合都属于横向扩量。上游仍未确认时先返回所属设计或职责 owner，不用执行切片暗中完成设计。
5. 结果成立时才按已证的组件契约、接缝、等价类和交互关系扩量；新增 case 必须能区分尚未覆盖的机制、oracle、边界或已知风险。失败时先裁决输入、环境、oracle、基础设施和产品机制，标记被遮蔽的下游为未知。上游判断被反例推翻时立即停止依赖动作，先把反例、失效范围、当前消费者和下一动作写回已有 owner，再返回该层重裁；写回完成前不继续依赖该判断的工作。
6. 新的完整运行必须说明它能推翻哪个当前判断；昂贵动作先按失败与成本引用完成适用 preflight，并由领域 runner 持有具体检查。更低成本的独立探针已经足够或输入、机制和环境未变时不运行。
7. 证据前沿、当前消费者、验证 case、最近有效结果或关键反例、失效来源、下一动作发生变化且需要跨轮或多人消费时，立即写回已有的方案、任务状态或结果 owner；普通进度不重复写入，本 skill 不另建运行日志、控制状态或完成摘要。

## 用户沟通与完成边界

- 用户质疑重复失败、原因、时间或 Token 成本且会改变下一动作时，先停止新的昂贵动作，说明直接失败、遮蔽关系、当前未知和下一证据；不为迎合接受不完整原因，也不把遮蔽当作无限逐层运行的理由。
- 调整执行顺序只为实现既有目标，不创建新的范围、外部写入或风险授权；需要改变用户目标或知情风险取舍时交由用户裁决。
- 本 skill 的选择、计划存在、任务数量和局部检查通过都不是完成证据；完成仍由用户结果及其实际消费者证据决定。
