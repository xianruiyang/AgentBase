# 失败遮蔽与验证成本

## 失败分类

一次失败先按直接证据区分：

- 输入或前置条件不满足；
- 测试环境、依赖、权限、路径或运行器基础设施失败；
- oracle 的对象、环境或失败语义无效；
- 产品或方案机制在适用输入下失败。

只有最后一类能够直接覆盖产品机制时才修改产品；基础设施失败不得转换成产品零分，oracle 无效不得用来选择实现。

## 遮蔽关系

当前失败使执行未到达下游机制时，下游保持未知，而不是通过、失败或“不存在其他问题”。继续前：

1. 列出当前直接失败和被它遮蔽的下游范围。
2. 找出无需完整链路即可独立观察的相邻前置条件。
3. 用有界组合 preflight 一次检查这些条件，避免完整运行逐层剥离基础问题。
4. 只有共同前置通过后，才重新运行一个完整消费者路径。

遮蔽可以解释为何问题串行暴露，但不能为无界逐层重跑辩护。

## 昂贵验证与重试

把模型调用、外部依赖安装、管理员交互、长进程、批量任务或跨多个消费者的验证视为昂贵动作。执行前写清：当前判断、可推翻观察、最低成本入口和失败分类。

### 昂贵动作 preflight

在第一次完整运行前，由当前领域正式 runner 或其明确 owner 一次检查本次适用项；不为不适用字段补默认值，也不把跨项目清单改成领域命令拼接：

- 当前待证判断、能够推翻它的直接观察，以及本次完整运行相对低成本探针新增的判别信息；
- 输入与 schema 身份，适用时的 fixture/catalog 身份，以及路径、权限和外部依赖是否可读；
- runner 身份、进程生命周期、准备/清理边界，以及重复运行前实际改变的输入、机制或环境；
- oracle 的对象、环境和失败语义是否到达待证产品机制，而不是在替身、基础设施或上游前置处提前结束；
- `ready` 时列出已证前置和仍由本次运行裁决的未知，`blocked` 时返回直接失败、被遮蔽范围与最小恢复动作。

preflight 结果是当前执行控制证据，不签发外部操作授权、不证明产品通过，也不建立跨领域统一 runner。已有领域 runner 持有具体检查和命令；缺失 owner 或人工拼装已反复造成失败时，按下文升级而不是继续扩大全局清单。

- 低成本探针能取得同一判别证据时，不运行完整入口。
- 多项共享相同未证机制时，只运行一个代表消费者。
- 输入、机制和环境未变时不重跑；真实变化后仍说明本次变化如何可能改变结果。
- 连续失败表明原执行模型或共同前提可能错误时，停止局部修补并返回证据前沿，不以“每次都有修改”替代收敛判断。

重复调用的稳定外部接口若依赖人工拼接引号、分隔符、环境、权限或生命周期，已有领域正式 runner 时改用该入口；没有 runner 且这种脆弱性已经造成失败或会反复影响当前结果时，返回 `$change-governance` 裁决领域入口 owner，再继续完整运行。一次明显且已正确恢复的普通输入笔误不自动创建公共 runner。

## 用户质疑

用户质疑重复失败、原因或成本时，把它视为当前因果模型可能不充分的新输入。若会改变下一动作，先暂停昂贵执行并回答：

- 已直接证明什么；
- 哪些只是被遮蔽的未知；
- 哪些耗时来自有效取证，哪些来自可避免返工；
- 下一次动作能新增什么判别证据；
- 继续原方案、重裁或停止各自的后果。

用户保有目标和知情风险取舍的最终裁决；模型不得为顺从接受与证据冲突的原因，也不得借纠正原因改变目标或扩大授权。
