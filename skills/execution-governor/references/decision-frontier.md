# 证据前沿与纵向消费者

## 证据前沿

证据前沿是当前结果路径上最早未证、且会改变多个后续动作或完成结论的判断。局部可直接实施和验证的未知不升级为共享前提。沿真实依赖确定它及可推翻观察，不按最易修改的文件或组件选择。

## 最小纵向路径

先证明共同前提并闭合一个正式消费者，再扩展；验证对象须经过真实机制。这个顺序不改变既定设计或实现质量，不能用 mock、硬编码旁路或中间产物替代用户结果。

### 活动切片锁

共享前提或组合覆盖未证，需要控制多个平级消费者/组合的实现、fixture、示例或测试时，先固定公共合同与 owner、一个活动消费者、有效 oracle、暂缓范围和解除条件（消费者闭合或上游被反证）。只在跨轮/多人恢复需要时写入已有检查点；等价、停止条件和单项验收已确认的批次不重建锁。

- 合同或 oracle 的多种解释会改变实现时，先交所属 owner 裁决；旧测试结构不替代合同。
- 当前消费者未闭合，不切换或绑定多个未闭环消费者；用户要求最终数量不改变依赖顺序。代码、fixture 和参数化测试都算扩量，只建设当前结果直接需要的内容。
- 共同前提已成立、消费者单独失败时，修该消费者覆盖的机制，不无依据重开前提。成立后按等价证据和真实差异扩展；反例只停止依赖它的范围。

受控转移仅适用于已证的当前消费者独有、授权内暂不可恢复的环境/权限/输入阻塞。另一既定消费者须经过同一机制、具备有效 oracle 且不受该阻塞影响；仍只推进一个。保留原改动，说明阻塞、恢复条件及替代对象，原项保持未完成并待条件恢复补验。产品失败、原因未明或替代对象绕过失败机制时不得换例。

### 替换闭环

按全局的改写、替换或独立并存判据处理当前切片，不再建立分类账本。替换闭合包含旧生产入口、绕过路径及仅绑定旧实现的验证/说明退出；保留不同当前契约需要的路径。不能以旧内容易回退、已有测试要求或以后清理作为叠加同责路径的理由。

上游设计、职责或正式入口尚未确认时先停止依赖实施，回所属来源裁决，不在切片中隐式决定。需形成或修订阶段设计时用 delivery-workflow；涉及 owner、入口、契约或迁移裁决时用 change-governance。已确认设计下的普通实施不因此加载两者。

## 验证维度与结论边界

同一声明的行为或 oracle 会随载体、模式、状态、版本、revision、持久化等边界变化时，确认实际相关维度及等价依据；选能区分候选机制的最小组合，不默认笛卡尔积。

扩量前的 coverage basis 保留以下信息；只有任务合同或恢复需要时显式写入，不为每次调用生成表格：

- `claim`：当前能力声明。
- `dimensions / equivalence`：改变机制的维度，以及可合并取值的契约、接缝或结构证据。
- `interactions`：共享分派、状态、持久化等实际耦合。
- `cases / promotion`：代表 case 的判别信息，以及升级组合或穷举的反例、未知与条件。

已由组件契约/属性/边界测试覆盖的数据变化，不自动增加端到端组合；同名、同一接口或代码路径不能单独证明等价。覆盖可由组件、接口接缝、真实消费者、代表交互和缺陷回归共同组成，结论保留等价依据。

pairwise 只有在故障机制最多涉及两维的证据成立时才证明相应交互，否则只是取样；高阶共享状态只升级相关组合。逐组合认证的明确要求、小而廉价的闭集，或高后果交互缺少充分等价证据时才穷举。owner、oracle 和验收明确且无共享未知的小闭集直接验证，不另建 coverage basis 或跨项目固定 case 数。

任务合同持有需裁决的维度及需跨轮复用的覆盖依据；当前检查点只持有实际 case。结果仅声明直接覆盖或可复核等价范围，反例只推翻其相关前提。

## 持久任务投影

需要任务表时，把证明动作与首个消费者的真实产出作为依赖，不以编号、深度或数量推断前沿。已有交付链的上游修订归 delivery-workflow，task-table-manager 只保存合同、依赖和结果；无可复核产出或下游不消费该结果时，先修方案而非设置形式门禁。
