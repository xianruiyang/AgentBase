# 可修订规划合同

本文件唯一维护模型设计、现状分析与方案设计的阶段语义；通用 ID 与条目格式继承 [artifact-contracts.md](artifact-contracts.md)。这些产物可随新证据修订，但不能静默改变受保护目标。

## 模型设计

- `DES` 说明为满足 `REQ/AC/UDES` 所需的权威职责、接口、状态、依赖和生命周期，并显式引用适用目标。
- 需要形成或调整公共职责时，写清稳定约束、当前消费者、共同决定、消费者差异和唯一正式入口。
- 不描述当前实现是否已经做到，也不把候选方案写成目标职责。

修订前保留当前显式影响集合；修订后结合实际系统检查旧、新关系对现状、方案、任务、消费者、派生产物和证据的影响。

## 现状分析

- `OBS` 记录来源、对象、环境、观察结果和证据能证明的上限，明确区分直接事实、推断和未知。
- 职责相关观察区分正式 owner、实际消费者、派生产物、绕过或复制决定路径以及未登记依赖。
- `GAP` 引用目标 `DES/AC` 与相关 `OBS`，只说明当前哪里尚未满足；根因尚未证明时保持为假设或未知，不混入解决动作。
- 职责错位只有会影响当前目标、复发条件或造成同一行为多个决定路径时才进入本次差距。

## 方案设计

- `SOL` 引用所处理的 `GAP` 与 `DES`，写明动作、预期结果、依赖、影响范围、风险和验证方式。
- 改变共享 owner、契约或既有职责实现时，先明确原位改写、替换或独立并存；把权威修正、当前消费者接入、旧同责路径及其实现绑定验证资产退出、派生结果更新和重新验证设计为一个闭环结果，不把退役留成无 owner 的后续清理。
- 真实候选存在差异时记录选择依据；关键选择未决时保留 `DEC`，不伪装成任务。
- 不把“以后确认”“由 owner 处理”或含糊等价能力当作可执行动作。

方案只处理已经确认的差距。使目标成立并接入唯一正式入口所必需的职责、接口和依赖调整属于当前方案；仅改善整体架构但不影响当前结果的调整不顺带纳入。
